+## 0.2 代码规范（**与仓库既有风格严格一致**）
+
+> 依据：`packages/rag-core/rag_core/*.py` 与 `packages/rag-contracts/rag_contracts/*.py` 的既有写法。
+> **这些不是建议，是仓库现行标准。**
+
+### 0.2.1 文件结构
+
+```python
+"""模块一句话职责。
+
+设计要点：
+1. 要点一（**为什么**这样做，而非做了什么）。
+2. 要点二。
+
+对应：<设计文档> §<章节>。
+"""
+
+from __future__ import annotations
+
+# 1) 标准库
+# 2) 第三方
+# 3) 本项目（rag_contracts / cg_observability / 本地相对导入）
+```
+
+| 规则 | 要求 |
+|---|---|
+| 模块 docstring | **中文**，首行一句话职责；随后用「设计要点」列 2~5 条 |
+| `from __future__ import annotations` | **必须有**（全仓一致） |
+| 导入分组 | 标准库 → 第三方 → 本项目，组间空一行（`ruff` isort 强制） |
+| 行宽 | 88（`ruff` 配置；`E501` 已 ignore 但仍应对齐） |
+| 类型标注 | **全量标注**，含返回值；可选参数用 `X \| None` |
+
+### 0.2.2 函数 docstring（Google 风格 + 中文）
+
+```python
+def search(self, vector: Sequence[float], top_k: int) -> list[VectorHit]:
+    """稠密检索。
+
+    Args:
+        vector: 查询向量。
+        top_k: 返回条数上限。
+
+    Returns:
+        按得分降序的命中列表。
+
+    Raises:
+        StoreUnavailableError: 检索失败。
+    """
+```
+
+| 规则 | 要求 |
+|---|---|
+| 段落 | 中文；`Args:` / `Returns:` / `Raises:` 三段**按需出现**（有才写） |
+| 注释语言 | **中文** |
+| 注释倾向 | 解释 **「为什么」**，而不是复述代码（范例：`service.py` 里解释为何用 clamp 而非 `(x+1)/2`） |
+| `__all__` | 每个公开模块末尾必须有，按字母序 |
+
+### 0.2.3 私有属性命名
+
+- 实例私有字段用 `_snake_case`（如 `self._vector_store`）
+- ⚠️ **重要**：`factory.build_service_from_settings(**overrides)` 通过反射访问 `f"_{key}"` 覆盖私有字段
+  → **新增可覆盖字段必须命名为 `_<同名>`**，否则 overrides 静默失效

+## 0.3 依赖方向红线
+
+```
+rag-contracts ──(被依赖)──> rag-core ──> ai-engine ──> async-worker
+                                    ↑
+                              api-gateway
+
+doc-processor（解析层，被 ai-engine / async-worker 消费）
+schema/openapi.yaml（SSOT → 生成 api-gateway DTO 与 web-ui TS/Zod）
+```
+
+| 红线 | 说明 |
+|---|---|
+| 🔴 **禁止反向依赖** | `rag-core` **不得** import `ai_engine` / `worker` / `apps/*` |
+| 🔴 **禁止 SDK 泄漏** | `rag-core/rag_core/service.py` **只依赖 `rag_contracts.ports` 的 Protocol**，不得 import 任何具体 SDK（`qdrant_client` / `pymilvus` / `httpx`） |
+| 🔴 **重依赖禁止入门** | `rag-core` **禁止** `torch` / `sentence-transformers` / `jieba` / `rank_bm25`（`pyproject.toml` 有明文注释）。需要精排 → **走 HTTP** |
+| 🔴 **生成物不可手改** | `apps/api-gateway/app/generated/schemas.py`、`apps/web-ui/src/api/generated/{types.ts,zod.ts}` 由 CLI 生成 |
+
+> **端口-适配器原则**：所有"会变的实现"（向量库 / 稀疏检索 / 向量化 / 重排）
+> 一律实现 `rag_contracts.ports` 的 Protocol，并通过 `rag_core.factory` 装配。
+> **换实现 = 加文件 + 加分支，绝不动 `service.py` 与 `rag_contracts`。**

+## 0.5 错误、降级与可观测规范
+
+### 0.5.1 错误体系（已存在，直接用，勿另造）
+
+- 所有异常继承 `rag_contracts.errors.RagError`，携带 `code`（`CG-RAG-xxxx`）与 `retryable`
+- 错误码常量见 `rag_contracts/errors.py`；**禁止在业务代码里写魔法字符串**
+- **降级不是错误**：`EMPTY_RECALL`（`CG-RAG-2001`）是**握手信号**（表示"没有依据"），
+  **不定义异常类**，只用于日志归因与 `RAGQueryResponse.fallback_reason`
+
+### 0.5.2 降级红线
+
+| 红线 | 说明 |
+|---|---|
+| 🔴 `RAGService.retrieve()` **永不抛异常** | 任何失败都必须转成 `degraded=True` 的响应 + `fallback_reason` + `warnings` |
+| 🔴 适配器异常**必须包装** | 统一包装为 `StoreUnavailableError`（或对应错误类型），供上层降级判断 |
+| 🔴 空召回必须给出提示语 | `context_block` 必须用 `rag_contracts.agent_tool.EMPTY_CONTEXT_HINT`（**单一真理源，禁止另写一份**） |
+
+### 0.5.3 可观测（`cg_observability`，已存在）
+
+```python
+from cg_observability import TokenMeter, TraceContext, get_logger, log_event
+
+_LOG = get_logger("rag_core.<模块名>")     # 命名空间与模块路径一致
+
+log_event(_LOG, "<事件名>", trace_id=trace_id, <字段>=<值>)
+# 事件名风格：retrieve.start / retrieve.dense / retrieve.degrade / context.build ...
+```
+
+| 要求 | 说明 |
+|---|---|
+| 每个新阶段必须打点 | 至少含 `trace_id` 与 `latency_ms` |
+| 耗时统一用 `meter.stage("<阶段名>")` | 阶段名沿用既有 6 个：`embed` / `dense` / `sparse` / `fusion` / `rerank` / `build` |
+| 严禁吞异常不记日志 | `except` 分支必须有 `log_event(..., level="WARNING")` |

+## 0.7 定义归属表（**「不出现重复定义」的核心机制**）

+### 0.7.1 规则
+
+> **任何一个概念/类型/常量，在仓库中只允许有唯一的定义处。**

+### 0.7.3 三条"禁止重复"的具体禁令
+
+1. 🔴 **禁止**在 `ai_engine/rag/*` 里重新实现检索逻辑
+   —— 该目录现存 `HybridRetriever` / `Reranker` 两个空壳，**必须降级为薄桥接**（转调 `rag_core`），不再实现检索。
+2. 🔴 **禁止**再定义第二份 `ScopedClauseMemory`
+   —— 现存两份（`agents/rewriter.py` 用 `list[dict]`；`memory/scoped_memory.py` 用 `list[DialogTurn]`）。
+   **以 `memory/scoped_memory.py` 为准**，另一处改为 import。
+3. 🔴 **禁止**再写一份"条款编号识别正则"
+   —— 唯一处：`rag_core/chunking/simple_chunker.py` 的 `_CLAUSE_HEAD_RE`。
+   OCR 侧的 `NodeExtractor` 若也需要，**必须 import 或提取到共享位置**，
+   否则会出现「解析层认为的第 3 条 ≠ 检索层认为的第 3 条」这类极难排查的 bug。
