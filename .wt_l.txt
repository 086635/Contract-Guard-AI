+### 🔴 关于编号正则的强制约束
+
+**全仓只允许存在一处条款编号识别正则**，唯一处为 `simple_chunker.py` 的 `_CLAUSE_HEAD_RE`。
+
+`SectionAwareChunker` 需要的扩展规则有两种合法做法：
+
+| 方案 | 做法 | 评价 |
+|---|---|---|
+| **A（推荐）** | 把 `_CLAUSE_HEAD_RE` 及其配套常量**提取到一个共享位置**（如 `chunking/patterns.py`），`simple_chunker` 与 `section_chunker` 同时 import | ✅ 唯一处仍成立，只是搬了家 |
+| B | `section_chunker` 直接 `from .simple_chunker import _CLAUSE_HEAD_RE` | 🟡 可行但引用私有名（下划线开头）不规范 |
+| ❌ C | 在 `section_chunker.py` 里**再写一份正则** | 🔴 **严禁**。会造成「解析层认为的第 3 条 ≠ 检索层认为的第 3 条」 |
+
+> 选方案 A 时，**必须同步更新 `simple_chunker.py` 的 import**，
+> 并确认 `SimpleChunker` 的既有测试**全部仍通过**（这是搬家成功的判据）。

+## ⑤ 现状：`SimpleChunker` 的能力与边界
+
+### 5.1 已具备
+
+| 能力 | 说明 |
+|---|---|
+| 编号锚点切分 | `_CLAUSE_HEAD_RE` 支持中文编号（`第五条` / `第五章` / `第3章` / `第五百八十五条`）与阿拉伯编号（`6.2` / `3.1.2` / `1)`） |
+| 🔴 **绝不跨条款边界** | 设计红线，`SimpleChunker` 天然满足（以编号行为锚点） |
+| 超长退化 | 段落超长时退化为 `WINDOW_SLICE` 子块，**强制带 `parent_section_id`** |
+| 前言归集 | 无编号的正文前缀归入 `PREAMBLE` 块 |
+| 确定性 `chunk_id` | 由 `make_chunk_id(doc_id, section_id, slice_idx)` uuid5 生成 |
+
+### 5.2 边界（本任务要解决的）
+
+| 边界 | 影响 |
+|---|---|
+| 平铺切分，**不建父子层级** | `parent_section_id` / `section_path` / `level` 三个字段未被充分利用 |
+| 「章 → 节 → 条」的**归属关系丢失** | 检索到第 5 条时，无法知道它属于"第三章 违约责任" |
+| `section_path` 无法拼出人类可读路径 | 前端展示与 `CitationOut.sourceTitle` 的兜底质量下降 |
+
+> 💡 **收益的直接体现**：`ContextBuilder.format_entry()` 会输出 `[section=xxx]`
+> 与 `doc.title`。层级信息补齐后，注入 Prompt 的上下文会带上"第三章/第六条"这类**结构提示**，
> 有助于 LLM 判断条款归属与冲突关系。

+## ⑥ 接口规格
+
+```python
+class SectionAwareChunker:
+    """层级感知切片器：识别章/节/条/款/项并建立父子关系。
+
+    与 `SimpleChunker` 的关系：
+    - **输出契约完全一致**（同样是 `list[ContractChunk]`），可互换使用；
+    - 差异在于它会填充 `parent_section_id` / `section_path` / `level` 三个层级字段，
+      并把层级信息编码进 `section_id` 的稳定编号中。
+
+    对应：RAG搭建框架.md §5（层级切片）；文件集合/codex/1-8层级切片器.md
+    """
+
+    def __init__(
+        self,
+        *,
+        max_chars: int = 1200,
+        window_chars: int = 800,
+        window_overlap: int = 100,
+        counter: TokenCounter | None = None,
+    ) -> None:
+        """初始化。
+
+        Args:
+            max_chars: 单切片字符上限，超出则退化为窗口子块。
+            window_chars: 窗口子块的目标长度。
+            window_overlap: 窗口子块之间的重叠字符数。
+            counter: Token 计数器；为空则自建。
+        """
+        ...
+
+    def chunk(self, doc: SourceDoc) -> list[ContractChunk]:
+        """把源文档切分为带层级信息的切片序列。
+
+        Args:
+            doc: 源文档（与 SimpleChunker 同一个 SourceDoc 类型）。
+
+        Returns:
+            按文档顺序排列的 ContractChunk 列表；每个 chunk 的
+            parent_section_id / section_path / level 已按层级填好。
+        """
+        ...
+```
+
+### 层级映射规则
+
+| 锚点样式 | `ChunkType` | `level` |
+|---|---|---|
+| `第X章` / `第X节` | `SECTION` | 1 / 2 |
+| `第X条` | `CLAUSE` | 3 |
+| `第X款` / 无编号自然段 | `PARAGRAPH` | 4 |
+| `（一）（二）` / `1.` / `1)` | `ITEM` | 5 |
+| 表格 | `TABLE` | 同其宿主层级 |
+| 超长退化块 | `WINDOW_SLICE` | **同其父块**，且**必须带 `parent_section_id`** |
+
+### `section_path` 拼接规则
+
+```text
+第三章/第六条/6.1        ← 人类可读层级路径，逐级用 / 连接
+```
+
+> ⚠️ 拼接时**只取当前层级的稳定编号**（`section_id`），不要取标题文字 ——
+> 标题文字会随文档措辞变化，导致 `section_path` 不稳定、无法跨版本比对。
+

+## ⑦ 实现规范
+
+| # | 规范 |
+|---|---|
+| 1 | 🔴 **输出契约不可变**：只允许填充 `ContractChunk` **已有**的字段。**新增字段 = 违约** |
+| 2 | 🔴 **`chunk_id` 仍用 `make_chunk_id(doc_id, section_id, slice_idx)`** 生成，保持确定性（uuid5）与跨重建稳定性 |
+| 3 | 🔴 **编号正则唯一处**（见 §③），不得复制 |
+| 4 | `text_hash` 用 `compute_text_hash(text)`，供增量更新跳过 embedding |
+| 5 | **绝不跨条款/法条边界切**（设计红线，`SimpleChunker` 已满足，本实现必须延续） |
+| 6 | 超长段落退化时，`parent_section_id` **必须**指向宿主条款，`slice_idx` 递增 |
+| 7 | 保留 `SimpleChunker` 对 `Sequence` / `SourceDoc` 的入参约定，**便于两者互换** |
+| 8 | 埋点：`chunk.done` 事件包含 `chunks` / `avg_chars` / `max_level` / `window_slices` |
+| 9 | 输出必须**按文档顺序稳定排序**（`seq_in_doc` 单调递增），不得依赖 dict 迭代顺序 |
+

+## ⑩ 避坑清单
+
+| # | 坑 | 后果 | 正确做法 |
+|---|---|---|---|
+| 1 | 输出里新增自定义字段 | **破坏契约**，下游 `from_payload()` 会因 `extra="forbid"` 直接校验失败 | 只用已有字段（用例 9 守卫） |
+| 2 | 重新写一份编号正则 | 解析层与检索层的"第 N 条"不一致，**极难排查** | 方案 A 提取共享，或方案 B import |
+| 3 | 为"完整性"让长条款跨边界续切 | 违反设计红线，检索到半句话 | 用 `WINDOW_SLICE` 子块，**保留父指针** |
+| 4 | `section_path` 拼标题文字 | 随文档措辞变化，跨版本不可比 | 只拼**稳定编号** |
+| 5 | 用 `uuid4()` 生成 `chunk_id` | **每次重建 id 都变** → 向量库产生孤儿点 + gold set 失效 | 用 `make_chunk_id()`（uuid5） |
+| 6 | 删除 `SimpleChunker` | 丢失默认路径与回退，且破坏既有测试 | **保留**，两者并存 |
+| 7 | 依赖 dict 迭代顺序决定 `seq_in_doc` | 输出顺序不稳定 | 显式排序后编号 |
+| 8 | 顺带改 `factory.py` 的默认切片器 | 影响面扩散，可能让默认路径行为突变 | **本次不改**，切换由后续决策 |
