## 5. 三处**实测纠偏 / 文档级发现**（原文保留，理由写明）

1. **§⑧-1 的用例名与 §⑤ 的行为表冲突**：原文 `test_rerank_preset_resolves_when_url_blank`（"留空 → 用预设"）
   与 §⑤「url 为空 → warning + `NoopReranker`（既有行为，保留）」矛盾。**以 §⑤ 为准**：
   留空 URL 不套预设（`test_blank_url_still_falls_back_to_noop` 锁死），预设只补"url 给了 provider 名 / 命中预设"时的 `path`/`model`。
2. **🔴 `RERANK_PRESETS["ollama"]` 不可用**：ollama 0.34 **没有** rerank 端点（`/rerank`、`/v1/rerank`、`/api/rerank` 全 **404**）。
   该条目为兼容 §⑤ 与 `.env.example` 保留，但工厂命中时**打 WARNING**、模块 docstring 也注明；
   **建议 T-A5 收尾时把 `1-6 §⑥.1` / `.env.example` 的 rerank 段改成 TEI**（`http://localhost:8081`）。
3. **冒烟脚本写死 `DENSE_ONLY`**：`scripts/phase1_smoke.py:296` 显式传 `DENSE_ONLY`，
   所以 §⑦.1 断言 4 的"sparse/fusion 阶段"在该脚本里永远看不到（本次用 `HYBRID_RRF` 直跑服务验齐五阶段）。
   **未改脚本**（属脚本/任务层），已在 `1-6 §⑪.6-③` 给出两条修正路径。

> 另：`service.py::_rank()` 有个**防御分支不置位**（第三方 reranker 返回长度不符但**不抛错**时只 warning、不置 `rerank_failed`）。
> 对本项目 `HttpReranker` 无影响（它抛错，走置位路径）；**未改**（`service.py` 不在 C4 落点），已登记建议。

## 8. 影响面与风险（回归判断）

- **默认离线路径零变化**：`rerank_mode` 默认仍是 `noop`；`RagSettings().rerank_mode == "noop"` 有用例锁死。
- **显式配置者零影响**：显式 `rerank_http_url` / `rerank_path` / `rerank_model` 一律优先（预设只补留空）。
- **唯一行为变化**：`rerank_http_url` 写成 provider 名（如 `tei`）时，会被展开为预设 URL；命中 ollama 时多打一条 WARNING（不影响功能）。
- **风险**：精排引入一次额外 HTTP 往返（本机 top-20 ≈ 1.0~3.3 s），会显著增加 `retrieve()` 延迟 → 演示时可用 `CG_RAG_RERANK_TOP_N` 控制喂给精排的候选数（属 T-A8 调参）。
- **依赖红线未破**：`rag-core` 仍不含 `torch` / `sentence-transformers`（验证服务跑在**仓库外**的系统 Python 上）。
