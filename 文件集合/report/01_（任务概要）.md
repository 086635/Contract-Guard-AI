## 4. 为什么"这么多卡片"最后都在做 Milvus？（正面回答）

这是最容易误读的一点，澄清如下：

1. **Milvus 卡片数量 ≠ 权重。** `1-2`(T-A1) / `1-4`(T-A3) / `1-5`(T-A4) / `1.C5` 四份文档
   之所以显眼，是因为 **Milvus 被拆成了"适配器 / 接线 / 编排 / 集成测试"四个可独立验收的切面**，
   而 Qdrant 是在 A 组 P0 那批（`1-1`/`1-3`/`1-6`）里**一次性做完**的，卡片少但分量重。
2. **主力从未改变。** 现状基线写明：**Qdrant 主力，Milvus 备选（P2）**，
   且**代码默认值是 `inmemory`，Milvus 不得成为任何默认值**（AGENTS.md §5.3 红线）。
3. **"可扩展"的代价就是多几个切面。** 想把 Milvus 做成真能插拔的备选，
   就必须有适配器 + 装配分支 + 容器编排 + 集成测试四件套；这正是 B 组存在的意义。
4. **A 组才是关键路径。** A 组（T-A0/A7/A5/A6/A8）**已 100% 闭合**，
   本轮真正补上的核心能力是 **T-A8 评测与召回基线**——它补的正是 RAG 唯一的"零"。

## 5. 定量证据：评测基线（T-A8 / C10）

四份基线全部为**真实跑出**（非占位），落点 `scripts/data/baseline_*.json`：

| 标注集 | 条数 | 后端 / 策略 | Recall@1 | Recall@5 | MRR | 空召回率 |
|---|---|---|---|---|---|---|
| **人工** `gold.jsonl` | **60** | inmemory + hash + DENSE_ONLY | 0.733 | **0.767** | 0.750 | 20.0% |
| **人工** `gold.jsonl` | **60** | qdrant + **bge-m3** + HYBRID_RRF + 精排 | 0.883 | **0.933** | 0.908 | 6.7% |
| **弱** `weak_gold.jsonl` | **121** | inmemory + hash + DENSE_ONLY | 1.000 | 1.000 | 1.000 | 0.0% |
| **弱** `weak_gold.jsonl` | **121** | qdrant + bge-m3 + HYBRID_RRF + 精排 | 1.000 | 1.000 | 1.000 | 0.0% |

**关键读数**：真实语义 + hybrid + 精排把人工集 **Recall@5 从 0.767 拉到 0.933**（达到 §8.3 的 ≥0.80 目标），
**空召回率 20.0% → 6.7%**，MRR 0.750 → 0.908。

口径纪律：人工集与弱标注集**按文件级区分、写进 `meta.gold_source`、永不合并成单一数字**（DoD 硬要求）。
退出码约定：`0` 通过 / `1` 回归退化（`recall@5` 跌幅 > 0.05，打印逐条退化 query_id）/ `2` 输入或配置错误。
