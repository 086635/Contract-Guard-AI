## 2. 指标口径（写死，不得中途更换）

| 指标 | 口径 |
|---|---|
| `Recall@K` | **命中即算**：`gold_chunk_ids ∩ topK ≠ ∅` 记 1，对全部 query 取均值（`1-7 §5.1`） |
| `MRR` | `1 / rank_of_first_gold`（topK 内无 gold 记 0）的均值（`1-7 §5.2`） |
| 另记 | `empty_recall_rate`（缺失标准对照信号）、`avg_top_score`、`avg_latency_ms`（仅 `--with-timing`） |

## 3. 实测数字（**核心证据**）

| 配置 | 集 | n | Recall@1 | **Recall@5** | MRR | 空召回率 | avg_top_score |
|---|---|---|---|---|---|---|---|
| `hash + noop + inmemory`（`DENSE_ONLY`） | 人工 | 60 | 0.733 | **0.767** | 0.750 | **0.200** | 0.365 |
| `http(bge-m3) + http(bge-reranker) + qdrant(local_memory)`（`HYBRID_RRF`） | 人工 | 60 | 0.883 | **0.933** | 0.908 | **0.067** | 0.872 |
| `hash + noop + inmemory` | 弱 | 121 | 1.000 | 1.000 | 1.000 | 0.000 | 0.986 |
| `http(bge-m3) + http(bge-reranker) + qdrant(local_memory)` | 弱 | 121 | 1.000 | 1.000 | 1.000 | 0.000 | 1.000 |

> - **弱标注集饱和是设计内的**：query 就是切片原文，自检索对伪向量也几乎必然命中 → 只作**回归门禁**，
>   **不能**当能力证据（`1-7 §⑩` 避坑 2）。
> - 人工集剩余 4 条 `EMPTY_RECALL`（`q008` 预付款比例、`q026` 质量保证金、`q042` 对外宣传、`q060` 附随义务）
>   属"该空召回是否合理"的人工抽查范围（`1-7 §8.3` 第三行）。
> - 延迟（CPU 参考）：精排每次 2.4~7 s（争用时可到 30~46 s）；121 条弱集的 http 跑一次约 **2389 s**。

## 5. 口径裁决与四条实测发现

**并集口径**（两份 L0 文档冲突，取并集 + 纠偏；细节见 `1-7 §⑪.1`）：
gold 字段 = 必填 `query_id`/`query`/`gold_chunk_ids` + 可选 `contract_type`/`source_types`/`note`/`source`；
CLI = 两文档并集 + `--dump-chunks`/`--make-weak`/`--with-timing`/`--force`；
**人工 vs 弱按文件级区分**并写入 `meta.gold_source`（**永不合并**）。

1. **`rerank_top_n` 会截断 Recall@K**：`_rank()` 在精排生效时按 `rerank_top_n`（请求默认 5）截断 →
   脚本固定 `top_k = rerank_top_n = max(cutoffs)`，并记入 `meta`。
2. **基线指纹必须覆盖数据集**：`config_fingerprint` = 哈希(配置 + 语料内容 + 标注集内容) →
   拦住"拿 hash 的基线比 http 结果""拿弱标注基线比人工标注结果"（不一致即退出码 2，`--force` 可越过）。
3. **确定性要主动设计**：默认输出剔除 `created_at` 与全部耗时字段，`--json` 时静音 `rag_core` 埋点 →
   stdout 是纯 JSON 且可逐字比对（否则 1-7 §⑨ 的"逐字相同"永远不成立）。
4. 🔴 **`strategy` 目前不 gate 融合路径**（编排器缺口，未越界改）：`retrieve()` 无条件
   dense + sparse + `_fuse()`，`strategy` 只进日志 → `DENSE_ONLY` 与 `HYBRID_RRF` **排序上无差别**。
   故上表两行的差异**只能归因于语义栈与精排**，不能归因于策略；已在 `1-7 §⑪.3-1` 登记待办（C8/T-A7）。
