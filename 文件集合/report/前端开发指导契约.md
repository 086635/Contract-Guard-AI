## 6. API 接口规范与"已开发"清单

### 6.1 通用规范（来自 `data_scheme.md`）

- **camelCase 字段 / kebab-case URL**：请求体、Query、Path 参数一律 camelCase（如 `contractId`，**不是** `contract_id`）。
- **统一响应包络**：成功 = `{ code:"SUCCESS", traceId, serverTime, data: <T> }`；失败 = `{ code: ErrorCode, message, detail, traceId }`（HTTP 状态码对应 400 / 404 / 409 / 413 / 415 / 500 / 502 / 504）。
- **集合兜底**：所有数组字段无数据时后端返回 `[]`，前端可安全 `.map`。
- **X-Request-ID**：写操作（POST / PUT）由 `client.ts` 自动注入 UUID 幂等头，你无需手动加。
- **时间**：ISO8601 带时区；前端按本地时区格式化。
- **SSE 特例**：`GET /tasks/{taskId}/stream` 是 `text/event-stream`，用浏览器原生 `EventSource`（**不能**带自定义 Header，X-Request-ID 不会发送）；事件 `data` 是 JSON 字符串，按 `ProgressMessage` / `AuditMessage` 解析。

## 7. 接入方式（代码层，红线）

### 7.1 单一 HTTP 客户端（必须遵守）

所有请求走 `src/api/client.ts`（`httpClient` 单例），**禁止** `fetch` / 新 `axios.create()` / 其他请求库（契约 §6.1）。它已自动注入 X-Request-ID；响应拦截里的 Zod 运行时断言目前是 TODO（尚未启用），**真正的运行时校验来自 §7.2 的 Zodios 客户端**（或你手动 `safeParse`）。

### 7.2 类型安全调用

**用生成好的 Zodios 客户端（推荐，零手写类型）**

```ts
// src/api/index.ts（你新建）
import { httpClient } from "@/api/client";
import { createApiClient } from "@/api/generated/zod";

// 复用全局单例（保留 X-Request-ID / Zod 拦截），由 Zodios 持有 /api/v1
export const api = createApiClient("/api/v1", { axiosInstance: httpClient });
```

```ts
// 在页面里
const res = await api.getContract({ params: { contractId } });
// res = { code, traceId, serverTime, data: Contract }
const contract = res.data;            // 领域对象
```

> 生成的方法别名即 `api.<alias>(...)`，与 OpenAPI operationId 一一对应，类型由 `zod.ts` 推导。常用：`listContracts` / `getContract` / `presignUpload` / `uploadContract` / `getElements` / `getRisks` / `getSeals` / `getConflicts` / `commitContract` / `createFeedback` / `generateReport` / `getReport` / `rewriteClause` / `listRules` / `getRule` / `updateRule` / `getTask` / `streamTask`。参数结构（`params` / `body`）也与 OpenAPI 完全对齐，无需手写类型。

> 注意：若实际请求路径出现重复 `/api/v1/api/v1`，将 `client.ts` 的 `baseURL` 改为空串（由 Zodios 统一持有 `/api/v1`），X-Request-ID 拦截不受影响。

**B. 手写 endpoints 层（不引入 Zodios 也能用）**

```ts
// src/api/endpoints.ts
import { httpClient } from "@/api/client";
import type { components } from "@/api/generated/types";
type Contract = components["schemas"]["Contract"];

export async function fetchContract(id: string): Promise<Contract> {
  const r = await httpClient.get<{ data: Contract }>(`/contracts/${id}`);
  return r.data.data;
}
```

（`client.ts` 响应拦截里已有 Zod 校验的 TODO，启用后会在 DEV 自动断言 payload。）

| `IN_REVIEW`      | commit 遇 `ERR_DATA_CONFLICT`（version 冲突） | 保持 `IN_REVIEW`   | 弹窗「覆盖保存 / 重新拉取」二选一（见 §9.2.1 乐观锁冲突分支） |
| `FINALIZED`      | （终态，只读）                                  | —                | 禁用编辑，仅可查看 / 导出报告               |

> 说明：`UPLOADING → PARSING` 由后端 MinIO 回调驱动；前端只需轮询 / SSE `GET /contracts/{id}/parse-status` 与 `GET /tasks/{taskId}`（或 `/stream`）感知状态扭转，**不要在** **`contractId`** **未就绪时发起 C/D/E/F 下游请求**（§5.2 显式约束）。

#### 9.2.2 长耗时任务状态机（TaskProgress.status）

| 当前状态      | 触发事件                                  | 下一状态         | 前端表现                 |
| --------- | ------------------------------------- | ------------ | -------------------- |
| —         | `POST /contracts/upload` 等返回 `taskId` | `RUNNING`    | 进度条 `percent` 0→1 递增 |
| `RUNNING` | SSE / 轮询回报 `status=DONE`              | `DONE`（终态）   | 触发下游并发（C/D/E/F）      |
| `RUNNING` | SSE / 轮询回报 `status=FAILED`            | `FAILED`（终态） | 错误卡 + 重试入口           |

> 进度结构：`{ taskId, stage, percent(0~1), status: 'RUNNING'|'DONE'|'FAILED', result? }`。
> 订阅方式：优先 **SSE** `GET /tasks/{taskId}/stream`；降级轮询 `GET /tasks/{taskId}`。

#### 9.2.3 异常流转分支（与状态机叠加，§4）

| 异常场景          | HTTP 状态码 | 响应体 `code`                                         | 前端动作                  |
| ------------- | -------- | -------------------------------------------------- | --------------------- |
| 参数校验失败        | 400      | `ERR_VALIDATION`                                   | 表单内联报错                |
| 未登录 / 无权限     | 401/403  | `ERR_UNAUTHORIZED` / `ERR_FORBIDDEN`               | 跳转登录 / 提示无权限          |
| 合同不存在         | 404      | `ERR_CONTRACT_NOT_FOUND`                           | 空态「合同丢失」+ 返回列表        |
| 解析失败（OCR/LLM） | 502      | `ERR_OCR_FAILED` / `ERR_LLM_TIMEOUT`               | 错误卡 + 「重新上传」          |
| 乐观锁冲突         | 409      | `ERR_DATA_CONFLICT`                                | 「覆盖保存 / 重新拉取」弹窗（见 §9.2.1） |
| 幂等拦截（重复提交）    | 409      | `ERR_DUPLICATE_REQUEST`                            | 静默返回首次结果，不打扰用户        |
| 文件过大 / 类型不支持  | 413/415  | `ERR_FILE_TOO_LARGE` / `ERR_UNSUPPORTED_FILE_TYPE` | 上传前前端预校验拦截            |
| 反馈重复提交        | 409      | `ERR_FEEDBACK_ALREADY_EXISTS`                      | 提示「已反馈」               |
| 系统内部错误        | 500      | `ERR_INTERNAL`                                     | 全局错误条 + 重试            |

> 约定：HTTP 状态码仅表网络/系统层；**业务异常一律走响应体** **`code`** **+** **`message`** **+** **`detail`**，禁止纯数字编码。所有 `code` 来自 `data_scheme.md` §4.1 的 `ErrorCode` 枚举。
> 注：当前 19 个端点**尚未接入鉴权**（无 401/403 流程），上表 401/403 两行是未来接入登录后的预期；前端现阶段无需实现登录页，但请保留对 `code` 分支的处理，以便平滑升级。

## 13. 质量红线（务必遵守）

- 只用 `client.ts` 发请求（§7.1 单实例）。
- 响应须经 Zod 校验：优先用 §7.2 的 Zodios 客户端（自动校验）；若走 `httpClient`，请手动 `safeParse` `@/api/generated/zod` 的 `schemas`。`client.ts` 拦截器的 Zod 断言尚为 TODO，不要依赖它。
- 禁止手写 API 类型 / `generated/` 文件；只 `import`。
- 列表 / 数组永远按"可能为空"处理（后端返回 `[]`）。
- 写操作无需手动加 X-Request-ID（client.ts 已注入）。
- 四态矩阵（Loading / Empty / Success / Error）覆盖每个数据视图（见 `data_scheme.md` §5.1）。
