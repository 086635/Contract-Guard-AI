```python
# rag_core/provider_presets.py

    "tei":     {"base_url": "http://localhost:8080",     "path": "/embed",         "model": "BAAI/bge-m3"},
    "openai":  {"base_url": "https://api.openai.com/v1", "path": "/embeddings",    "model": "text-embedding-3-large"},
}
RERANK_PRESETS: dict[str, dict[str, str]] = {
    "ollama":  {"base_url": "http://localhost:11434/v1", "path": "/rerank", "model": "bge-reranker-v2-m3"},
    "tei":     {"base_url": "http://localhost:8080",     "path": "/rerank", "model": "BAAI/bge-reranker-v2-m3"},
}
def resolve_preset(kind: Literal["embed", "rerank"], provider: str) -> dict[str, str]: ...
```

**维度校验口径（唯一处）**：`HttpEmbedder` 拿到向量后，若 `len(vector) != settings.vector_dim` →
记 `embed.dim_mismatch` warning + **该批返回 None**，由 `factory`/`service` 走既有降级（`HashEmbedder` 兜底）。

> ⚠️ **落地纠偏（2026-09-22，实测后）**：上面这句里的「**该批返回 `None`**」**不可实现** ——
> `EmbedderPort` 是**冻结**协议（`embed_batch(texts) -> list[list[float]]`，`rag_contracts/ports.py`），
> 返回 `None` 会让 `service.retrieve()` 的候选聚合直接 `TypeError`，而改 `service.py` 又不在本卡授权内
> （`0.§0.11.2` + 卡片 §①）。**按同一意图改用既有错误类型**：记
> `embed.degrade`（`level=WARNING`、`reason=dim_mismatch`、带上 `expected_dim` / `actual_dim` / `batch`）
> 后抛 `EmbedFailedError`（`TransientRagError`，`code=CG-RAG-1002`）→ `service.retrieve()` 已把它
> 降级为 `degraded=True`（实测：全量冒烟里这条路径可复现）。**不截断、不补零**这条红线未变。
> 另：`resolve_preset` 之外还加了 `detect_provider(kind, base_url)` 一个公开符号（见 §⑥-2 纠偏），
> 用于在**不新增配置项**的前提下选择 provider。

## ⑥ 实现规范

1. 🔴 **默认必须离线**：`embed_mode` 的代码默认值仍是 `hash`，`provider` 预设只在 `embed_mode=http` 时生效。
2. 🔴 **预设只补"留空"**：`base_url` / `path` / `model` 只要显式配置了，就以配置为准（预设不得覆盖用户值）。
3. 🔴 **维度不符不硬扛**：长度不符 → warning + 降级（**不要**截断/补零，那会静默污染向量库）。
4. 🔴 **批量分批**：按 `embed_batch_size` 切块；单批失败**不吞**——整批返回 None 并记 warning，由上层决定降级。
5. ⚠️ **超长文本**：按 `CG_RAG_MAX_QUERY_CHARS` 截断后送服务（与 2-5 的"防线 1"同口径，但**各管各的层**：工具层截 query、本层截 embedding 输入）。
6. ⚠️ **打点**：`log_event("embed.done"/"embed.degrade", provider=…, dim=…, batch=…, latency_ms=…)`。
7. ⚠️ **真实服务用例必须可跳过**：`CG_RAG_TEST_EMBED_BASE_URL` 未设置 → `pytest.mark.skipif`（`0.§0.6.2`）。

> ⚠️ **落地纠偏（2026-09-22，实测后）**：第 5 条的「按 `CG_RAG_MAX_QUERY_CHARS` 截断」与
> 本文档 §⑩-4（"口径各自声明，不要引用彼此的实现"）**自相矛盾**，且与 **C9 的字段归属冲突** ——
> `config.py` 里 `max_query_chars` 的 description 明确写「消费方：Agent 工具层「防线 1 · 超长拦截」
> （T-B4）；**rag-core 不实现切分（分层红线）**」，`1-3配置与工厂接线.md` §⑧ 亦同。
> **裁决**（谁的红线优先）：采用 **C9/T-B4 的归属**，本层**不做本地截断**，
> 并在 `HttpEmbedder.embed_batch` 的 docstring 里**显式声明本条口径**（超长文本原样送出，
> 服务端拒绝即 `EmbedFailedError` → 上层降级）；用例 `test_overlong_text_is_not_truncated_locally`
> 把这条口径锁死。若将来确需"模型侧输入上限"，应由 **C9 新增独立字段**（如 `embed_max_chars`），
> **不得复用 `max_query_chars`**（否则同一配置项出现两个语义不同的消费方）。
>
> ⚠️ **§⑥-2 的补全（provider 从哪来）**：第 2 条只说了"预设只补留空"，但没说**谁选 provider**。
> 本卡不允许新增 `embed_provider` 配置项（配置唯一处是 C9），故新增**唯一处**函数
> `provider_presets.detect_provider(kind, value)`，从既有配置值反查两种形态：
> ① 值本身就是 provider 名（`CG_RAG_EMBED_BASE_URL=ollama`）；② 值是 URL 且 `host:port` 命中预设表
> （`…:11434/v1` → ollama）。两者都实测通过；**其它自定义端点不套预设**（只按配置值走）。
