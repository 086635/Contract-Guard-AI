## ⑩ 落地记录与实测纠偏（**2026-09-24**）

### ⑩.1 `search` 用默认一致性 → **静默 0 命中**（真 server 专有）

真 server 上「`upsert` 后立刻 `search`」会返回 **0 条**，而同一时刻 `count()` 已能看到数据 ——
即 **假空召回**（不报错、不降级，比异常更难排查）。对照实验（同一进程、同一对向量）：

| 调用 | 结果 |
|---|---|
| `store.search(q, 10)`（适配器原实现，无 `consistency_level`） | **0** |
| 同上但 `consistency_level="Strong"` | **10** |
| `store.count()`（本就是 Strong） | **24** |
| 再调 `store.search(q, 10)`（上一次 Strong 查询推进了会话时间戳） | **10** |

**处置**：`search` 显式带 `consistency_level="Strong"`（与 `count()` 同口径）。
**排除过的替代解释**：不是 `load_collection` 未就绪 —— 试过「等 `get_load_state` 到 `Loaded`」
与「已 Loaded 则跳过 load」，都不能消除 0 命中（`get_load_state` 会**抢报 Loaded**）。

### ⑩.2 COSINE `score` 口径在**两个后端相反**

同一对向量（Python 自算 `cos(v0, v1) = 0.0586883`）在两个后端的原始 `distance`：

| 后端 | 自检索 | `cos = 0.0587` 时 | `distance` 语义 |
|---|---|---|---|
| `milvus-lite 3.0`（`mode="lite"`） | `0.0` | `0.9413117` | **余弦距离** `1 - cos` |
| `milvusdb/milvus v2.5.4`（`mode="server"`） | `1.0` | `0.0586883` | **余弦相似度** `cos` |

两列互为补数 → 确证是同一原始余弦值的两种口径。原实现固定 `1 - distance`（**按 lite 实测写的**，
见 `1-2 §⑪.2-#4`），在真 server 上会把 `score` **整体反向** ——
而 `RAGService.score_threshold`（默认 0.35）直接作用在 `score` 上，**真相关切片会因「分数高」被当噪声丢掉**。

**处置**：按 `self._mode` 分派（server 取原值 / lite 取 `1 - distance`）；
离线守卫用例改为**两个后端各验一次**。详见 `1-2 §⑪.7`。
