## ⑤ 接口规格

### 5.1 依赖注入

```python
# ai_engine/graphs/deps.py
@dataclass(frozen=True, slots=True)
class GraphDeps:
    """图依赖容器。

    为什么不塞进 state：checkpointer 需要序列化 state，
    模型与工具句柄不可序列化 —— 故依赖走**闭包注入**。
    """

    rag_tool: Callable[..., AgentRAGToolResult]   # 2-5 提供；可调用对象即可
    llm: BaseChatModel | None = None              # None → 由 llm.get_chat_model() 惰性获取
    prompt_lib: PromptLibrary | None = None       # None → 空库（所有 LLM 阶段将 SKIPPED）
    max_clauses: int = 100                        # 单次审核条款上限
    max_conflict_pairs: int = 50                  # 冲突精判候选对上限
    conflict_batch_size: int = 10                 # 每次 LLM 调用处理的对数
```

### 5.2 图构造

```python
# ai_engine/graphs/audit_graph.py
def build_audit_graph(deps: GraphDeps, *, checkpointer: BaseCheckpointSaver | None = None):
    """构造并编译审核图（固定 6 阶段，**同步**执行）。

    Args:
        deps: 依赖容器。
        checkpointer: 检查点保存器；开发用 InMemorySaver，生产见 2-8（决策 D2-c）。

    Returns:
        已编译的 StateGraph（`invoke` / `ainvoke` 均可）。
    """
```

**拓扑（唯一处，禁止在别处再写一遍）**：

```text
START → classify → extract → risk → conflict → standard_compare → report_draft → END
```

| 节点 | 读 | 写（增量） | 降级 |
|---|---|---|---|
| `classify` | `clauses` | `contract_type`、`llm_calls+1` | 模板缺失 → `SKIPPED`，`contract_type=None` |
| `extract` | `clauses`、`elements` | `elements` | 无解析结果且 LLM 不可用 → 保留空列表 + warning |
| `risk` | `clauses`、`contract_type`、`tolerance` | `risks`、`rag_calls+n`、`llm_calls+n` | RAG 失败 → 无上下文继续；LLM 失败 → 跳过该条款 + warning |
| `conflict` | `clauses` | `conflicts`、`llm_calls+n` | 候选对为 0 → 空结果 + `detail="无可疑条款对"` |
| `standard_compare` | `clauses`、`contract_type` | `missing_clauses`、`rag_calls+n` | 空召回 → **正是缺失信号**（不是错误） |
| `report_draft` | `risks`、`conflicts`、`missing_clauses` | `report_draft`、`health_score` | **纯聚合，不调 LLM**，无可降级点 |

### 5.3 `extract` 节点的边界（**最容易被做重的地方**）

```text
文档 →【模块 3】doc_processor.NodeExtractor → ParsedElement[]（含 bbox/confidence）
                    ↓ 由 worker 注入 state.elements（2-6）
本节点只做：归一化（字段收敛到 ContractElement）→ 去重 → LLM 补漏（仅当 elements 为空）
```

🔴 **本节点不得解析 PDF / 不得再写一套要素正则**：那会与 `doc_processor` 形成第二处定义（L3 **F6** 的同类错误）。

### 5.4 冲突节点：先粗筛、后精判（**性能红线落地**）

```text
① 规则粗筛（零 LLM 成本）
   付款组：付款 / 支付 / 价款 / 结算 / 发票
   责任组：违约 / 赔偿 / 责任 / 免责 / 不可抗力
   期限组：期限 / 有效期 / 提前 / 终止 / 续约
   → 同组内两两配对，产出候选对（上限 max_conflict_pairs=50，超出按"条款跨度"排序截断）

② LLM 精判（批量）
   每 conflict_batch_size=10 对打包成一次 invoke_structured →
   List[CrossClauseConflict]，代码回填 id / sourceClauseId / targetClauseId
```

### 5.5 `health_score` 计算规则（**本文件唯一定义处**）

```text
风险扣分（按 RiskLevel）      HIGH=10  MEDIUM=5  LOW=2
矛盾扣分（按 RiskLevel）      HIGH=8   MEDIUM=4  LOW=1
缺失标准对照扣分              每条 3

维度归类（**类别 → 维度，唯一映射**）：
  performanceRisk 类：UNLIMITED_LIABILITY / LIABILITY_IMBALANCE / PENALTY_TOO_HIGH
                     / PAYMENT_TERM_RISK / UNILATERAL_TERMINATION
                     + 矛盾类型 PAYMENT_CONTRADICTION / LIABILITY_CONTRADICTION
  compliance 类：     UNFAVORABLE_JURISDICTION / MISSING_DISPUTE_CLAUSE / FORCE_MAJEURE_ABSENT
                     / IP_OWNERSHIP_RISK / VAGUE_CONFIDENTIALITY / OTHER
                     + 矛盾类型 TERM_CONTRADICTION / OTHER

compliance          = clamp(100 - Σcompliance 扣分, 0, 100)
performance_risk    = clamp(100 - Σperformance 扣分, 0, 100)
clause_completeness = clamp(100 - 3 × len(missing_clauses), 0, 100)
overall             = round(0.4×compliance + 0.4×performance_risk + 0.2×clause_completeness)

字段名与 openapi `HealthScore{overall, dimensions{compliance, performanceRisk, clauseCompleteness}}` 对齐。
```

## ⑥ 实现规范

1. 🔴 **节点签名统一** `_node(state: AuditState, deps: GraphDeps) -> dict`，注册时用 `functools.partial` 绑定 `deps`；**不接 `config` 参数**（避免把依赖藏在 config 里）。
2. 🔴 **节点永不抛异常**：整体 `try/except Exception` → `warnings` + `stage_log(status="DEGRADED", detail=...)`（标准 §0.5.2）。
3. 🔴 **每阶段必须打点**：`log_event(_LOG, f"audit.{stage}", trace_id=..., latency_ms=..., status=...)`；命名空间 `get_logger("ai_engine.graphs.nodes")`。
4. 🔴 **预算先于调用**：`clauses[: deps.max_clauses]`，超限时写 warning `f"条款数 {n} 超过上限 {m}，仅审核前 {m} 条"`；冲突候选同理。
5. 🔴 **`id` / `clauseId` / `bbox` 由代码回填**，Prompt 里只让模型产出 `category / level / title / suggestion / reasoningSteps / citations`。
6. 🔴 **RAG 上下文必须进 Prompt 且必须回填 citations**：`AgentRAGToolResult.citations` → `EnhancedRiskItem.citations`（否则"报告含法律依据"指标拿不到分）。
7. 🔴 **空召回合规**：`status == "EMPTY"` 时把 `context_block`（即 `EMPTY_CONTEXT_HINT`）原样注入 Prompt，**不得**另写提示语（标准 §0.5.2）。
8. ⚠️ **`tolerance` 只通过 Prompt 变量影响模型**，不在代码里分支改阈值（阈值属 RAG 侧配置）。
9. ⚠️ **阶段名一律取自 `AUDIT_STAGES`**；`stage_log[].stage` 与 SSE `stage` 同源。
10. ⚠️ 同步调用（Celery 是同步 worker）：`graph.invoke(...)`；若将来提供异步 API，用 `ainvoke` 并在 `2-6` 注明。
11. ⚠️ `report_draft` 结构固定为 `{"summary": str, "risk_counts": {HIGH/MEDIUM/LOW: int}, "top_risks": [...], "health_score": {...}}`，供 `2-6` 直接落库/推 SSE。

## ⑨ 避坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | 为每个条款建节点 | 节点数 = 条款数 → checkpoint 巨大、编译耗时爆炸。**Graph 只有 6 个节点**，条款循环写在节点内部 |
| 2 | 冲突节点 O(n²) | 100 条款 = 4950 次调用。必须"规则粗筛 → 批量精判" |
| 3 | 把 `deps` 塞进 state | checkpointer 无法序列化。依赖走闭包（§⑤.1） |
| 4 | 节点里 `new ChatOpenAI()` / 读 `os.getenv` | 违反 2-2 的单一构造点与标准 §0.4 |
| 5 | 忘了传 `thread_id` | `InMemorySaver` 下会直接报错；`2-6` 必须传 `contract_id` |
| 6 | 让 LLM 产出 `id` / `bbox` | 幻觉 id 会污染溯源与前端高亮；一律代码回填 |
| 7 | 空召回时另写兜底话术 | 必须用 `EMPTY_CONTEXT_HINT`（标准 §0.5.2，单一真理源） |
| 8 | `report_draft` 里再调一次 LLM | 该节点是**纯聚合**，调 LLM 会让分数不可复现 |
| 9 | 用 `timezone.utc` / 字符串字面量阶段名 | 前者触发 `UP017`，后者与 `AUDIT_STAGES` 漂移 |
| 10 | 在节点里 `await` | Celery 是同步 worker；本图用 `invoke` |

### 建议推进顺序（3.0 人日的拆法）

```text
a) deps.py + audit_graph.py 骨架 + classify/extract      ≈ 1.0 人日（先让图能跑起来）
b) risk + standard_compare（含 RAG Tool 调用与缺失检测）   ≈ 1.2 人日（赛题核心指标）
c) conflict + report_draft + health_score（含预算与降级）  ≈ 0.8 人日
```
