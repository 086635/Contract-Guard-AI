**Diff 生成算法（唯一处）**：

```text
1. before_lines / after_lines = 原文与改写文的 splitlines()
2. matcher = difflib.SequenceMatcher(None, before_lines, after_lines)
3. 产出统一 diff 文本（context=3 行），并原样保留 before / after 全文
4. DiffMessage(type="DIFF", before=<before 全文>, after=<after 全文>, clauseId=<clause_id>)
```

## ⑥ 实现规范

1. 🔴 **`thread_id` 必须组合**：只传 `contract_id` 会让同合同下多条款的改写互相污染（模块总纲 §2.4.2 明确警示）。
2. 🔴 **上下文预算**：Prompt 里只放「当前条款全文 + 近 3~5 轮对话 + RAG top 3~5 条」，**禁止**塞入整份合同（`max_context_tokens` 预算由 `1-6` 侧的上下文构建负责）。
3. 🔴 **`ScopedClauseMemory` 只 import 不复制**；改完后 `agents/rewriter.py` 内**不得**出现 `class ScopedClauseMemory`。
4. 🔴 **幂等表必须有界**：`OrderedDict` + 上限（默认 256 条），命中即返回同一 `RewriteResponse`（**不重复调 LLM**）；表满淘汰最旧。
5. 🔴 **记忆写入时机**：只在 `finalize` 成功后 `record_turn(role="USER")` + `record_turn(role="ASSISTANT")` + `set_draft(after)`；**失败不写**（避免污染下一轮上下文）。
6. 🔴 **时间戳** `datetime.now(UTC).isoformat()`（**不要** `timezone.utc`，会新增 ruff `UP017`）。
7. 🔴 **降级**：RAG 不可用 → `rag_context=None` 继续改写（`citations=[]`）；LLM 调用最终失败 → 抛
   `RewriteUnavailableError`（`ai_engine/agents/errors.py`，**继承 `rag_contracts.errors.RagError`**，
   `retryable=True`，沿用基类默认错误码），由 API 层转 5xx 或降级文案。
   > ⚠️ 这是模块 2 **唯一**允许抛异常的运行期路径：`RewriteResponse` 契约**没有** `warnings` 字段（且已冻结），
   > 无法像 `AuditState` 那样把失败写进状态。登记在 §⑨ 第 6 条。
8. ⚠️ 阶段名一律取自 `REWRITE_STAGES`；埋点事件 `rewrite.prepare` / `rewrite.generate` / `rewrite.finalize`。
9. ⚠️ `reasoning_steps` / `citations` 字段名与 `RewriteResponse` 一致（snake_case，该模型未用 alias）。

## ⑨ 避坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | `thread_id` 只用 `contract_id` | 同合同多条款互相污染（模块总纲明确点名） |
| 2 | 保留 `rewriter.py` 里的类定义"以防万一" | 就是 F7 本身；必须删干净（断言 1 会抓） |
| 3 | 把整份合同塞进 Prompt | Token 爆炸且改写漂移；只放当前条款 + 近 3~5 轮 + RAG top3~5 |
| 4 | Diff 只给文本不给全文 | 前端并排对照需要 `before` / `after` 全文（`DiffMessage` 三字段） |

| 8 | 复用 `2-4` 的 `AUDIT_STAGES` 当改写阶段名 | 两套阶段语义不同；各自常量分开定义（`AUDIT_STAGES` / `REWRITE_STAGES`） |
| 9 | 直接 `from rag_core import RAGService` 调检索 | 绕过 `RagTool` 的三道防线与埋点；一律经 T-B4 |
