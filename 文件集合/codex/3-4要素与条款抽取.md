## ⑤ 接口规格

### 5.1 共享正则（`rag_contracts/patterns.py`）

```python
# packages/rag-contracts/rag_contracts/patterns.py
"""跨模块共享的词法模式（**唯一定义处**）。

设计要点：
1. 条款/法条编号的识别必须**全仓唯一** —— 解析层与检索层若各持一份，
   会出现"解析层认为的第 3 条 ≠ 检索层认为的第 3 条"，溯源与高亮会整体错位。
2. 本模块被 `rag_core.chunking.simple_chunker` 与 `doc_processor.parser.extractor`
   **共同 import**，因此必须放在**零重型依赖**的契约层（而非解析层）。
"""

from __future__ import annotations

import re

CLAUSE_HEAD_RE: re.Pattern[str] = re.compile(
    r"^\s*(?P<num>"
    r"第[一二三四五六七八九十百千零〇\d]+[条章节款项]"
    r"|\d+(?:\.\d+)+"
    r"|\d+\)"
    r")\s*(?P<rest>.*)$"
)
```

> ⚠️ **迁移纪律**：上面这段正则**逐字取自** `simple_chunker.py` 的现有实现，
> 迁移**只允许改变"定义位置"**，不允许顺手"优化"（改语义 = 改变切片结果 = 触发 RAG 侧回归）。

### 5.2 抽取接口

```python
# doc_processor/parser/extractor.py
@dataclass(frozen=True, slots=True)
class TextLine:
    """行级文本单元（解析层的通用"行"）。"""

    page: int
    text: str
    x: float          # PDF_POINTS
    y: float
    width: float
    height: float
    char_start: int   # 在全文字符串中的起始偏移（0-based，半开区间）
    char_end: int     # 结束偏移（不含）


class LocalNodeExtractor(NodeExtractor):
    """要素与条款抽取（规则优先）。

    设计要点：
    1. **规则优先**：数字版 PDF 与 DOCX 都能靠行数据 + 正则抽准；
       规则命中的结果不带 LLM 幻觉，且可复现。
    2. 缺要素时 `value=None`、`confidence=0.0` —— **绝不编造**。
    3. 条款切分复用 `CLAUSE_HEAD_RE`（**唯一处**）。
    """

    def __init__(self, settings: OcrSettings | None = None) -> None: ...

    def extract_elements(self, source_path: str) -> list[ParsedElement]:
        """抽取合同要素（甲乙方 / 金额 / 签订日期 / 期限 / 管辖地）。"""

    def extract_clauses(self, source_path: str) -> list[ParsedClause]:
        """抽取条款并构建 AST（`level` / `parent_id` / `children_ids`）。"""

    def elements_from_text(self, text: str) -> list[ParsedElement]:
        """纯函数版要素抽取（便于单测，不碰文件系统）。"""

    def clauses_from_lines(self, lines: Sequence[TextLine]) -> list[ParsedClause]:
        """由行序列切分条款（**3-6 的主调用入口**）。"""

    def build_ast(self, clauses: list[ParsedClause]) -> list[ParsedClause]:
        """回填层级关系：`parent_id` / `children_ids` / `level`。"""


def build_node_extractor(settings: OcrSettings | None = None) -> NodeExtractor:
    """工厂：返回本机实现（与 `3-6` 的接线约定）。"""
```

### 5.3 要素规则表（**唯一处**）

| 要素 `key` | 中文 `label` | 规则要点 | 基础置信度 |
|---|---|---|---|
| `party_a` | 甲方 | `甲\s*方[：:\s]*(.{2,40})`，限定首 2 页 | 0.90 |
| `party_b` | 乙方 | `乙\s*方[：:\s]*(.{2,40})`，限定首 2 页 | 0.90 |
| `amount` | 合同金额 | **必须带单位/币种**：`([¥￥]|人民币)?\s*([0-9][0-9,，]*(?:\.[0-9]{1,2})?)\s*(元|万元)`；大写金额 `[壹贰叁肆伍陆柒捌玖拾佰仟万亿]+元整` 若同时命中 → 0.95 | 0.85 |
| `sign_date` | 签订日期 | `\d{4}\s*年\s*\d{1,2}\s*月\s*\d{1,2}\s*日` 或 `\d{4}-\d{2}-\d{2}` | 0.90 |
| `term` | 合同期限 | `自.{2,40}?至.{2,40}` 或 `\d+\s*(个月|个月|年)(?![0-9])` | 0.70 |
| `jurisdiction` | 管辖地 | `.{2,30}(人民法院|仲裁委员会)` | 0.75 |

> 规则统一实现为 `(key, label, pattern, base_confidence)` 元组表（**表驱动**，便于回归与扩展）；
> `is_custom` 一律 `False`（自定义要素属前端配置，不在本任务）。

### 5.4 条款层级判定（**唯一处**）

```text
匹配 CLAUSE_HEAD_RE 的 `num` 字段后：
  第X章        → level = 1
  第X条        → level = 2
  第X款 / 第X项 → level = 3
  n.m（n>=1）  → level = 1 + 段数        # 6.2 → 2 ；3.1.2 → 3
  n)           → level = 3

AST 构建（单遍 + 层级栈）：
  栈中保存"最近一个 level 更小的条款"；新条款 level 更大 → parent = 栈顶；
  level 相当或更小 → 依次弹栈直到找到更小者；
  children_ids 按出现顺序回填；parent_id 无父时为 None。
条款 id：`f"clause-{seq:04d}"`（顺序绑定 + 零填充；**不参与跨模块契约**）
条款文本：从本编号行起，到下一个编号行前一行止（**含编号行**）
```

## ⑥ 实现规范

1. 🔴 **正则唯一性可验证**：迁移后全仓只允许 `rag_contracts/patterns.py` 出现该模式字面量（§⑦.1）。
2. 🔴 **`simple_chunker` 的改动最小化**：只把定义换成 import + 私有别名，**不动其余任何逻辑**；
   跑 `pytest packages/rag-core -q` 必须仍全绿（切片行为不得变化）。
3. 🔴 **要素"不编造"**：未命中 → `ParsedElement(key=..., label=..., value=None, confidence=0.0)`；
   命中但内容含占位符（如"甲方：________"）→ `value=None` + 记 warning。
4. 🔴 **金额必须带单位**：合同里数字极多，取"第一个数字"必错；无单位/币种的裸数字**不作为金额**。
5. 🔴 **日期只认两种格式**，不做自然语言推断（"下月"之类留给人工）。
6. 🔴 **`TextLine.char_start/char_end` 必须由拼接后的全文计算**：调用方（3-6）负责拼接，
   本模块只校验单调不减（`char_start` 递增），不合法则记 warning 并跳过该行。
7. 🔴 **不 import `aligner`**（防循环导入，§③）。坐标已是 PDF_POINTS，本模块**不做任何换算**。
8. 🔴 **打点**：`log_event("ocr.extract", lines=..., clauses=..., elements=...)`；
   命名空间 `get_logger("doc_processor.parser.extractor")`。
9. ⚠️ **单页条款跨页**：条款文本可跨页（下一页继续），切分按**行序列**而非按页；
   跨页条款的行坐标来自各自页（`TextLine.page` 已带）。
10. ⚠️ **超长条款**：不在本任务内切分（切片属 RAG 侧 `simple_chunker`）；本模块只产出条款原文。

## ⑨ 避坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | 另写一份条款编号正则 | 会导致"解析层第 3 条 ≠ 检索层第 3 条"，溯源/高亮整体错位；本任务的核心就是消除这个隐患 |
| 2 | 迁移时"顺手优化"正则 | 会改变切片结果 → RAG 评测基线漂移；**迁移 = 换位置，不改语义** |
| 3 | 把正则放进 `doc_processor` | `rag_core` 将反向依赖解析层（违反标准 §0.3）；必须放零依赖的 `rag_contracts` |
| 4 | 给 `ParsedClause` 加 `bbox` 字段 | 契约冻结；条款级框应由 3-5 的偏移索引按需算出 |
| 5 | 金额取"第一个数字" | 合同里数字遍地；必须带单位/币种 |
| 6 | 日期做自然语言推断 | 会引入不可复现的错误；只认两种固定格式 |
| 7 | 跨页条款被切成两条 | 切分按行序列、`page` 记在 `TextLine` 上 |
| 8 | `extractor` import `aligner` | 形成循环导入（aligner 需要 `TextLine`）；方向必须单向 |
| 9 | 条款 id 用随机/UUID | 评测与 diff 无法复现；用顺序绑定 + 零填充 |
| 10 | 忘记跑 RAG 侧回归 | 迁移正则后**必须**跑 `pytest packages/rag-core -q` |
