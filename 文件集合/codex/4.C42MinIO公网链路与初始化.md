## ⑤ 接口规格

```text
CG_MINIO_ENDPOINT=minio:9000
CG_MINIO_PUBLIC_ENDPOINT=localhost:9000
CG_MINIO_REGION=us-east-1
```

```python
class MinioObjectStorage:
    def presign_put(...): ...   # public client
    def presign_get(...): ...   # public client
    def stat_object(...): ...   # internal client
```

`docker/minio-cors.json` 是允许来源的单一 JSON 数组；MinIO 启动时读取并注入 `MINIO_API_CORS_ALLOW_ORIGIN`，允许 `http://localhost:5173` 与 `http://localhost:8080`。允许方法至少 `GET, PUT, HEAD`，允许必要请求头由 MinIO CORS 中间件处理。

## ⑥ 实现规范

1. public endpoint 未配置时回退 internal endpoint，但 Compose 必须显式设置浏览器可访问地址。
2. 两个 `Minio` client 分别构造，各自签名；禁止把 internal URL 替换 host 后返回。
3. `presign_put` / `presign_get` 只使用 public client；`stat_object` 必须使用 internal client。
4. `minio-init` 必须幂等：重复 `up` 不报 bucket 已存在错误。
5. CORS 来源只允许来自 `docker/minio-cors.json`；`minio` 服务启动时必须读取该文件并注入 `MINIO_API_CORS_ALLOW_ORIGIN`，不得在 Compose 命令或代码中重复硬编码来源。
6. 当前 MinIO 版本不支持 S3 PutBucketCors（mc cors set 实测 HTTP 501）；minio-init 只负责幂等建 bucket，不得回退到无效的 CORS API 调用。
7. 两个 client 都必须显式传入 minio_region，避免 presign 时 SDK 对 public endpoint 发 GetBucketLocation 探测；否则容器内 localhost:9000 会连接失败。
8. 不改变 C19 报告上传的对象 key 和 content type。
