## ② 范围

### ✅ 做

- worker 用 `celery -A worker.main inspect ping`（或等效）做 healthcheck，确保 Celery 能连 broker。
- `CG_CELERY_BROKER` / `CG_CELERY_BACKEND` 固定指 redis（`redis://redis:6379/1`、`/2`）。
- 真实验证 `update_state` 不再 30 s/次空转（结果后端可达）。

### ❌ 不做

- 不改 Celery 任务体、不改 `worker/main.py`。
- 不新增结果后端实现、不新增 skip。

```yaml
worker:
  environment:
    CG_CELERY_BROKER: redis://redis:6379/1
    CG_CELERY_BACKEND: redis://redis:6379/2
  healthcheck:
    test: ["CMD-SHELL", "uv run --package async-worker celery -A worker.main inspect ping -d celery@$$HOSTNAME"]
    interval: 15s
    timeout: 10s
    retries: 5
    start_period: 30s
```

## ⑥ 实现规范

1. `CG_CELERY_BROKER` / `CG_CELERY_BACKEND` 与 `worker/main.py` 的默认值一致（broker `/1`、backend `/2`）。
2. healthcheck 探针必须能真正证明「broker 可达」，不得用恒真命令冒充。
3. 验证 `update_state`：跑一个最小 `parse_doc` 后，结果能在秒级（而非约 30 s/次重试）到达 backend。
4. 离线单测沿用「autouse fixture 置空 `result_backend`」现有写法，不新增 skip（见 `apps/async-worker/tests/test_parse_doc_task.py`）。
