### 报告结构

```python
{
    "summary": str,
    "risk_counts": {"HIGH": int, "MEDIUM": int, "LOW": int},
    "top_risks": list[dict],
    "health_score": {
        "overall": int,
        "dimensions": {
            "compliance": int,
            "performanceRisk": int,
            "clauseCompleteness": int,
        },
    },
}
```

### 扣分与维度

风险扣分：

```text
HIGH = 10
MEDIUM = 5
LOW = 2
```

矛盾扣分：

```text
HIGH = 8
MEDIUM = 4
LOW = 1
```

缺失标准对照：

```text
每条 3
```

维度映射：

```text
performanceRisk:
  UNLIMITED_LIABILITY / LIABILITY_IMBALANCE / PENALTY_TOO_HIGH
  / PAYMENT_TERM_RISK / UNILATERAL_TERMINATION
  + PAYMENT_CONTRADICTION / LIABILITY_CONTRADICTION

compliance:
  UNFAVORABLE_JURISDICTION / MISSING_DISPUTE_CLAUSE / FORCE_MAJEURE_ABSENT
  / IP_OWNERSHIP_RISK / VAGUE_CONFIDENTIALITY / OTHER
  + TERM_CONTRADICTION / OTHER
```

公式：

```text
compliance          = clamp(100 - compliance_deduction, 0, 100)
performance_risk    = clamp(100 - performance_risk_deduction, 0, 100)
clause_completeness = clamp(100 - 3 * len(missing_clauses), 0, 100)
overall             = round(
    0.4 * compliance
    + 0.4 * performance_risk
    + 0.2 * clause_completeness
)
```

### 父文档断言纠偏

`2-4 §⑦` 原示例写：

```text
risks=[HIGH, MEDIUM] + missing=1 -> compliance=95, performance=100, overall=97
```

该示例与 `2-4 §5.5` 的扣分公式不一致：只要存在 HIGH 风险，不可能同时得到对应维度 100 分。
本卡以公式为唯一口径，测试采用可核算示例：

```text
performance HIGH + compliance MEDIUM + 1 missing
-> compliance 95 / performanceRisk 90 / clauseCompleteness 97
-> overall round(38 + 36 + 19.4) = 93
```

## ⑥ 实现规范

1. 所有输入读取使用 `state.get(..., [])`，不得假设 reducer 字段已存在。
2. `compute_health_score()` 和 `build_report_draft()` 不得读取 state、环境变量或 deps。
3. 风险类别映射必须完整覆盖 `RiskCategory` 的 11 个值。
4. 矛盾类别映射必须完整覆盖 `ConflictType` 的 4 个值。
5. 未知类别按 compliance 处理并记 warning；不得静默丢分。
6. `clamp` 使用 `max(0, min(100, value))`。
7. `top_risks` 排序规则：HIGH > MEDIUM > LOW，再按 `id` 字典序，最多 5 条。
8. `top_risks` 使用 `model_dump(mode="json", by_alias=True)` 转纯 dict。
9. `risk_counts` 固定包含 HIGH / MEDIUM / LOW 三个键，零也必须出现。
10. 摘要固定格式：`共识别 {risk_count} 条风险、{conflict_count} 条矛盾、{missing_count} 条缺失标准对照。`
11. 报告节点永远 `OK`；无输入也输出 100 分和空列表。
12. `report_draft_node` 的 `llm_calls` / `rag_calls` 增量均不出现，默认视为 0。
