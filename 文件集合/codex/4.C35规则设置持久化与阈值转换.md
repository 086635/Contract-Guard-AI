## ② 范围

### ✅ 做

- 规则列表、规则详情、规则更新继续经真实 `settingsApi` 访问后端。

## ⑤ 接口规格

```ts
export const settingsApi = {
  list(contractType?: ContractType): Promise<SystemAuditConfiguration[]>;
  get(configId: string): Promise<SystemAuditConfiguration>;
  update(
    configId: string,
    body: SystemAuditConfiguration
  ): Promise<SystemAuditConfiguration>;
};
```

阈值约定：

```text
UI 0..100  <->  API 0.00..1.00
enabled    <->  SystemAuditConfiguration.enabled
version    ->   乐观锁原样透传
```

## ⑥ 实现规范

1. 页面加载时使用服务端 `enabled` 与 `reviewThresholds` 初始化控件，禁止用硬编码 `true/85/65/40` 覆盖。
2. 拖动阈值只更新编辑态；保存时统一转换并发送完整 DTO。
3. `update` 成功后用响应 DTO 更新当前规则和规则列表；失败保留编辑态并显示错误。
4. 版本冲突按后端错误展示，不自动重试覆盖；用户可重新加载后再保存。
5. 切换规则时丢弃未保存的旧规则编辑态或明确提示，禁止把旧阈值写入新规则。
6. 不负责 `enabledRules`、Prompt 等未由 T-D6 持久化字段的额外改造。

## ⑦ 验收标准

| # | 断言 |
|---|---|
| 1 | 两条规则切换后各自显示服务端 `enabled` 与阈值 |
| 2 | 修改 `enabled` 保存，刷新后保持 |
| 3 | 修改三类阈值保存，刷新后保持，后端值在 0~1 |
| 4 | UI 输入 0/100 边界转换正确，无浮点显示错误 |
| 5 | 保存失败或 409 显示错误且不伪造成功 |
| 6 | 切换规则不会把上一规则编辑态写入当前规则 |
