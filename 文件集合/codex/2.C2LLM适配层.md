## ⑥ 实现规范（**前三条来自本机实测，违反必崩**）

1. 🔴 **结构化输出必须 `method="function_calling"`**：DeepSeek 不支持 `response_format={"type":"json_schema"}`
   （实测 HTTP 400 `This response_format type is unavailable now`）→ 默认 `json_mode="json_mode"`（**不是 `json_schema`**）。
2. 🔴 **三级降级链**：`with_structured_output(schema, method="function_calling")` → 失败则 `response_format={"type":"json_object"}` + 手工校验 → 再失败则纯提示词 + 后置 JSON 解析；**三级都要记 warning 并带 `stage`**。
3. 🔴 **`max_tokens` 下限守卫**：`deepseek-flash` 是 reasoning 模型（`reasoning_tokens` 先吃额度，实测 16 → `content` 空串）→
   默认 ≥ 2048；若「`content` 为空且 reasoning 触顶」→ 判**截断**，记 warning 并允许**一次**放大重试。
4. 🔴 **默认必须离线**：`provider="offline"` 是代码默认；缺 Key / 缺 base_url 时抛 `LlmConfigError`（**不得**静默联网）。
5. 🔴 **模型实例缓存**：`get_chat_model()` 进程内缓存（构造开销大）；`clear_llm_cache()` 供测试隔离。
6. ⚠️ **provider 预设**：`deepseek` → `https://api.deepseek.com/v1`；`ollama` → `http://localhost:11434/v1`（api_key 任意）；三者共用同一 OpenAI 兼容适配器。
7. ⚠️ **打点**：`log_event("llm.invoke.start"/"llm.invoke.done"/"llm.invoke.degrade", provider=…, model=…, tokens=…, latency_ms=…)`；**禁止**把 prompt 全文写日志（隐私）。

## ⑨ 避坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | 用 `json_schema` 输出 | DeepSeek 直接 400（实测）；必须 function calling |
| 2 | `max_tokens` 给小 | reasoning 模型会吃掉额度 → content 空串，看起来像"模型不听话" |
| 3 | 在节点里直接 `ChatOpenAI(...)` | 破坏"唯一构造入口"，缓存/降级/打点全绕过了 |
| 4 | 缺 Key 时静默降级为联网 | 演示现场会不可控；必须抛 `LlmConfigError` |
| 5 | 把 prompt 全文写日志 | 含合同原文，隐私 + 日志爆炸 |
| 6 | 默认 provider 设成 deepseek | 会让离线基线依赖网络；默认必须 `offline` |
