## 2. 接入架构（谁接谁、数据流）

```text
api-gateway ──> celery worker.run_audit（T-B8）──> audit_graph 节点（T-B3）
                                                        │
                                              ┌─────────┴─────────┐
                                              │  risk / standard_compare / conflict
                                              │  调 RagTool（T-B4）
                                              └─────────┬─────────┘
                                                        ▼
                        RagTool ──包装──> RAGService.retrieve ──> vector_store / sparse / rerank
                                                        │
                                          AgentRAGToolResult ──> Prompt 注入 + citations
```

依赖方向（红线不变）：`rag-contracts → rag-core → ai-engine → async-worker`，`api-gateway` 只依赖左侧。

## 3. 详细接入方案（三步，按依赖顺序）

### 3.1 RAG 侧暴露面（已就绪，零改动，可直接消费）

唯一入口是工厂，不要自己拼组件：

```python
from rag_core.config import RagSettings
from rag_core.factory import build_service_from_settings
from rag_contracts.query import RAGQueryRequest

service = build_service_from_settings(RagSettings())  # 默认 inmemory + hash + noop，离线可跑
resp = service.retrieve(
    RAGQueryRequest(trace_id="t1", query="试用期最长可以约定多久", top_k=5)
)
# 空召回是设计行为：resp.retrieved_docs == [] 且 resp.fallback_reason 非空 → 缺失提示
```

切真实语义只改环境变量（业务代码零改动）：`CG_RAG_VECTOR_STORE=qdrant`、`CG_RAG_EMBED_MODE=http`、`CG_RAG_EMBED_BASE_URL=ollama`、`CG_RAG_RERANK_MODE=http`、`CG_RAG_RERANK_HTTP_URL=http://127.0.0.1:8081`。

### 3.2 Agent 工具层（T-B4，落点 `packages/ai-engine/ai_engine/agents/tools.py`）

`RagTool` 是**薄桥接**，检索逻辑全在 `RAGService`：

- 入参对齐 `AgentRAGToolInput`（`query` / `contract_type` / `source_types` / `top_k` / `reason`），出参对齐 `AgentRAGToolResult`。
- `as_langchain_tool()` 的 `name` 必须等于 `rag_contracts.agent_tool.TOOL_NAME`（`retrieve_contract_knowledge`）。
- `spec` 直接复用 `build_function_calling_spec()`，**不要**另写一份工具 JSON。
- 三道防线按 `2-5 §⑤` 判定表落地：①超长 `min(max_query_chars, 2000)` 截断；②空召回 → `status="EMPTY"` + `EMPTY_CONTEXT_HINT`；③`TIMEOUT`/`STORE_UNAVAILABLE` 指数退避重试，`EMPTY_RECALL` **不重试**。

### 3.3 worker 与 API 接线（T-B8，落点 `apps/async-worker/worker/tasks/run_audit.py`）

- `run_audit_task` 组装 `GraphDeps` 时**注入 `build_rag_tool()`**，节点只拿依赖、不自己构造 RAG。
- 入参经 `worker/adapters.py::to_clause_inputs()` 适配为 `ClauseInput`（缺 `clause_id`/`label`/`bbox` 按 `2-6 §⑤` 兜底）。
- 进度经 `AuditProgressReporter` 上报（阶段百分比表唯一处在 `worker/progress.py`）。
- api-gateway 从 mock 切真实任务下发属模块 4 配套；最小可用路径是 worker 单测 + 直接调 `run_audit.delay()`。

## 4. 开发规范与边界（红线）

- 🔴 **F6 红线**：不得在 `ai_engine/rag/*` 重新实现检索/融合/重排，一律包装 `RAGService.retrieve`（`2-5 §②` 已要求删除旧空壳 `retriever.py`）。
- 🔴 **依赖方向**：`rag-core` 不得 import `ai_engine` / `worker` / `apps/*`；`service.py` 只依赖 `rag_contracts.ports`，不得 import `qdrant_client` / `pymilvus` / `httpx`。
- 🔴 **默认离线**：`vector_store=inmemory` + `embed_mode=hash` + `rerank_mode=noop` 保持可离线跑；`Milvus` 不得成为任何默认值。
- 🔴 **契约唯一处**：工具名、`EMPTY_CONTEXT_HINT`、入/出参模型唯一处在 `rag_contracts/agent_tool.py`；接入方只 import，禁止复制。
- 🔴 **超时重试边界**：`max_query_chars` / `timeout_ms` / `max_retries` 的消费方在 **Agent 工具层**（T-B4），不塞回 `rag-core`。
- 🔴 **空召回语义**：`EMPTY_RECALL` 是「缺失标准对照」信号，禁止靠放宽阈值硬消（`0-C4` 已证 4 条空召回是语料缺失真信号）。
