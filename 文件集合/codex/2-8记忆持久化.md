## ② 范围

### ✅ 做

- 定义 `MemoryStorePort`（本地 Protocol：`get` / `set` / `delete` / `keys`）
- 三个实现：`InMemoryMemoryStore`（**默认，离线可跑**）、`RedisMemoryStore`、`PostgresMemoryStore`
- 改造 `GlobalStateManager` / `ScopedMemoryManager`：接收注入的 store（默认 `InMemory`），**方法签名保持兼容**
- `build_memory_store()` / `build_checkpointer()` 工厂（读 `CG_MEMORY_*` 配置）
- 序列化：Pydantic `model_dump_json()` / `model_validate_json()` + 版本包裹 `{"v": 1, "data": ...}`
- 缺依赖降级：`redis` / `psycopg` / `langgraph-checkpoint-postgres` 未安装 → 回落 `InMemory` + `warnings`（**不崩**）

### ❌ 不做

- ❌ 不把 `MemoryStorePort` 加进 `rag_contracts.ports`（那是 RAG 的端口契约，加了就是第二处定义）
- ❌ 不改 `ScopedClauseMemory` / `GlobalContractState` 的字段
- ❌ 不用 Qdrant / Milvus 存记忆（向量库不是 KV 记忆库）
- ❌ 不实现会话鉴权 / 加密 / 多租户隔离（超出赛题范围）
- ❌ 不改 `worker/main.py` 的 Celery 配置（broker/backend 已有）

## ⑤ 接口规格

```python
# ai_engine/memory/store.py
class MemoryStorePort(Protocol):
    """记忆存储端口（字符串进出，序列化由上层负责）。"""

    def get(self, namespace: str, key: str) -> str | None: ...

    def set(self, namespace: str, key: str, value: str, ttl_s: int | None = None) -> None: ...

    def delete(self, namespace: str, key: str) -> None: ...

    def keys(self, namespace: str) -> list[str]: ...


class InMemoryMemoryStore:
    """进程内实现（**默认**）。

    ⚠️ 多进程 Celery 下**不可用**（各进程各一份），仅用于单测与单进程开发。
    """

    def __init__(self, *, clock: Callable[[], float] = time.monotonic) -> None: ...
```

**key 命名规则（唯一处）**：

```text
全局状态   {key_prefix}:global:{contract_id}
条款记忆   {key_prefix}:scoped:{contract_id}:{clause_id}
```

> 🔴 条款记忆的 key 含 `clause_id`，与 `2-7` 的 `thread_id = f"{contract_id}:{clause_id}"` **同构** ——
> 这样"图状态"与"业务记忆"落在同一逻辑分片上，排查问题时可直接对齐。

**值格式（唯一处）**：

```json
{"v": 1, "data": {/* ScopedClauseMemory 或 GlobalContractState 的 model_dump(mode="json") */}}
```

## ⑥ 实现规范

1. 🔴 **默认必须离线**：`backend` 默认 `"inmemory"`；`build_memory_store()` 在无任何外部服务时也能返回可用实现（标准 §0.4）。
2. 🔴 **checkpointer ≠ memory store**：
   - checkpointer 存**图状态**（`AuditState` 快照，供断点续跑/多轮）
   - memory store 存**业务记忆**（合同全局态 + 条款对话窗口）
   **两者不得互相替代**，也不要把 `AuditState` 塞进 memory store。
3. 🔴 **延迟导入重依赖**：`redis_store.py` / `postgres_store.py` 里的 `import redis` / `import psycopg` 必须**写在函数内部或 `try` 块内**，否则缺包会导致 `ai_engine.memory` 整包 import 失败（当前环境 `redis` 随 `celery[redis]` 而来，`psycopg` **未装**）。
4. 🔴 **TTL 只对 Redis / Postgres 生效**；`InMemoryMemoryStore` 用注入的 `clock()` 判断过期（**不可用 `time.time()` 硬编码**，否则测试无法确定性验证）。
5. 🔴 **序列化统一 `model_dump_json()` / `model_validate_json()`**，并包 `{"v": 1, ...}` 版本壳；读到未知版本 → 记 warning 并**当作 miss**（不抛异常）。
6. 🔴 **写入前必须过 Pydantic**：不得把裸 dict 直接存（防止字段漂移后读取端崩溃）。
7. 🔴 **降级必记日志**：`log_event(_LOG, "memory.degrade", level="WARNING", reason=..., backend=...)`，命名空间 `get_logger("ai_engine.memory.factory")`。
8. ⚠️ `ScopedMemoryManager` 的窗口上限仍由 `_MAX_TURNS=5` 控制；持久化只**延长生命周期**，不放大窗口。
9. ⚠️ 键前缀统一走 `key_prefix` 配置；**禁止**在业务代码里散写 `"cg:mem:"` 字面量。
10. ⚠️ 不存敏感信息（API Key / 身份证号）；记忆体只放合同 ID、条款文本与对话窗口。

**断言 2 · 跨实例可见性（同 store 共享）**

```powershell
D:\aanacoda1\python.exe -c "from ai_engine.memory import build_memory_store; from ai_engine.memory import ScopedMemoryManager; s=build_memory_store(); a=ScopedMemoryManager(store=s); b=ScopedMemoryManager(store=s); a.record_turn('c1','USER','你好', created_at='2026-09-21T00:00:00+00:00'); assert b.snapshot('c1').recentDialog, 'not shared'; print('shared ok')"
```

**断言 3 · 序列化往返（含 `draftAfter`）**

写入 `ScopedClauseMemory(targetClauseId="c1", recentDialog=[...], draftAfter="草稿")` → 读回字段**逐字段相等**。

**断言 4 · TTL 过期（注入假时钟）**

```powershell
D:\aanacoda1\python.exe -c "from ai_engine.memory.store import InMemoryMemoryStore; t=[0.0]; s=InMemoryMemoryStore(clock=lambda: t[0]); s.set('ns','k','v', ttl_s=10); t[0]=11.0; assert s.get('ns','k') is None; print('ttl ok')"
```

**断言 5 · Redis 未配置时降级不崩**

`MemorySettings(backend="redis", redis_url="redis://127.0.0.1:1")` → `build_memory_store()` 返回可用实现且**不抛异常**（连不上或未装包都走降级）。

**断言 6 · checkpointer 默认与降级**

`build_checkpointer()` 返回 `InMemorySaver` 实例；`backend="postgres"` 且包未装 → 仍返回 `InMemorySaver`（+ warning）。

**断言 7 · key 命名**

`keys("global")` 返回 `["cg:mem:global:C1"]` 形式（前缀可配）。

**断言 8 · 版本壳兼容**

写入 `{"v": 999, "data": {...}}` → 读取返回 `None`（当作 miss）且不抛异常。

**断言 9 · 测试基线**：`D:\aanacoda1\python.exe -m pytest -q` → **≥ 140 passed**。

## ⑨ 避坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | 把 `MemoryStorePort` 放进 `rag_contracts.ports` | 那是 RAG 端口层（5 个端口已冻结）；通用 KV 端口不属检索域 |
| 2 | 用 `InMemoryMemoryStore` 上生产 | Celery 多进程各自持有内存 → **记忆丢失且无报错**；生产必须 `redis` / `postgres` |
| 3 | checkpointer 与 memory store 混用 | 一个存图状态、一个存业务记忆；混用会导致 `AuditState` 反序列化失败 |
| 4 | 顶层 `import redis` | `psycopg` / `langgraph-checkpoint-postgres` 未装时会让整包 import 崩 |
| 5 | 用 `time.time()` 做 TTL 判断 | 测试不可确定性；必须注入 `clock` |
| 6 | 直接存裸 dict | 字段漂移后读取端崩溃；必须过 Pydantic |
| 7 | 读到未知 `v` 直接抛异常 | 版本升级期会让老数据把服务打挂；当作 miss 更安全 |
| 8 | 在 key 里拼裸字符串 `"cg:mem:"` | 前缀必须走配置，避免多环境串键 |
| 9 | 把敏感字段写进记忆体 | 记忆体可能落 Redis/Postgres，属持久化面 |
| 10 | 认为"P1 可以不做" | 单机演示能过，但**多进程下改写多轮记忆会静默失效**，属演示事故高发点 |
