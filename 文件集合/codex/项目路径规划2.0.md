## 2. 契约对齐（参考稿纠偏）

> 任何表字段与枚举**只从冻结契约 derive**，不得另造第二套定义。

| 参考稿写法 | 真实契约（以此为准） |
|---|---|
| 合同状态 `UPLOADED/PARSING/AUDITING/COMPLETED/FAILED` | `ContractStatus`：`UPLOADING / PARSING / PENDING_REVIEW / IN_REVIEW / FINALIZED`（**无 FAILED**，失败只体现在任务级） |
| 任务状态 `PENDING/RUNNING/SUCCESS/FAILURE` | `TaskProgress.status`：`RUNNING / DONE / FAILED`；`percent` 为 **0..1** |
| 风险等级含 `INFO` | `RiskLevel`：`HIGH / MEDIUM / LOW` |
| 反馈枚举 `ACCEPT/REJECT/MODIFY` | `FeedbackVerdict`：`CORRECT / FALSE_POSITIVE / MISSING` |
| `/agent/audit`、`/report/{id}/download` | **不存在**。真实端点 18 个（见 §6）；报告下载走 `ReportData.downloadUrl`（MinIO 预签名） |
| `contract_elements` 自定义字段 | 列 = `ContractChunk` **28 字段**的持久化投影 + `contract_id` + `vector_id`（=`chunk_id`，uuid5 确定性） |
| `audit_risks` 自定义字段 | 列 = openapi `EnhancedRiskItem` / `CrossClauseConflict` 的持久化投影 |
| `user_feedbacks` 只有 `risk_id` | openapi `Feedback.targetType ∈ {RISK, CONFLICT, SEAL, ELEMENT}` → 表用 `target_type + target_id` 多态关联 |
| DB 驱动用 `psycopg` | 统一 **`asyncpg`**（`.venv` 已装，且是 `CG_POSTGRES_DSN` 默认值） |
| 报告 PDF/DOCX | **先只出 DOCX**（python-docx，Windows 零外部依赖；PDF 后续可加） |

## 3. 目标状态与总体策略

**目标**：compose 全栈可一键起、18 端点全部真实化、一次「上传→解析→审核→报告」端到端可演示、前端可渲染。

**分层解耦（契约优先）**：

```text
Frontend ──HTTP/SSE──> API Gateway ──> Service 层 ──> DAL ──> PostgreSQL
                                     └──> Celery/Redis ──> Worker ──> RAG/Agent/OCR
Worker ──> MinIO（文件/工件）＋ Qdrant/Milvus（向量）
```

**三存储分工（不变）**：PostgreSQL=状态机/结构化结果/配置/反馈；Qdrant/Milvus=切片向量+检索 payload；MinIO=原始文件/解析工件/报告 DOCX。

## 6. 数据流转穿透（真实 18 端点）

**端点分组（SSOT = `openapi.yaml`）**：

| 组 | 端点 | 真实化依赖 |
|---|---|---|
| Contracts | `GET /contracts`、`GET /contracts/{contractId}`、`GET .../elements`、`GET .../risks`、`GET .../conflicts`、`GET .../seals`、`GET .../parse-status` | DAL 读 PostgreSQL / 工件 |
| Contracts | `POST /contracts/presign`、`POST /contracts/upload`、`POST /contracts/{contractId}/commit` | MinIO 预签名 + 建行 + 派发 Celery |
| Agent | `POST /agent/rewrite` | 派发 `rewrite_graph` |
| Settings | `GET/PUT /settings/rules`、`GET/PUT /settings/rules/{configId}` | DAL CRUD |
| Feedback | `POST /feedback` | DAL 写 `user_feedbacks` |
| Tasks | `GET /tasks/{taskId}`、`GET /tasks/{taskId}/stream` | Celery 状态 + Redis Pub/Sub SSE |
| Report | `POST /report/{contractId}/generate`、`GET /report/{contractId}` | `gen_report` + MinIO + 预签名 |

**全链路**：

```text
1 上传：presign → MinIO 直传 → commit 建 contracts 行 → 派发 parse_doc
2 解析：worker 读 MinIO → OCR/Layout → 切片 + 向量入 Qdrant → 写 contract_elements → 任务 DONE
3 审核：派发 run_audit → audit_graph（classify/extract/risk/conflict/compare/report）→ 写 audit_risks/conflicts → SSE 实时推
4 报告：派发 gen_report → 生成 DOCX → 传 MinIO → 写 audit_reports → 返回 downloadUrl
5 渲染：前端 GET /risks /conflicts /seals /report 渲染
```

**状态机**：`UPLOADING → PARSING → PENDING_REVIEW → IN_REVIEW → FINALIZED`；失败只体现在 `audit_tasks.status=FAILED`（`ContractStatus` 无 FAILED）。
