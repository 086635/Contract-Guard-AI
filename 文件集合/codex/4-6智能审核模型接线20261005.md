## ② 范围

1. 已下载官方 Ollama 和 Qwen3 4B 并真实复审。按用户最新选择切换原工厂支持的 DeepSeek，停止本任务启动的本地 LLM 释放显存；保留下载缓存供回滚。OCR、embedding 和印章极坐标展开（cv2.warpPolar）保持原本地路径，当前 embedding 实测默认 hash，不能声称已接通真实 BGE 语义模型。
2. 原运行脚本设定 provider/model/base_url/timeout 等既有配置；保留仓库默认值、认证、数据库、队列、RAG、OCR 与前端框架。
3. 修复实际 SDK 把 max_tokens 改名后 Ollama 不限输出的兼容缺陷；DeepSeek 官方也定义 max_tokens，故为两者透传原名，并在结构化截断重试时同步扩容。DeepSeek JSON 模式关闭默认 thinking，减少空 content 与等待；OpenAI 配置维持原行为。不伪造风险、健康分或审核成功。
4. 前端依据真实审核终态和警告展示健康分、模型运行方式、失败/降级原因；必要改动限定现有状态投影与审核页。
   审核运行期间只轮询状态；终态刷新详情，避免完整工作台反复闪动、重复装载 PDF 和打断定位。
5. 优先重审用户当前合同，保留原上传文件与解析数据；真实结果与日志作为交付证据。
6. 真实联调发现 EMPTY 召回被判为合同缺失（首轮 44 条款产生 44 条缺失）。修正标准比对：没有标准依据只标记降级，不能据此推断合同缺失；评分公式与六节点框架不改。原 C7 的对应断言改为更严格的“不得生成无依据缺失项”，不是降低测试门槛。
7. 接线后发现网关投影器另写了 15/8/3 扣分并反转履约维度，与原图节点 40%/40%/20% 算法不一致。网关改为调用原唯一评分函数；原查询测试改为明确断言总分 94、合规 100、履约 86、完整性 100，补强跨页面一致性，不改原算法。报告生成在真实终态时传入本次审核完整健康分，运行/失败时不补造分数。
8. 实测合同详情 GET 先读旧风险，风险子接口才入库新审核，导致首屏与后续页面数据不同。详情读取先沿用现有 finalize_audit 收敛当前终态，再读最新分类和风险；不改 DAL、数据模型与原上传文件。
9. DeepSeek 有时返回符合原 Schema 的完整 JSON 而没有 tool_calls，旧工具解析器把它判为空、发起第二次请求。原工具调用路径在无解析错误、无工具返回、且原始正文通过同一 Schema 校验时直接接受 JSON；不放宽字段校验，错误 JSON 继续原降级链。
10. 真实复审仍有 9 次工具响应为空，经原 JSON 备用路径恢复，分类/要素/风险/矛盾阶段全部 OK。原页面把第一个已恢复的底层错误当作审核结论，遮住了实际的标准依据不足。状态摘要仅在四个模型阶段全部 OK 且终态可用时优先展示业务限制；原任务保留所有诊断，真正失败不隐藏错误。
