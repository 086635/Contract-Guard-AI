### 三道防线

| 防线 | 触发 | 结果 |
|---|---|---|
| 超长拦截 | `len(query) > min(max_query_chars, 2000)` | 头尾截断 + warning + 正常检索 |
| 空召回 | `not retrieved_docs` 或 service 已判 EMPTY | `EMPTY` + `EMPTY_CONTEXT_HINT` + 空 citations |
| 部分降级 | `degraded=True` 且有 docs | `DEGRADED` + 原 context + warnings |
| 超时重试 | 异常或 `TIMEOUT / STORE_UNAVAILABLE` | 指数退避，最多 `max_retries` 次重试 |
| 不重试 | `EMPTY_RECALL` | 立即返回 EMPTY |

退避固定：

```text
base = 0.2s
factor = 2
cap = 2.0s
```

## ⑥ 实现规范

1. 工具只调用 `RAGService.retrieve()`，不得接触向量库 SDK。
2. `context_block` 只允许来自 `RAGQueryResponse.context_block` 或 `EMPTY_CONTEXT_HINT`。
3. `citations` 直接取 `[doc.citation for doc in response.retrieved_docs]`。
4. `token_usage` 透传；重试时累计 token。
5. `took_ms` 使用工具自身墙钟耗时。
6. 配置项必须全部消费：截断阈值、timeout、max retries、score threshold、max context tokens、rerank top n。
7. `top_k` 夹取到 `[1, 20]`，越界记 warning。
8. `reason` 只进日志，不进入检索请求参数。
9. 每次失败、重试、降级都带 `trace_id`。
10. 测试通过注入 `sleeper` 完成，不真实等待。

### 实测后回填

| 项 | 实测值 |
|---|---|
| 截断阈值实际生效值 | ✅ `RagSettings.max_query_chars=2000`，与冻结契约上限取 `min` 后仍为 **2000**；5000 字输入截为 2000 字，omitted=3018 |
| 单次检索平均耗时 / P95 | ✅ 默认 `inmemory + hash + noop`、20 次空召回实测：平均 **1.25 ms**、中位 1 ms、P95 **14 ms**、min 0 / max 14 ms |
| 重试触发次数 | ✅ 离线桩：异常重试后成功 2 次等待；TIMEOUT fallback 重试 1 次后成功；EMPTY_RECALL 重试 0 次；异常耗尽共调用 3 次后返回 EMPTY |
| Tool 上下文 Token 比例 | ⏳ 当前 C6 Prompt 尚未接入，暂无可比基线；Tool 已透传 `token_usage`，待 C6 联调后按 Tool context tokens / Prompt tokens 统计 |
