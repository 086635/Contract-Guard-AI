## ⑥ 任务 T-A0-2 · `SparseHit.payload` 契约补丁（**本文件核心**）

### 背景（为什么要做）

`RAGService._fuse()` 的既有注释与警告已自述该缺陷：

> `chunk_id` 无法取回完整 `ContractChunk`（`SparseHit` 只有 `text`），只能丢弃
> —— 并追加 warning：`"N 条仅 BM25 命中的候选无法取回完整切片，已丢弃"`

**后果**：BM25 在合同场景最不可替代的能力是**精确编号/专名检索**（如「第五百八十五条」「6.2.1」），
而这恰恰是稠密向量最容易漏的。丢弃稀疏独占候选 = **混合检索退化为「稠密为主」**，
`HYBRID_RRF` 策略名不副实。

### 接口规格

**改动 1：`rag_contracts/ports.py`**

```python
class SparseHit(BaseModel):
    """BM25 返回的单条命中。"""

    model_config = ConfigDict(extra="forbid")

    chunk_id: str = Field(description="切片 ID")
    score: float = Field(description="BM25 原始分（未归一，越大越相似）")
    text: str = Field(default="", description="命中文本（调试用）")
    payload: dict[str, Any] = Field(
        default_factory=dict,
        description="完整 ContractChunk payload，供稀疏路独占候选还原切片",
    )
```

> ⚠️ **必须给默认值 `default_factory=dict`**：否则旧 pickle 反序列化会因缺字段而校验失败。

**改动 2：`rag_core/adapters/bm25_store.py`**

| 成员 | 改动 |
|---|---|
| `__init__` | 新增内部状态 `self._payloads: dict[str, dict[str, Any]] = {}` |
| `upsert(chunks)` | 除 `_texts` / `_doc_len` / `_doc_source` 外，**同时写 `self._payloads[chunk.chunk_id] = chunk.to_payload()`** |
| `_load()` | 反序列化元组**追加一项** `self._payloads`；⚠️ **必须兼容旧格式**（见下） |
| `save()` | 序列化元组**追加一项** `self._payloads`，**顺序与 `_load()` 严格一致** |
| `search()` | 构造 `SparseHit` 时带 `payload=self._payloads.get(chunk_id, {})` |
| `delete_by_doc()` | 按 `_doc_source` 删除时**同时删 `_payloads`**（避免内存泄漏） |

### 实现规范（**关键：pickle 向后兼容**）

`_load()` 现在解包 6 元组；改成 7 元组后，**磁盘上已有的旧 `index.pkl` 会导致解包失败**。
源码原本已用 `try/except` 兜底「索引损坏则重建」，但**重建会静默丢掉整个索引**。
**必须显式兼容两种长度**：

```python
def _load(self) -> None:
    """启动时加载索引。文件不存在或损坏时静默降级为空索引。"""
    if not self._path.exists():
        return
    try:
        blob = pickle.loads(self._path.read_bytes())
        if len(blob) == 7:
            (self._tf, self._texts, self._doc_len, self._doc_source,
             self._df, self._avgdl, self._payloads) = blob
        else:
            # 兼容旧版 6 元组：payload 缺失，置空（首次 save() 后自动升级为 7 元组）
            (self._tf, self._texts, self._doc_len, self._doc_source,
             self._df, self._avgdl) = blob
            self._payloads = {}
    except Exception:  # noqa: BLE001 - 索引损坏时重建优于崩溃
        self._tf, self._texts = {}, {}
        self._doc_len, self._doc_source = {}, {}
        self._df, self._avgdl = defaultdict(int), 0.0
        self._payloads = {}
    else:
        self._df = defaultdict(int, self._df)
```

**改动 3：`rag_core/service.py` 的 `_fuse()`**

现在行为是「稀疏独占候选 → 丢弃 + 计数 + warning」。改为「**用 payload 还原 `ContractChunk`**」：

```python
# 稀疏路独占候选：用 payload 还原完整切片（payload 为空时仍丢弃并告警）
for chunk_id, score in sparse_ranked:
    if chunk_id in dense_ids:
        continue
    payload = hit_payloads.get(chunk_id) or {}
    if not payload:
        sparse_only += 1          # payload 缺失（旧索引）→ 保守丢弃
        continue
    try:
        chunk = ContractChunk.from_payload(payload)
    except ValidationError:
        sparse_only += 1
        warnings.append(f"稀疏候选 {chunk_id} 的 payload 无法还原切片，已丢弃")
        continue
    candidates.append((chunk, 0.0, score))   # 稠密分填 0.0（该路未命中），融合分取 BM25 分
```

### 避坑清单

| 坑 | 正确做法 |
|---|---|
| 给 `SparseHit.payload` 不设默认值 | **必须** `default_factory=dict`，否则旧 pickle 反序列化失败 |
| 改 7 元组后不兼容旧索引 | `_load()` 里**显式判断 `len(blob)`**，不要依赖 `try/except` 重建 |
| `save()` 与 `_load()` 元组顺序不一致 | 源码已有警示「顺序错位会导致 TF/DF 静默错乱」，**加字段时两处必须同步改** |
| 稀疏独占候选的稠密分填 `None` | `_Candidate` 三元组的稠密分是 `float`，填 **`0.0`**（表示该路未命中） |
| 忘了 `delete_by_doc` 清理 `_payloads` | 会造成内存泄漏（已删除切片的 payload 常驻） |
| 顺带把 `SparseHit` 加进导出 JSON Schema | **不要**。它「不在 4 份 Schema 之列」正是本改动不触发红线的前提 |
