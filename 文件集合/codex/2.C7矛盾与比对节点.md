### 候选对算法

1. 遍历所有 `(i, j)`，`i < j`。
2. 两条款至少命中同一关键词组才保留。
3. 用 clause_id 对去重，同一对只保留一次。
4. 按 `(abs(i - j), i, j)` 升序排序，优先比较距离近的条款。
5. 截断到 `max_pairs`。

`max_pairs <= 0` 时返回空列表，并记录 warning。

### 冲突批处理

- `batch_size = max(1, deps.conflict_batch_size)`。
- 每批一次 `invoke_structured()`，schema 为 `_ConflictBatch`。
- Prompt 的 `pair_block` 中每对写 `pair_index`，模型只回传索引。
- 代码回填：

```text
id = f"{contract_id}:conflict:{ordinal}"
sourceClauseId = candidates[pair_index][0]["clause_id"]
targetClauseId = candidates[pair_index][1]["clause_id"]
citations = []
```

### 缺失条款结构

`standard_compare_node` 只把 `AgentRAGToolResult.status == "EMPTY"` 映射为缺失：

```python
{
    "id": f"{contract_id}:missing:{ordinal}",
    "standardClauseId": "",
    "title": clause["label"] or clause["clause_id"],
    "reason": rag_result.context_block or EMPTY_CONTEXT_HINT,
    "suggestion": f"补充与“{clause['label']}”对应的标准条款",
    "canAutoFill": False,
}
```

## ⑥ 实现规范

1. 无 clauses 时两个节点均 `SKIPPED`，不调用 LLM / RAG。
2. `conflict` 候选为 0 时返回 `conflicts=[]`、`OK`、detail `无可疑条款对`，`llm_calls=0`。
3. `conflict` 缺模板时 `SKIPPED`，不得退化为规则直接判定矛盾。
4. LLM 调用次数必须等于处理的 batch 数；不得按候选对数逐对调用。
5. 单批 LLM 失败时跳过该批并 warning，其它批继续；stage 最终 `DEGRADED`。
6. `pair_index` 越界或重复时丢弃该项并 warning。
7. `standard_compare` 无条款时 `SKIPPED`。
8. `standard_compare` 的 `rag_tool=None` 时返回 `missing_clauses=[]`、`DEGRADED`，warning 明确“无法判定缺失”。
9. 每个 clause 的一次 RAG 尝试都计入 `rag_calls`，包括异常尝试。
10. RAG 返回 `OK` / `DEGRADED` 且有 citations：视为已有标准对照，不生成 missing。
11. RAG 返回 `EMPTY`：生成 missing，这是设计内信号，不是失败。
12. RAG 抛异常：只 warning，不生成 missing，避免把服务故障伪装成语料缺失。
13. 两个阶段的 `stage_log.stage` 分别精确为 `conflict` / `standard_compare`。
