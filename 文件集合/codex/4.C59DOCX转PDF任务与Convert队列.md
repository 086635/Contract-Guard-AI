## ⑤ 接口规格

```text
convert_doc(contract_id,source_key)->{contractId,status,storagePath,converterVersion,warnings}
CELERY_QUEUES=convert
```

## ⑥ 实现规范

1. 每次转换使用独立临时目录。
2. 超时/非 0 退出转 FAILED。
3. 输出 key 使用服务端生成路径。
4. 转换版本写入预览表。

### 实测后回填·断言逐条

| # | 断言 | 实测结果 |
|---|---|---|
| 1 | DOCX 成功生成 PDF | 通过：`test_convert_doc_success`（产物上传到 `contract_previews/{contractId}/{uuid}-*.pdf`，`converterVersion` 随结果回传） |
| 2 | 损坏 DOCX FAILED | 通过：`test_convert_doc_failure`（非 0 退出 → `FAILED/CONVERT_EXIT_CODE:1`）、`test_convert_doc_missing_output_is_failure`（退出 0 但无产物 → `CONVERT_NO_OUTPUT`） |
| 3 | 转换超时 FAILED | 通过：`test_convert_timeout`（`TimeoutExpired` → `FAILED/CONVERT_TIMEOUT`）、`test_convert_timeout_is_read_from_env`（`CG_CONVERT_TIMEOUT_S` 原样传给子进程） |
| 4 | 原文仍存在 | 通过：`test_convert_preserves_source`（本地源字节不变、无 `remove_object`）、`test_convert_never_deletes_or_overwrites_source_object`（只 `fget` 原 key，写入的新 key ≠ 原 key） |
| 5 | 重试不覆盖其他合同 | 通过：`test_retry_does_not_overwrite_other_contract`（同合同两次转换 key 不同；跨合同命名空间不同） |

> §⑧ 四个用例名全部落盘：`test_convert_doc_success`、`test_convert_doc_failure`、`test_convert_timeout`、`test_convert_preserves_source`。
