```powershell

$env:CG_RAG_RERANK_MODE="http"; $env:CG_RAG_RERANK_HTTP_URL="http://127.0.0.1:8081"
$env:CG_RAG_SCORE_THRESHOLD="0.30"   # 扫参变量
$env:CG_RAG_RERANK_THRESHOLD="0.35"  # 扫参变量
python scripts/eval_recall.py --out scripts/data/sweep_0.30_0.35.json
```

### ⑩.2 三条结论

1. **默认配置已在平台期**：5 个阈值项**没有一个**能换来可测的召回提升 →
   建议**全部维持默认**（`1-6 §⑧` 已按此回填）。调参预算应转向 ⑩.3 的耗时瓶颈。
2. **`rerank_threshold` 是"条件生效"的**：生效口径 `max(score_threshold, rerank_threshold)`
   （`rag_core/service.py:575`）—— 低于 `score_threshold` 时**恒不生效**（第 4 点实测与 ref 逐字相同即证）。
   调它之前先看 `score_threshold`。
3. **`dense_top` / `sparse_top` 翻倍 = 纯亏**：`20→30` 融合候选由 **29.2**（28–33）涨到 **42.2**（39–46）、
   精排对数 **+44%**，而指标**逐字不变**。

### ⑩.3 🔴 演示期精排耗时红线（**本卡最重要的运维发现**）

| 指标 | 实测 |
|---|---|
| `retrieve.rerank` 单次（`pairs` 28–33，n=12） | 中位 **3319.5 ms** · P95 **3698 ms** · min 2310 / max 3995 |
| 整次 `retrieve`（`took_ms`） | 中位 **3539 ms** |
| 本节原标称"热态 top-20 ≈ 1.06 s" | 本机实测**慢 3 倍以上**（机器常年跑 WPS/微信/钉钉/Excel），**不是回归** |

🔴 **默认 `CG_RAG_RERANK_TIMEOUT_MS=3000` 在本机不够**（中位 3.32 s 已超 3 s）。
实测按默认 `3000` 跑完整评测时，**大量查询的精排被判失败并静默降级**
（`stage=retrieve.degrade, fallback_reason=RERANK_FAILED`），`final` 退回 clamp 后的余弦分 ——
该降级态下 Recall@5 反而"升到 1.000"（**换了打分口径**），**不可误读为调参收益**。
→ 演示前**必须显式调大**（本轮统一 `60000`）；且耗时 **> 3 s**，演示须标注 **"CPU 推理"**。
