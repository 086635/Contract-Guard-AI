## ② 范围

### ✅ 做

- **基线冻结**：以 `apps/web-ui` 当前实际代码为唯一前端基线；`apps/web-ui__demo` 只做历史对照，不参与合并、构建或验收。
- **类型同步**：先执行一次 `pnpm --filter @contract-guard/schema gen` 落盘，再检查 `types.ts` / `zod.ts` / `schemas.py` 是否稳定；禁止手改生成物。
- **API 与 SSE 适配**：统一错误体兼容 `{message, detail, traceId}`；SSE 监听命名事件 `progress`；终态关闭连接；断线按 2 秒周期轮询并在 `DONE/FAILED` 停止。
- **上传闭环**：真实执行 `presign → MinIO PUT → upload → SSE → DONE`；不跳过 `.local`、不伪造上传成功、不隐藏 MinIO/CORS/权限错误。
- **审核工作台适配**：使用合同列表选中的 `contractId` 读取真实详情、要素、风险、矛盾、印章和解析状态；生成报告后先等待任务 `DONE`，再进入报告页。
- **报告页适配**：区分“生成中”“尚未生成”“生成失败”“可下载”“重新生成”状态；只有真实 `ReportData.downloadUrl` 可下载，不以浏览器打印冒充 DOCX 成功。
- **反馈与设置适配**：反馈页读取真实列表、统计从列表派生、CSV 前端导出；设置页持久化 `enabled` 与 `reviewThresholds`，页面 0~100 与后端 0~1 正确转换。
- **路由与导航**：移除导航中的示例合同 UUID 硬编码；无选中合同时回到合同中心或显示空态引导。
- **部署与交付**：Vite `/api` 代理统一指向 `http://localhost:8000`；Docker Web 容器具备 SPA history fallback；README 与最终交付报告按真实命令、真实端点和实测结果更新。

- ❌ 不修改 `openapi.yaml`，不新增/删除/改名公共 DTO 字段；T-D5 只消费 T-D6 已落盘后的生成类型。

## ⑤ 接口规格

T-D5 **不新增公共 API**。以下均为前端消费约定，字段与响应形状以 `openapi.yaml` 和 T-D6 产物为唯一来源：

| 前端接口 | 消费端点/事件 | 必做行为 |
|---|---|---|
| `feedbackApi.list` | `GET /feedback` | 支持合同/目标类型/判定/分页参数；返回列表用于统计与导出 |
| `settingsApi.update` | `PUT /settings/rules/{configId}` | 发送 `enabled` 与 `reviewThresholds`；阈值按后端 0~1 保存 |
| `taskApi.subscribe` | `GET /tasks/{taskId}/stream` | 监听命名事件 `progress`，不依赖 `onmessage`；终态关闭 |
| `reportApi.generate` | `POST /report/{contractId}/generate` | 返回 `TaskProgress`；等待任务终态后再加载报告 |
| `reportApi.get` | `GET /report/{contractId}` | 未生成与失败必须可区分，不把 404/失败伪装成空报告 |
| `agentApi.rewrite` | `POST /agent/rewrite` | 失败显示真实原因；成功仅展示真实 `RewriteData` |

**不变约束**：

- `TaskProgress` 字段名、`RUNNING/DONE/FAILED` 枚举和 `percent` 的 0~1 口径不变。
- SSE 后端事件固定为 `event: progress`；前端不得新增第二套事件名。
- 所有 HTTP 请求必须经 `src/api/client.ts`；不得在页面新增 `fetch` 或独立 Axios 实例。
- 反馈统计、设置阈值和合同导航不得再使用硬编码示例数据。

## ⑥ 实现规范

1. **先同步再适配**：先运行一次 `pnpm --filter @contract-guard/schema gen`，确认生成物变更后再改前端；T-D6 未落盘的接口不得由前端自行补造。
2. **统一错误处理**：响应错误优先读取 `message`，兼容 `detail`，开发环境保留 `traceId`；页面只展示可操作错误，不吞掉实际失败。
3. **SSE 生命周期**：连接建立后监听 `progress`；`DONE/FAILED` 立即关闭；`onerror` 后按 2 秒间隔轮询，终态停止轮询；组件卸载清理连接与定时器。
4. **上传流程**：严格按 `presign → PUT → upload → stream` 执行；真实预签名地址不可访问时显示失败原因，不跳过直传，不把本地文件状态标记为成功。
5. **路由与空态**：所有审核/报告入口必须带真实 `contractId`；没有合同时回到合同中心并显示空态，不生成示例 UUID。
6. **报告等待**：生成报告按钮只负责派发；订阅返回任务，`DONE` 后加载 `ReportData`，`FAILED` 显示失败并提供重试；未生成时显示引导而非通用错误。
7. **反馈与设置**：反馈列表、统计和 CSV 使用真实数据；设置页重新进入必须重新读取后端值；阈值 UI 显示 0~100、请求/响应统一 0~1。
8. **部署**：Vite 开发代理为 `http://localhost:8000`；Docker Web 容器对非 API 路径使用 `try_files $uri $uri/ /index.html`；顶层 nginx 继续负责 `/api` 反代。
9. **文档真实性**：README 与交付报告只能写已验证命令和结果；T-D6/T-D4 未完成时，必须显式标注“静态构建通过、真实 E2E 未验收”。

## ⑧ 测试要求

### 静态与类型

- 运行 `pnpm --filter @contract-guard/web-ui lint`、`pnpm --filter @contract-guard/web-ui build`。
- 运行两次 `pnpm --filter @contract-guard/schema gen`，使用 `Get-FileHash` 记录并比对三个生成物。
- 检查前端代码无新增 Mock 数组、固定合同 UUID、`.local` 跳过或页面级 `fetch`。

### 真实浏览器 E2E

必须按以下顺序验证：

1. 打开合同中心，确认列表来自真实 API。
2. 上传 PDF/DOCX，观察真实 MinIO PUT、上传任务和 SSE 进度。
3. 进入审核工作台，确认要素、风险、矛盾、印章均来自选中合同。
4. 触发 AI 改写，确认返回真实 Diff。
5. 提交批注，确认结果可查询/重读。
6. 生成 DOCX 报告，确认任务终态后才加载报告并下载。
7. 提交反馈并刷新，确认列表仍存在。
8. 修改规则启用状态和阈值并刷新，确认仍保持。

### 失败与部署

- MinIO 不可用、预签名 URL 不可访问、SSE 中断、报告未生成、报告失败、空列表六类路径必须有可见状态。
- 运行 `docker compose -f docker/docker-compose.yml config --quiet`。
- 验证 `http://localhost:5173` 与 `http://localhost:8080` 下根路径、动态路由深链接和 `/api` 反代。
- 运行 `scripts/e2e_smoke.py`，退出码必须为 0；全量 pytest 不低于总纲登记的当前基线。
