## ⑥ 实现规范

1. 🔴 **声明必须与实际一致**：现状是"声明 `paddleocr>=2.7` 但无 `paddlepaddle`"，导致**装了包装层却一行都跑不了**（F4）。本任务的验收就是消除这种悬空声明。
2. 🔴 **版本区间不得敞口**：`paddleocr` 2.x 与 3.x 的构造参数与 `ocr()` 返回结构**不兼容**（模块总纲 §3.1.3），必须写 `>=2.10,<3.0` 或 `>=3.0,<4.0`，禁止 `>=2.7`。
3. 🔴 **模型可离线**：路线 A 首次运行会**联网下载**检测/识别模型；演示机若离线必须先落到 `CG_OCR_MODEL_DIR` 并登记。路线 B 模型随轮子分发，**离线可用**——这是它在演示场景的关键优势。
4. 🔴 **延迟导入是 3-3 的责任，但本任务要为之铺路**：装完引擎后**不要把任何引擎 import 写进 `doc_processor/*/__init__.py` 顶层**（否则缺引擎会让整包 import 崩溃）。
5. 🔴 **装包只进 `.venv`**：本机系统 Python（`D:\aanacoda1`）与 `.venv` 是两套环境；`1-1`/`2-x` 的所有验证都假定 `.venv` 优先。
6. ⚠️ 新增依赖后必须复跑全量测试（基线 **140 passed**），确认没有把 `numpy` / `opencv` 版本顶上去而破坏既有用例。
7. ⚠️ `.env.example` 只写 `CG_OCR_ENGINE=auto` 这类**注释示例**，不写真实绝对路径。

## ⑨ 避坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | 在 `paddlepaddle` 上死磕 | 本机 Python **3.13.9 + Windows**，官方轮子覆盖有限；最多试 3 次，失败即切 RapidOCR |
