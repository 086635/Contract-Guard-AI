## ⑤ 接口规格

```text
用法：
  python scripts/eval_recall.py --gold scripts/data/gold.jsonl [--corpus <jsonl>]
        [--top-k 10] [--baseline scripts/data/baseline.json] [--json]

退出码：0 = 达标且不低于基线；1 = 低于基线（门禁失败）；2 = 输入/配置错误

输出（人类可读）：
  config      : vector_store=… embed_mode=… rerank_mode=… model=…
  pairs       : <N> 条 query
  Recall@1    : 0.xx   Recall@5 : 0.xx   Recall@10 : 0.xx   MRR : 0.xx
  EMPTY_RECALL: <m> 条（阈值 0.35 下判为"无标准对照"）
  baseline    : <路径> → 判定 PASS / FAIL

标注集行格式（JSONL）：
  {"query": "买方逾期付款的违约金上限", "gold_chunk_ids": ["<chunk_id>", "…"], "source": "human|weak"}
```

## ⑥ 实现规范

1. 🔴 **必须走 `RAGService`**：脚本里**不得**直接调 embedder/store/reranker 拼流程（否则评的不是产品路径）。
2. 🔴 **配置由环境决定**：脚本只读 `CG_RAG_*`（经 `build_service_from_settings()`），**不得**在脚本里覆盖阈值/模式。
3. 🔴 **两种配置各跑一次**：`hash`（离线基线，必跑）与 `http`（真实语义，服务不可用时跳过并标注"N/A"）。
4. 🔴 **两套标注集分列**：输出与回填表都必须区分 `human` / `weak`；**不得合并成一个数字**。
5. ⚠️ **确定性**：`temperature` 无关（检索是确定性的）；同配置两次运行结果必须逐字相同。
6. ⚠️ **`EMPTY_RECALL` 单列**：它既是降级信号，也是"缺失标准对照"的业务信号 —— 单独计数并打印 query。
7. ⚠️ **基线文件**：`--baseline` 传入上一次的 json（含各指标），低于即退出码 1；基线文件本身**入库**（便于回归对比）。

## ⑨ 避坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | 脚本里自己拼检索 | 评的不是产品路径，数字没有意义；断言会抓 |
| 2 | 把 `hash` 的基线当成"召回能力" | `hash` 是**伪向量**，它的数字只是**回归基线**；真实能力看 `http` 那一行 |
| 3 | 把弱标注与人工标注合并成一个数 | `AGENTS.md §6 DoD-4` 明确禁止；两者混淆会让指标虚高 |
| 4 | 在脚本里覆盖 `score_threshold` | 阈值口径是冻结的（0.35）；要调参走单独评审 |
| 5 | 只跑一次就下结论 | 必须两次运行验确定性（否则"评测"不可复现） |
| 6 | 基线文件不入库 | 没有基线就无法回归；基线 json 必须入库 |
