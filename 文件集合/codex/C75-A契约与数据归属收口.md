## ② 范围

### ✅ 做

1. `Contract` 模型兼容新增 `created_by_id`（UUID, nullable, FK → users.id）与 `legacy`（Boolean, default false）。
2. Alembic 迁移：老合同 `created_by_id = null` 且 `legacy = true`；**不得伪造管理员归属**（对齐 `4-7` §⑤.11）。
3. 上传/派发链路接线 `created_by_id`（`ingestion.py` 已预留 `user` 参数，本卡把当前用户写入归属）。
4. 可见性收紧：合同列表 / 详情 / 预览归还 / 任务查询 / SSE 订阅均按归属过滤；仅 ADMIN 可跨归属（对齐 `4-7` §⑥.2「任务访问权由网关在派发和查询时校验」）。
5. 契约兼容加法：`packages/schema/openapi.yaml` 的 `Contract` 增加可选 `createdById`、`legacy`；执行 `pnpm --filter @contract-guard/schema gen`。
6. **P1-1 一并收口**：重生成后确认 TS 生成物含 `TASK_RECOVERED` / `FILE_REJECTED`，并登记四产物哈希。

### ❌ 不做

- 不做多租户 SaaS、组织层级、OIDC SSO（`4-7` §②）。
- 不改 `rag_contracts` 既有字段/枚举；不改既有枚举语义（只做兼容加法）。
- 不新增未登记路径；不动 `rag_core/service.py`。
- 不在本卡内执行 C75-C 的 P1-2~P1-5。

## ⑤ 接口规格

```text
# 迁移（Alembic）
upgrade():   ALTER TABLE contracts ADD COLUMN created_by_id UUID NULL REFERENCES users(id);
             ALTER TABLE contracts ADD COLUMN legacy BOOLEAN NOT NULL DEFAULT FALSE;
             UPDATE contracts SET legacy = TRUE WHERE created_by_id IS NULL;
downgrade(): DROP COLUMN legacy; DROP COLUMN created_by_id;

# OpenAPI（兼容加法）
Contract:
  createdById: { type: string, nullable: true }   # 新增可选
  legacy:      { type: boolean, default: false }  # 新增可选

# 可见性（服务层，不新造函数）
list_contracts(user)      -> 仅返回 created_by_id == user.id（ADMIN 例外）
get_contract(id, user)    -> 归属不符 → 404（不泄露存在性）
task/SSE 订阅             -> 复用同一归属判定
```

## ⑥ 实现规范

1. 迁移**只做兼容加法**：新列可空/带默认；禁止 drop 既有列或改既有列类型。
2. 老数据迁移后必须 `legacy = TRUE`（`created_by_id IS NULL`），**禁止**回填成某个管理员 id。
3. 归属过滤必须落在**服务/仓储层单一入口**，路由只透传当前用户；禁止在多处各写一份过滤条件（`0.§0.7`）。
4. 归属不符统一返回 **404**（不区分「无权」与「不存在」，防 IDOR 探测）。
5. 生成物一律 `pnpm gen` 重生成，**禁止手改**（`0.§5.3`）。
6. 新增列若被契约暴露，必须同步 `types.ts` / `zod.ts`，并由 release 漂移守卫锁死。
7. **回滚**：`alembic downgrade` 删除新增两列即可；回滚保留既有数据卷，**不 drop 用户/合同数据**；回滚镜像保留对新列的兼容读路径（`4-7` §⑤.11）。
