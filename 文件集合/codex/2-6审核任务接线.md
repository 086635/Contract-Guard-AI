## ⑤ 接口规格

```python
# worker/adapters.py
def to_clause_inputs(payload: list[dict]) -> list[ClauseInput]:
    """把解析层/联调用的条款 payload 适配为审核图输入。

    字段映射（唯一处）：
      clause_id  ← payload["clause_id"] 或 payload["id"]（**二者皆缺 → 跳过该条并记 warning**）
      label      ← payload["label"] 或 payload.get("section_id") 或 clause_id（兜底）
      text       ← payload["text"]（缺失 → 跳过）
      level      ← payload.get("level", 0)
      parent_id  ← payload.get("parent_id")
      page_no    ← payload.get("page_no")
      bbox       ← payload.get("bbox")（**缺省必须是 None，禁止用 (0,0,0,0) 伪造**）

    Args:
        payload: 条款字典列表（来自 parse 产物或联调脚本）。

    Returns:
        适配后的 `ClauseInput` 列表（顺序与入参一致，跳过的条目会在日志中记数）。
    """
```

```python
# worker/progress.py
class AuditProgressReporter:
    """审核进度上报（Celery `update_state` 封装）。

    meta 结构对齐 openapi `TaskProgress`：{taskId, stage, percent, status, result}。
    """

    def __init__(self, task, contract_id: str, trace_id: str) -> None: ...

    def start(self) -> None:
        """RUNNING / stage="classify" / percent=0.0。"""

    def stage(self, name: str) -> None:
        """按**阶段→百分比表**上报（name 必须 ∈ AUDIT_STAGES，否则记 warning 并忽略）。"""

    def finish(self, result: dict | None = None) -> None:
        """DONE / percent=1.0 / result=result。"""

    def fail(self, reason: str) -> None:
        """FAILED / percent=当前值 / result={"reason": reason}。"""
```

**阶段 → 百分比表（唯一处）**：

| stage | percent | 说明 |
|---|---|---|
| （start） | `0.00` | 任务开始 |
| `classify` | `0.10` | |
| `extract` | `0.25` | |
| `risk` | `0.60` | 最耗时阶段（逐条款 OCR+RAG+LLM） |
| `conflict` | `0.75` | |
| `standard_compare` | `0.88` | |

```python
def run_audit_task(
    self,
    contract_id: str,
    clause_payload: list[dict] | None = None,
    tolerance: str = "BALANCED",
) -> dict:
    """对单个合同执行批量审核（§10 步骤4-5）。

    Returns:
        形如 `{"contractId", "traceId", "status", "risks", "conflicts",
        "missingClauses", "healthScore", "warnings", "stageLog", "tookMs"}` 的字典；

```

**流式执行（进度如何与阶段对齐）**：

```python
graph = build_audit_graph(deps)
for chunk in graph.stream(state, config={"configurable": {"thread_id": contract_id}}, stream_mode="updates"):
    for node_name in chunk:            # 每个 yield 恰是一个已完成节点
        reporter.stage(node_name)
final = graph.get_state(config).values          # 或最后一次 chunk 合并结果
```

> 🔴 **这不是"每条款一个节点"**：`stream_mode="updates"` 的粒度是**节点**，本图只有 6 个节点，
> 因此**恰好**产生 6 次进度事件（与 `AUDIT_STAGES` 一一对应）。这正是 `2-4` §② 拒绝"按条款建节点"的收益之一。

## ⑥ 实现规范

1. 🔴 **`thread_id = contract_id`**（审核流）；多合同并发靠 `thread_id` 隔离。改写流的组合键规则见 `2-7`。
2. 🔴 **`trace_id` 由任务生成一次并贯穿**：`state.trace_id` → `log_event` → `RagTool(..., trace_id=...)` → 进度 meta。
3. 🔴 **`meta` 必须 JSON 可序列化**：Pydantic 模型一律 `model_dump(by_alias=True)` 后再放进 `update_state`（Celery `json` 序列化器，见 `worker/main.py`）。
4. 🔴 **任务内不得构造模型**：`GraphDeps(rag_tool=build_rag_tool(), llm=None, prompt_lib=PromptLibrary(<templates 目录>))`——模型由 `2-2` 的工厂惰性提供。
5. 🔴 **失败必落进度**：`except Exception as exc:` → `reporter.fail(...)` + `log_event(..., level="ERROR")` → 返回 `{"status": "FAILED", "reason": str(exc)}`。
6. 🔴 **无条款数据是降级不是失败**：`clause_payload` 为空 → `status="DEGRADED"`、`warnings` 含 `"无条款数据"`，**不调图**。
7. ⚠️ **`clause_payload` 缺省时的取数路径**：`None` 时**不猜**——直接返回 `DEGRADED`（`detail="未提供条款数据"`），
   把"从解析产物取数"留给 `3-6` 定义的对象键与读取器（**避免第二处定义存储键**）。
8. ⚠️ 进度**单调不减**：`AuditProgressReporter` 内部记录上次 percent，出现回退时记 warning（防止重跑阶段导致前端进度条倒退）。
9. ⚠️ 日志命名空间 `get_logger("worker.tasks.run_audit")`；事件名 `audit.task.start` / `audit.task.stage` / `audit.task.done` / `audit.task.fail`。
10. ⚠️ 结果里的 `risks` / `conflicts` / `missingClauses` **按 openapi 字段名（camelCase）**输出，供 `gen_report` 与前端直接消费。
