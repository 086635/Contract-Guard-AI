## ⑤ 接口规格

不新增业务接口。部署验收命令与行为：

```text
GET /                       -> SPA index
GET /contracts             -> SPA index
GET /contracts/{id}/audit  -> SPA index
GET /api/v1/...            -> API gateway
```

Docker Web 使用：

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

## ⑥ 实现规范

1. `vite.config.ts` 的代理 target 必须为 `http://localhost:8000`，不得保留 `8008`。
2. Docker Web 的 nginx 配置只回退前端路由；`/api` 仍由顶层 nginx 或同源代理转发到 API。
3. README 的命令必须可从仓库根执行；写明 `pnpm install`、`pnpm gen`、`web-ui dev/build` 和 compose 启动顺序。
4. `INTEGRATION_STATUS.md` 必须把 2026-08-29 的 Mock 阶段与当前 T-D4/T-D6 状态区分，不确定处写“待验收”，不写完成。
5. 交付报告必须包含：改动文件清单、命令、输出摘要、实测值、未完成项、越界声明。
6. 若 T-D6/T-D4 未闭合，报告只能写“前端静态构建通过、真实 E2E 未验收”，不得下最终闭环结论。
