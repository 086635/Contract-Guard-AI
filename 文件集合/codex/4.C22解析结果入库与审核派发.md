## ② 范围

### ✅ 做

- 新增 `IngestionService`（网关侧惰性落库，沿用 C21「worker 不直连 DB、gateway 按 Celery 结果落库」模式）。
- `finalize_parse(contract_id)`：按最新 `PARSE_DOC` 任务的 Celery 结果，把 `clauses` 投影为 `ContractChunk` 写入 `contract_elements`、把 `sealDetections` 写入 `seal_detections`。
- `ensure_audit_dispatched(contract_id, clause_payload)`：解析入库成功后派发 `TaskKind.RUN_AUDIT` 并建 `audit_tasks` 行。
- 在 `GET /contracts/{id}/elements`、`.../seals`、`.../parse-status` 读前触发 `finalize_parse`（幂等，重复调用不重复 upsert/派发）。

### ❌ 不做

- 不新增 API 端点、不改 `openapi.yaml` / 生成物。
- worker 不直连 PostgreSQL。
- 不改 RAG/Agent/OCR 实现，不重写解析/审核逻辑。
- RUNNING / FAILED / 无快照时不入库、不派发。

### ⑤.1 `clause_payload → ContractChunk` 投影口径（唯一处）

| clause 键 | `ContractChunk` 字段 | 规则 |
|---|---|---|
| `clause_id` | `section_id` / `chunk_id` | `chunk_id = make_chunk_id(contract_id, str(clause_id), 0)` |
| `text` | `text` / `text_hash` / `char_count` / `token_count` | `hash = compute_text_hash(text)`；`token_count = round(char_count / 1.5)` |
| `label` | `title` / `section_path` | 缺省兜底取 `clause_id` |
| `level` / `parent_id` | `level` / `parent_section_id` | 缺省 `0` / `None` |
| `page_no` + `bbox` | `bbox` | 有几何才构造 `BBox`，否则 `None` |
| — | `doc_id` / `source_type` / `chunk_type` / `seq_in_doc` | `contract_id` / `STANDARD_CLAUSE` / `CLAUSE` / 序号（对齐 `test_contract_query_real.py::_chunk` 既有口径） |

## ⑥ 实现规范

1. `finalize_parse` 先读最新 `PARSE_DOC` 任务的 Celery 快照；非 DONE（RUNNING/FAILED/无快照）直接返回 `False`，不写库。
2. 只信任快照 `result` 顶层的 `clauses` / `sealDetections`，缺失按空列表处理，不伪造。
3. `bulk_upsert` 天然幂等（主键冲突更新），重复 `finalize_parse` 不得重复建行。
4. `ensure_audit_dispatched` 幂等：该合同已存在 `RUN_AUDIT` 任务行且 `celery_task_id` 非空时不再派发。
5. 派发参数 `(str(contract_id), clause_payload)`；`clause_payload` 取自解析结果的 `clauses`（可直接被 `worker.adapters.to_clause_inputs` 消费的形状）。
6. 埋点 `log_event`（含 `trace_id` 与 `contract_id`）；异常不向路由抛，收敛为「不入库 + warning」。
