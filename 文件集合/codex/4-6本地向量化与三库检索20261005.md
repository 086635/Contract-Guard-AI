## ② 范围

1. 复用已有官方 Ollama；从 HuggingFace 下载 BGE-M3 的 GGUF 转换版本，固定版本、核对 SHA-256，导入本机 Ollama。8 GB 显存使用小批次向量化，不加载本地生成模型。
2. 用官方 Windows Qdrant 服务持久化并共享索引，运行配置显式切换，保留代码默认 inmemory/hash、既有契约、框架与评分算法。
3. 初始库分标准库（官方合同示范文本）、条款库（官方范本的可检索条款，复用人工维护入口）、法典库（官方民法典原文）。范本不是强制性法规；不冒充企业已审批标准或全部行业标准。
4. 复用原切片与入库代码；来源、发布日期、适用范围、原文哈希落在语料和来源清单。法条不能被当前合同类型过滤掉。检索依据经现有 ContextBuilder 注入风险审核和条款改写，再调用 DeepSeek；不另写检索算法。
5. 验证真实语义、重启后持久化、来源引用、实际模型输入与审核终态。增补现有设置入口展示三库来源和语义状态（必要时），不更换前端。

## ⑤ 接口规格

沿用 /v1/embeddings 和原 RAGQueryRequest / AgentRAGToolResult。本机向量库服务仅监听回环。生成模型配置保持 DeepSeek。官方导入 CLI 接收本机来源清单及其中声明的提取原文；语料来源不是官方、数据为空、无来源或校验不符时明确失败，不能静默装成功。来源状态和预览只读、要求登录；人工条款编辑沿用原 ADMIN 接口。

## ⑨ 避坑清单

Qdrant local_path 不允许多个进程同时占用，故使用既有 server 模式连接本机官方服务。切换嵌入模型时使用新集合与独立稀疏目录，避免哈希向量混入语义索引。标准库与条款库属于同一来源类型的不同粒度，不能新增 PRECEDENT 冒充标准。官方示范文本和法条有适用范围，初始库不等于完备企业基线；检索相似不等于确认违法。Ollama 不是 reranker，本轮不把它接成精排。凭据只留本机忽略配置，报告只写模型身份及计数。

验收 A1–A6 已按上述范围完成；A4 保留缺少企业审批基线的真实 DEGRADED 状态，A5 的浏览器视觉验证限制单独说明。测试命令、版本、逐文件改动和官方适用范围见完成报告。
