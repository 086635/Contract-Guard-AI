### ✅ 做

- 建立 operationId → generated Zod Schema 的注册表。

- 不做全局 any 容错。
- 不修改生成物。

## ⑤ 接口规格

```text
endpointSchemas[operationId]
safeParse(response.data.data)
invalid -> ApiClientValidationError
```

## ⑥ 实现规范

1. 只校验业务 data 和错误体，不重新定义 API 类型。
2. 错误带 operationId/traceId，不带敏感响应。
3. 开发 fail fast，生产受控策略。
4. 覆盖所有 P0 端点。

### 实测后回填·断言逐条

| # | 断言 | 实测结果 |
|---|---|---|
| 1 | 合法响应通过 | 通过：`test_zod_valid_response`（`getCurrentUser` / `getReport` / `getRisks` / `getTask` 合法体全部 null；未登记 operationId 不校验） |

| 3 | 错误体符合 ApiError | 通过：`test_zod_api_error_shape`（`schemas.ApiError` 接受合法错误体，拒绝缺字段与枚举外 code）；兼容期错误体**只上报不硬失败**（保留 detail 回退一个发布周期） |
