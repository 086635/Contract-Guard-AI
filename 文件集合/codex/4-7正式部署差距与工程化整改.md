## ⑤ 接口规格

### ⑤.1 公共契约原则

- OpenAPI 是唯一接口真理源；所有新增字段先改 `packages/schema/openapi.yaml`，再执行生成脚本。
- 只允许兼容加法：不删除、不改名、不改变既有字段类型和枚举语义。
- 所有受保护端点在 OpenAPI 增加 `security: bearerAuth`；`/auth/login`、`/auth/refresh`、`/health/*` 除外。
- 成功响应继续使用 `ApiEnvelopeBase`；失败响应统一使用 `ApiError`。
- `ApiError` 保留 `code`、`message`、`detail`、`traceId`，新增可选 `issues` 数组用于字段级校验；旧客户端可忽略。
- 新增写接口必须声明 `X-Request-ID` 幂等；缺失或格式非法在正式环境返回 `ERR_VALIDATION`。
- 时间统一 UTC ISO 8601；ID 统一字符串；金额与百分比不改既有语义。

### ⑤.2 认证与用户接口

| 方法 | 路径 | 请求 | 响应 | 权限 |
|---|---|---|---|---|
| POST | `/api/v1/auth/login` | `LoginRequest{username,password}` | `TokenData{accessToken,expiresIn,user}` + HttpOnly refresh cookie | 公开 |
| POST | `/api/v1/auth/refresh` | `RefreshRequest` / cookie | `TokenData` | refresh cookie |
| POST | `/api/v1/auth/logout` | 无体 | `LogoutData{revoked}` | 已登录 |
| GET | `/api/v1/auth/me` | 无 | `CurrentUser` | 已登录 |
| GET | `/api/v1/admin/users` | 分页/筛选 | `UserListData` | ADMIN |
| POST | `/api/v1/admin/users` | `UserCreateRequest` | `CurrentUser` | ADMIN |
| PATCH | `/api/v1/admin/users/{userId}` | `UserUpdateRequest` | `CurrentUser` | ADMIN |

- `Role` 枚举：`ADMIN`、`REVIEWER`、`VIEWER`。
- access token 15 分钟，内存保存；refresh token 7 天，HttpOnly + Secure + SameSite=Lax cookie，服务端保存哈希与撤销状态。
- 密码使用 Argon2id；首个管理员只允许通过显式 bootstrap 环境变量或一次性 CLI 创建，禁止默认账号密码。
- 登录失败 5 次锁定 15 分钟；错误信息不得区分“用户名不存在”和“密码错误”。
- 所有用户管理与登录事件进入审计。

### ⑤.3 审计接口

| 方法 | 路径 | 请求 | 响应 | 权限 |
|---|---|---|---|---|
| GET | `/api/v1/audit/events` | `page`、`pageSize`、`actorId`、`action`、`resourceType`、`from`、`to` | `AuditEventListData` | ADMIN |

- `AuditEvent`：`id`、`actorId`、`actorRole`、`action`、`resourceType`、`resourceId`、`outcome`、`ipAddress`、`userAgent`、`traceId`、`metadata`、`createdAt`。
- `metadata` 只存结构化摘要，禁止存合同原文、Prompt 全文、API Key、refresh token。
- 审计表由应用只追加；生产数据库账号不授予 UPDATE/DELETE 审计表权限。

### ⑤.4 错误与幂等接口

- 全局异常映射：
  - `HTTPException` → 对应 `ErrorCode` + `ApiError`
  - `RequestValidationError` → `ERR_VALIDATION`，字段问题放 `issues`
  - 未处理异常 → `ERR_INTERNAL`，`detail` 只输出安全摘要
- `ApiError.issues[]`：`{path:string, code:string, message:string}`。
- 幂等键格式：`cg:idempotency:{operationId}:{userId}:{requestId}`，TTL 24 小时。
- Redis 保存请求体 SHA-256、响应状态码、响应 JSON、创建时间；同 key 同 body 重放原响应；同 key 不同 body 返回 409 `ERR_DUPLICATE_REQUEST`。
- Redis 不可用时，正式环境对声明幂等的写操作返回 503，不允许“降级后可能重复创建”。
- `/tasks/{taskId}` 和 SSE 均校验任务所属合同访问权限。

### ⑤.5 LLM 与 RAG 配置

- 新增生产环境标识：`CG_RUNTIME_ENV=development|test|production`。
- 生产启动校验：
  - `CG_LLM_PROVIDER != offline`
  - `CG_RAG_EMBED_MODE != hash`
  - `CG_RAG_RERANK_MODE != noop`
  - 外部模型必须显式设置 `CG_LLM_ALLOW_EXTERNAL_DATA=true`；默认 false。
- 模型失败处理：
  - 单条款失败允许隔离，但任务整体必须 `DEGRADED`，并写入明确 warning。
  - 全部模型调用失败或核心节点不可用时任务必须 `FAILED`，不得落空结果后显示“无风险”。
  - 报告生成必须在审核任务成功或用户显式确认 DEGRADED 后允许。
- RAG 质量门禁复用 `scripts/eval_recall.py` 与 `1-7`/`1.C10` 已登记阈值；不得在 4-7 新造第二套基线。
- 生产模型调用必须记录 provider、model、耗时、token、traceId；不得记录合同原文。

### ⑤.6 文档预览接口

| 方法 | 路径 | 请求 | 响应 | 权限 |
|---|---|---|---|---|
| GET | `/api/v1/contracts/{contractId}/preview` | 无 | `PreviewData` | 已登录且可见合同 |
| POST | `/api/v1/contracts/{contractId}/preview/retry` | `X-Request-ID` | `TaskProgress` | REVIEWER/ADMIN |

- `PreviewData`：`contractId`、`status`、`previewUrl`、`expiresIn`、`pageCount`、`converterVersion`、`createdAt`。
- `PreviewStatus`：`PENDING`、`RUNNING`、`DONE`、`FAILED`。
- PDF 直接把原 PDF 作为预览源；DOCX 通过独立 `convert` Celery 队列转 PDF。
- DOCX 预览坐标通过转换后 PDF 重新运行文本抽取/对齐，不把 DOCX 合成坐标冒充真实页面坐标。
- 预览 PDF 是派生物，原始文件永久保留；转换失败不删除原文。
- 前端使用 PDF.js 坐标空间与 `BBox.coordinateSystem=PDF_POINTS` 做比例映射。

### ⑤.7 任务可靠性与 SSE

- 外部 `Status` 继续只使用 `RUNNING`、`DONE`、`FAILED`，保持兼容；内部阶段继续使用现有 stage 常量。
- Celery 配置：`task_acks_late=True`、`worker_prefetch_multiplier=1`、软超时、硬超时、有限重试、指数退避。
- 数据库任务字段新增：`attempt_count`、`max_attempts`、`last_heartbeat_at`、`next_retry_at`、`error_code`、`locked_at`、`completed_at`。
- reconciler 定期扫描超时/失联任务：可重试则重新派发，超限则标记 FAILED 并写审计；不得无限重试。
- `POST /tasks/{taskId}/stream-token` 返回 60 秒、单任务范围 token；EventSource URL 使用 `?streamToken=...`。
- SSE 断线后前端继续使用现有 2 秒轮询；轮询同样经过权限检查。

### ⑤.8 上传安全

- `PresignRequest` 兼容新增 `sizeBytes`、`contentType`；正式环境必须提供并在 pre-sign 阶段拒绝超限。
- 服务端只允许 `PDF`、`DOCX`、约定图片类型；文件 key 由服务端生成，客户端不得提交任意 key。
- `upload` 阶段重新 `stat_object` 复核大小、ETag、bucket、prefix。
- 使用纯 Python 或 Linux 容器内可靠 MIME sniff 校验 magic bytes；扩展名与内容不一致返回 `ERR_UNSUPPORTED_FILE_TYPE`。
- `CG_UPLOAD_AV_MODE=off|clamav`：development/test 可 off；production 必须 clamav，扫描失败或发现病毒不得派发 parse。
- 所有拒绝事件写审计，不写文件内容。

### ⑤.9 生产部署配置

- 新增 Compose prod profile/overlay，development 仍可沿用当前 compose。
- 生产只暴露 nginx 的 80/443；PostgreSQL、Redis、MinIO、Qdrant、Worker 只在 compose 内网。
- Secret 从 Docker secret/受控 env 文件注入；默认口令、空 JWT secret、零长度密钥、localhost public endpoint 必须在启动时失败。
- nginx 增加 TLS、HSTS、CSP、X-Content-Type-Options、Referrer-Policy、限流和请求体大小限制。
- `/health/live` 只检查进程和事件循环；`/health/ready` 检查 DB、Redis、MinIO、Qdrant；生产禁用公开 `/docs` 或加管理员控制。
- 备份：PostgreSQL 每日 `pg_dump`，MinIO 每日镜像，保留策略按客户约定配置，至少每季度执行恢复演练。

### ⑤.10 产品与前端契约

- 标准条款库复用 RAG 的 `STANDARD_CLAUSE` 数据源与唯一检索入口；不新增第二套检索。
- `ReportData` 保留 `downloadUrl`，新增 `wordDownloadUrl`、`pdfDownloadUrl`；旧客户端继续使用 `downloadUrl`。
- Zod 运行时校验绑定 `operationId` 到生成 Schema；development/test 失败即报错，production 上报并拒绝脏数据进入核心状态。
- 所有错误、空态、加载态、重试和权限拒绝统一为现有 UI state 组件，不新增第二套状态体系。

### ⑤.11 迁移与兼容

- 迁移顺序：users/audit → contracts 归属字段 → tasks 可靠性字段 → previews → 索引/约束。
- 老合同迁移时 `created_by_id` 允许 null，但必须打上 `legacy` 标记；不得伪造管理员归属。
- 新枚举只追加，不删除；如果客户端 exhaustive switch，先发兼容版本再启用。
- 回滚时保留新增表/列的兼容读路径，禁止直接 drop 用户数据。
- 生成物哈希在发布报告中登记。

## ⑥ 实现规范

### ⑥.1 模块边界

- `api-gateway`：身份、RBAC、审计、错误包络、幂等、合同访问校验、预览元数据、SSE token、readiness。
- `async-worker`：真实模型任务、DOCX→PDF 转换队列、ClamAV 调用、任务心跳/重试、RAG 索引维护。
- `web-ui`：登录态、内存 access token、refresh、PDF.js、BBox、错误/空态、权限隐藏与拒绝提示。
- `packages/ai-engine` / `packages/rag-core`：只调整配置校验、真实 provider 接线、失败语义；不得在网关复制模型或检索算法。
- `docker/nginx`：生产网络、TLS、安全头、限流；不承载业务逻辑。
- `rag_contracts` 既有字段和 `rag_core/service.py` 在本任务中不得修改；契约变化只进 `packages/schema/openapi.yaml` 并生成。

### ⑥.2 D7-I01 / D7-I02 身份、RBAC 与用户管理

- **实测证据**：OpenAPI 有 `bearerAuth`，但后端无鉴权依赖；`GET /api/v1/contracts` 无令牌实测 200；前端无 Authorization 注入。
- **根因**：接口契约是“终态”，实现是 walking skeleton；认证没有被登记为独立施工工作包。
- **影响**：任何能访问网络的人都能读取、上传、改写和导出合同，正式环境不可接受。
- **解决路径**：先定义身份端口和角色矩阵，再接 PostgreSQL 用户表、密码哈希、JWT、refresh 撤销列表、管理员 CLI，再接前端 token 生命周期。
- **工程化方案**：`AuthService` 只依赖 `UserRepository` 和端口；`get_current_user` 只从 Bearer token 解析；路由依赖 `require_roles()`；刷新 token 只在 HttpOnly cookie 中保存。
- **模块边界**：认证只在 api-gateway 和 web-ui；worker 不 import `app.*`；任务访问权由网关在派发和查询时校验。
- **开发规范**：不得把密码、refresh token、JWT secret写日志；错误不得泄露账号是否存在；所有权限拒绝必须有单元测试。
- **单元测试**：登录成功/失败、锁定、过期 access、刷新轮换、登出撤销、角色矩阵、无权限 403、无 token 401、IDOR 拒绝。
- **验收/回滚**：关闭认证开关只允许 development；生产启动缺少密钥直接失败。回滚时保留用户/会话表但撤销新 token。

### ⑥.3 D7-I03 审计与隐私

- **实测证据**：当前仅有普通日志和 traceId；没有可查询、不可篡改的用户动作审计。
- **根因**：可观测性日志被当成合规审计，未定义“谁对哪个资源做了什么”的数据模型。
- **影响**：无法追责合同查看、导出、改写、设置修改；合同原文可能进入普通日志。
- **解决路径**：建立 append-only audit_events，采集登录、上传、查看、风险/要素读取、改写、提交、报告、设置、导出、拒绝事件。
- **工程化方案**：审计写入通过 `AuditService` 唯一入口；失败不阻断主业务但必须告警；metadata 白名单过滤；管理员分页查询。
- **模块边界**：审计采集在 api-gateway；worker 只上报必要 task 事件；不把合同正文写入事件。
- **开发规范**：所有敏感字段必须走脱敏 helper；新增动作必须登记 action 常量；日志不得携带 cookie/Authorization。
- **单元测试**：action 白名单、metadata 脱敏、分页过滤、append-only repository、审计写入失败告警、权限限制。
- **验收/回滚**：管理员可查到指定 traceId 的完整动作链；回滚只关闭查询入口，不删除审计数据。

### ⑥.4 D7-I04 / D7-I05 错误包络与幂等

- **实测证据**：404 实测返回 `{"detail":"contract not found"}`；422 实测返回 FastAPI 校验数组；OpenAPI 要求 ApiError。
- **根因**：路由层直接抛 FastAPI 异常，没有全局转换；客户端不得不兼容 `detail`，掩盖了契约漂移。
- **影响**：外部客户端无法稳定解析错误，traceId 丢失，重试可能重复创建任务。
- **解决路径**：注册全局异常处理器，统一错误码映射；实现 Redis 幂等中间件，业务路由不重复写第二套缓存。
- **工程化方案**：`ApiError` 增加可选 issues；中间件按 operationId/user/requestId 生成 key；存储 body hash 与响应；冲突返回 409。
- **模块边界**：api-gateway middleware/service；OpenAPI 只加可选字段；前端删除对裸 detail 的核心依赖，但保留兼容回退。
- **开发规范**：异常只能抛领域异常或 HTTPException；禁止路由手拼错误 JSON；错误 detail 不包含堆栈和敏感数据。
- **单元测试**：401/403/404/409/422/503 响应形状、traceId、issues、幂等重放、同 key 不同 body 409、Redis 不可用 503。
- **验收/回滚**：旧客户端仍能读取 message/detail；回滚时保留旧错误格式兼容分支，至少一个发布周期。

### ⑥.5 D7-I06 / D7-I07 / D7-I08 真实 LLM 与语义 RAG

- **实测证据**：Compose worker 设置 offline；离线桩对 `_RiskDraft` 返回 `UNLIMITED_LIABILITY/HIGH/空标题/空建议`；当前 rewrite 返回 502。
- **根因**：离线默认值既服务测试又服务部署，生产 false-positive/false-negative 语义未定义。
- **影响**：用户会看到无依据风险或错误“无风险”；外部模型可能接收未授权合同文本。
- **解决路径**：生产 profile 强制真实 provider；模型失败按 FAILED/DEGRADED 显式返回；RAG 接真实 embedding/rerank 并执行召回评测。
- **工程化方案**：配置启动校验；provider 客户端仍由现有 factory 唯一构造；RAG 服务继续由 `build_service_from_settings` 装配；不外泄原文到日志。
- **模块边界**：ai-engine/rag-core 只改配置和失败语义；worker 只消费端口；api-gateway 只接收结构化结果。
- **开发规范**：禁止在生产生成空风险占位；禁止输出 Prompt、合同全文、API Key；模型调用必须有超时、重试、预算和成本字段。
- **单元测试**：offline 生产拒绝、真实 provider 选择、模型超时、结构化解析失败、全失败 FAILED、部分失败 DEGRADED、外部数据开关。
- **验收/回滚**：真实模型 Diff、风险样本、Recall@K/MRR 达到已登记阈值；回滚只能回滚应用镜像，不把 offline 当生产降级。

### ⑥.6 D7-I09 / D7-I10 真实文档预览

- **实测证据**：PdfStage 固定采购合同、固定 8 页、固定文字；PdfViewer 仍是占位；无 DOCX→PDF 任务。
- **根因**：前端原型先做视觉骨架，后端只解决解析和文本坐标，未定义浏览器可消费的派生产物。
- **影响**：审核页无法定位真实合同原文，BBox 与实际页面对不上，正式审核不可信。
- **解决路径**：PDF 直用 PDF.js；DOCX 入 convert 队列；转换后重新抽取文本/对齐；API 只返回短期预览 URL 和状态。
- **工程化方案**：现有 async-worker 新增 `convert_doc` 任务与 `convert` 队列；LibreOffice 只运行在容器；预览元数据写 contract_previews；失败可重试且不影响原文。
- **模块边界**：doc-processor 算法层只复用现有解析/aligner；web-ui 只消费 BBox，不自己推断坐标；worker 不写业务 DB。
- **开发规范**：禁止硬编码文件名/页数/合同文字；预览 URL 必须短期签名；转换版本要写入元数据；BBox 映射统一 PDF_POINTS。
- **单元测试**：PDF 预览状态、DOCX 转换成功/失败/超时、重试幂等、无坐标条款不伪造 bbox、相对变焦映射、越界 BBox 夹取。
- **验收/回滚**：上传 PDF 和 DOCX 均能打开真实文档；点击风险能跳到正确页并提供高亮；转换失败显示可重试而非空白纸张。

### ⑥.7 D7-I11 / D7-I12 任务可靠性与 SSE 鉴权

- **实测证据**：Celery 没有 acks_late/超时/心跳回收；EventSource 原生不能携带 Authorization；任务表没有 attempts/heartbeat。
- **根因**：当前实现验证了 happy path，但没有定义 worker crash、网络中断、重复派发和长期 RUNNING 的处理。
- **影响**：任务可能永久卡住、重复执行或显示假进度；认证上线后 SSE 会失效。
- **解决路径**：DB 任务状态作为真实状态源，Celery 仅作执行器；acks_late + 心跳 + reconciler；SSE 使用短期 stream token。
- **工程化方案**：任务派发前先写 QUEUED/RUNNING 兼容行；report/rewrite/parse 全部幂等；stale 超限标 FAILED；前端 token 失效后转轮询。
- **模块边界**：api-gateway 负责任务身份和 token，worker 负责执行和心跳，Redis 只做进度/队列，不成为唯一状态源。
- **开发规范**：不得无限重试；不得吞异常当成功；不得用 time.sleep 做长任务；任务参数必须 JSON schema 化。
- **单元测试**：重试、超时、心跳过期、reconciler、重复派发、token 过期、跨用户任务拒绝、SSE 断线轮询。
- **验收/回滚**：worker 被杀后任务最终进入 FAILED 或重试；SSE 鉴权可通过，无权限返回 403。

### ⑥.8 D7-I13 上传安全

- **实测证据**：文件类型和 50 MB 限制只在 UploadPanel 前端；后端 presign 不接收大小/内容约束，无 AV。
- **根因**：开发阶段把用户体验校验误当成安全边界。
- **影响**：绕过前端可上传任意对象、伪造扩展名或压缩炸弹，解析/OCR 可被滥用。
- **解决路径**：服务端在 presign、stat、scan、parse 四个阶段逐层校验；客户端输入只作提示。
- **工程化方案**：预签名绑定 key/expiry/size；upload 复核 ETag/size/magic；ClamAV 异步扫描；扫描前的对象不能进入 parse。
- **模块边界**：api-gateway 管元数据和准入，worker 管扫描/解析，MinIO 只存对象；不把 AV 逻辑塞进前端。
- **开发规范**：禁止信任 Content-Type/文件扩展名；错误信息不回显恶意文件名；文件 key 由服务端生成。
- **单元测试**：超限拒绝、类型不匹配、空文件、伪造扩展名、ETag 不一致、病毒结果、AV 超时、恶意 key 拒绝。
- **验收/回滚**：绕过前端直接调 API 也不能上传非法对象；回滚不得关闭生产强制校验。

### ⑥.9 D7-I14 / D7-I15 生产部署与运维

- **实测证据**：Compose 使用 `cg/cg`、`minioadmin/minioadmin`，公开多个基础设施端口，`CG_MINIO_PUBLIC_ENDPOINT=localhost:9000`，无 TLS/备份/限流。
- **根因**：开发 Compose 没有生产 profile，基础设施边界和密钥治理缺失。
- **影响**：数据库/对象存储可被直接访问，外部浏览器预签名失效，故障无法恢复。

- **工程化方案**：Docker secrets、nginx TLS、限流、CSP、PostgreSQL pg_dump、MinIO mirror、只暴露 80/443、启动自检。
- **模块边界**：部署配置只改 docker/nginx/scripts 与配置校验；不写业务逻辑，不绕过迁移。
