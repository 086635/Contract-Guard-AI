## ⑤ 接口规格

### 5.1 分流接口

```python
# doc_processor/router.py
class RouteKind(str, Enum):
    """输入文档的处理支路（模块 3 内部枚举，不进契约层）。"""

    DOCX = "DOCX"                # python-docx 直抽（结构化程度最高）
    PDF_NATIVE = "PDF_NATIVE"    # pdfplumber 直抽（逐词坐标，精度最高）
    PDF_SCANNED = "PDF_SCANNED"  # pypdfium2 渲染 → OCR
    IMAGE = "IMAGE"              # 直接 OCR


@dataclass(frozen=True, slots=True)
class RouteDecision:
    """一次分流的结论（**必须可解释**）。"""

    kind: RouteKind
    reason: str                        # 中文，含关键数字（如"抽样 3 页平均 412.0 字符 ≥ 50"）
    page_count: int                    # 图片为 1
    sampled_pages: list[int]           # 1-based；图片为 [1]
    avg_chars_per_page: float          # 采样页的平均可抽字符数（图片为 0.0）


class DocRouter:
    """文档分流器。

    设计要点：
    1. **绝不对所有 PDF 都跑 OCR** —— 数字版 PDF 直抽更准、更快、坐标天然精确。
    2. 判定依据是"抽样页的平均可抽字符数"，阈值来自 `OcrSettings`（**配置必须被消费**）。
    3. 每条支路的决策都必须写进 `reason` 并打点，便于排查"为什么这份走了 OCR"。
    """

    def __init__(self, settings: OcrSettings | None = None) -> None: ...

    def route(self, path: str | Path) -> RouteDecision:
        """判定输入文件的处理支路。

        Args:
            path: 输入文件路径（.docx / .pdf / 图片）。

        Returns:
            分流结论。

        Raises:
            UnsupportedFormatError: 扩展名不在支持集合内，或文件不可读。
        """
```

### 5.2 支路映射表（**唯一处**）

| `RouteKind` | 扩展名 | 后续处理 | 由谁实现 |
|---|---|---|---|
| `DOCX` | `.docx` | `python-docx` 段落/表格直抽 | 3-4 |
| `PDF_NATIVE` | `.pdf`（采样页平均字符 ≥ 阈值） | `pdfplumber` 逐词坐标 | 3-4 / 3-5 |
| `PDF_SCANNED` | `.pdf`（采样页平均字符 < 阈值） | `pypdfium2` 渲染（`render_dpi`）→ OCR | 3-3 |
| `IMAGE` | `.png` `.jpg` `.jpeg` `.bmp` `.tif` `.tiff` `.webp` | 直接 OCR（按 72dpi 解释，或用 `render_dpi` 时归一） | 3-3 |

### 5.3 配置（`OcrSettings`，**模块 3 全部配置项的唯一处**）

```python
# doc_processor/config.py
class OcrSettings(BaseSettings):
    """OCR / 解析模块配置（唯一处）。默认值必须离线可跑。"""

    model_config = SettingsConfigDict(env_prefix="CG_OCR_", env_file=".env", extra="ignore")

    # —— 分流（消费方：3-2）——
    native_text_min_chars: int = 50     # 采样页平均可抽字符数 ≥ 此值 → PDF_NATIVE
    route_sample_pages: int = 3         # 采样页数（首/中/末），不足则全取

    # —— 引擎与渲染（消费方：3-3）——
    engine: Literal["auto", "rapid", "paddle"] = "auto"
    render_dpi: int = 200               # PDF → 图像 DPI；**坐标归一必须用它**
    image_dpi: int = 72                 # 独立图片的 DPI 假设（1 像素 = 1 点）；3-3 消费
    lang: str = "ch"
    min_confidence: float = 0.5         # 低于此值的 OCR 结果丢弃
    model_dir: str | None = None        # 引擎模型目录（离线场景必填）
    timeout_s: int = 60                 # 单页 OCR 超时

    # —— 印章（消费方：3-8）——
    seal_min_area_ratio: float = 0.0005 # 红色区域最小面积占比（相对页面）
    seal_ring_steps: int = 360          # 极坐标展开采样角数
```

> 🔴 **每一项都必须有消费方**（标准 §0.4「新增配置必须被消费」）。上表已逐项标注消费任务；
> 未落地的字段在对应任务完成前**不得**出现在代码里（先加声明、后无人读 = 重造 8 项失效配置的老问题）。

## ⑥ 实现规范

1. 🔴 **采样算法（唯一处）**：
   - 页数 `n ≤ route_sample_pages` → 采样全部页；
   - 否则取 **首 / 中 / 末** 三页（`1`、`ceil(n/2)`、`n`，去重后可能少于 3 页）。
2. 🔴 **判定规则**：`avg_chars_per_page ≥ native_text_min_chars` → `PDF_NATIVE`，否则 `PDF_SCANNED`。
   阈值**必须**来自 `OcrSettings.native_text_min_chars`（禁止硬编码 50）。
3. 🔴 **`.docx` 不采样**：直接 `DOCX`（它没有"文本层"概念）。
4. 🔴 **图片不判扫描**：直接 `IMAGE`（不做无意义采样）。
5. 🔴 **损坏 / 不可读文件**：抛 `UnsupportedFormatError`（附路径与原因），**不得**静默降级为 `PDF_SCANNED`
   —— 否则一个坏文件会让 OCR 白跑几分钟。
6. 🔴 **`reason` 必须含数字**：如 `"抽样 3 页平均 412.0 字符 ≥ 阈值 50 → 数字版直抽"`。
7. 🔴 **打点**：`log_event(_LOG, "ocr.route", trace_id=trace_id, kind=..., page_count=..., avg_chars=...)`；
   命名空间 `get_logger("doc_processor.router")`。
   ⚠️ 因此 `pyproject.toml` 需补 `cg-observability`（**唯一日志通道**，不要另起 `logging.basicConfig`）。
8. ⚠️ **`pymupdf` 只用于测试夹具与（受控的）页面渲染**：生产渲染路径统一 `pypdfium2`（模块总纲 §3.4.1）。
   若测试里用 `pymupdf` 生成夹具，需在 `pyproject.toml` 的 `[dependency-groups] dev` 声明，**不进运行期依赖**。
9. ⚠️ 路径统一用 `pathlib.Path`；扩展名判定小写化。
10. ⚠️ `DocRouter` 不得持有引擎句柄（无状态、可重复 `route()`）。

## ⑨ 避坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | 对所有 PDF 都跑 OCR | **本模块最大的坑**：数字版 PDF 直抽更准更快，OCR 只会引入误差 |
| 2 | 把 `native_text_min_chars` 写死 50 | 违反标准 §0.4；且无法应对"图文混排"样本调参 |
| 3 | `route_sample_pages=0` | 采样除零；配置需 `ge=1` |
| 4 | 把读取失败当成扫描件 | 坏文件会白跑几分钟 OCR；必须抛错 |
| 5 | 为 `.docx` 做"文本层采样" | docx 无此概念，纯属浪费 |
| 6 | 在 `router.py` 里 import 引擎 | 分流不该依赖引擎；缺引擎时分流仍应可用（便于排查） |
| 7 | 另起一套 `logging` | 日志必须走 `cg_observability`（标准 §0.5.3），否则 trace_id 断链 |
| 8 | 用 `pdf2image` 渲染 | Windows 无 poppler；生产渲染统一 `pypdfium2`（3-3） |
| 9 | 忘记把 `RouteDecision.reason` 落日志 | 演示时"为什么这份走了 OCR"无法解释，排查成本极高 |
