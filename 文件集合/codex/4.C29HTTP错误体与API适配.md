## ② 范围

### ✅ 做

- 统一兼容后端错误体 `{ code, traceId, serverTime, message?, detail? }`。
- `message` 优先作为用户可见错误，`detail` 作为兼容回退；保留 `traceId` 供开发日志和交付证据使用。
- 保持 Axios 单例、`X-Request-ID` 注入、超时和成功包络处理不变。
- 将网络错误与业务错误区分，页面可收到稳定、可读的 `Error`。

### ❌ 不做

- ❌ 不改 `services.ts` 各业务方法的端点或参数。
- ❌ 不新增第二套 HTTP Client、拦截器或请求封装。
- ❌ 不改变成功包络 `{code, traceId, serverTime, data}` 的消费规则。
- ❌ 不吞掉 401/403/404/409/500 等真实状态码。

## ⑤ 接口规格

```ts
// 不新增导出接口；保持：
export const httpClient: AxiosInstance;

// 错误行为约定：
// - error.response.data.message 优先
// - error.response.data.detail 兼容回退
// - error.response.data.traceId 保留在开发日志/错误上下文
// - 无响应时保留 Axios network error，不伪造业务错误
```

## ⑥ 实现规范

1. 在响应错误拦截器中读取 JSON 错误体；字段读取必须做类型守卫，不能假定必存在。
2. 若 `message` 非空，覆盖 `error.message`；否则仅在有 `detail` 时使用 `detail`。
3. `traceId` 只用于开发环境日志或错误上下文，不拼接面向用户的中文说明。
4. 成功响应继续原样返回，不在 Client 层解包 `data`；解包仍由 `services.ts` 负责。
5. 不在页面层捕获错误后重置为固定成功状态。
