## ⑤ 接口规格

### 5.1 流水线主体

```python
# apps/async-worker/worker/parse_pipeline.py
from __future__ import annotations

from dataclasses import dataclass, field
from pathlib import Path
from typing import Sequence

from doc_processor.aligner.aligner import build_bbox_aligner
from doc_processor.ocr.engine import build_ocr_engine, render_pdf_page
from doc_processor.parser.extractor import TextLine, build_node_extractor
from doc_processor.router import DocRouter, RouteDecision

Row = tuple[int, str, float, float, float, float]   # (page, text, x, y, width, height)


class SourceUnavailableError(RuntimeError):
    """源文件三种途径都拿不到（本地路径不存在 + MinIO 不可用/对象不存在）。"""


@dataclass(slots=True)
class ParseOutcome:
    """解析流水线结果信封（**不落库**：本仓当前无 DB DAL）。"""

    contract_id: str
    status: str                       # SUCCESS | DEGRADED | FAILED（判定表见 §6.7）
    file_type: str                    # FileType：DOCX / PDF_NATIVE / PDF_SCANNED / IMAGE
    route_reason: str                 # 直接取 RouteDecision.reason（可解释）
    page_count: int
    elements: list[dict] = field(default_factory=list)
    clauses: list[dict] = field(default_factory=list)
    seal_detections: list[dict] = field(default_factory=list)
    layout_blocks: list[dict] = field(default_factory=list)   # 3-7 的产物（P1 软依赖）
    line_count: int = 0
    char_count: int = 0
    coordinates_synthetic: bool = False   # DOCX 路径为 True（无真值坐标）
    ocr_used: bool = False
    engine_name: str = "none"
    warnings: list[str] = field(default_factory=list)
    stage_log: list[dict] = field(default_factory=list)
    artifact_path: str | None = None
    took_ms: int = 0

    def to_payload(self) -> dict:
        """转 camelCase 信封（字段表见 §5.3）。"""


def assemble_text_lines(rows: Sequence[Row]) -> tuple[list[TextLine], str]:
    """把「页 / 文本 / 坐标」行序列装配为 `TextLine` 序列 + 全文（**字符偏移唯一处**）。

    规则（唯一处，四条支路共用）：
      1. 只保留 `text.strip()` 非空的行（空行不占偏移，避免前端高亮掐到空白）；
      2. 行间分隔符固定 `"\\n"`；`char_start` = 上一行 `char_end` + 1；
      3. `char_end = char_start + len(text)`，**半开区间**（与 3-5 的 `locate()` 语义一致）；
      4. 不排序、不去重（顺序由各支路负责给出阅读顺序）。

    Args:
        rows: 行元组序列，按阅读顺序。

    Returns:
        `(lines, full_text)`；`full_text` 为各行以 `"\\n"` 拼接的结果。
    """


def clause_payloads(clauses: list, lines: Sequence[TextLine], aligner) -> list[dict]:
    """条款 → 2-6 适配器的输入 dict（**键名映射唯一处**，见 §5.4）。

    bbox 规则：按 3-4 §5.4 的条款边界规则复扫行序列得到行区间 → 取该区间的
    `aligner.locate()` 并集框；跨页条款取**起始页**的并集框；**无法定位则 `None`（禁伪造）**。
    """


class ParsePipeline:
    """解析流水线（与 Celery 解耦，可直接离线单测）。"""

    def __init__(self, settings=None, router=None, extractor=None, ocr=None, reporter=None) -> None:
        """全部依赖可注入（默认按工厂构造）；`reporter` 为 `None` 时不报进度。"""

    def run(self, source_path: Path, contract_id: str) -> ParseOutcome:
        """跑完整条流水线（**任何异常都在此处收敛为 FAILED，不向外抛**）。"""


def build_parse_pipeline(settings=None, reporter=None) -> ParsePipeline:
    """工厂：返回本机实现。"""


def resolve_source(file_key: str, local_path: str | None = None) -> Path:
    """定位源文件（**三条途径，顺序固定**）。

    1. `local_path` 指定且存在 → 直接用；
    2. `file_key` 本身是存在的本地路径 → 直接用；
    3. 否则经 `get_minio_client().fget_object(bucket, file_key, tmpdir)` 下载。

    Args:
        file_key: MinIO 对象键**或**本地路径。
        local_path: 显式本地路径（联调/测试用，优先级最高）。

    Returns:
        可读的本地文件路径（MinIO 下载落 `.tmp_t/parse/{uuid}`）。

    Raises:
        SourceUnavailableError: 三条途径都失败（**不猜桶名、不猜路径**）。
    """


def write_parse_artifact(outcome: ParseOutcome, directory: Path | None = None) -> Path | None:
    """把 `to_payload()` 写成 `data/parse/{contractId}.json`（**原子写**：先写 `.tmp` 再 replace）。

    Returns:
        写入路径；失败（磁盘/权限）时返回 `None` 并追加 warning —— **工件失败不影响任务状态**。
    """
```

## ⑥ 实现规范

1. 🔴 **源文件定位顺序固定**（`resolve_source`）：`local_path` → 本地路径 → MinIO。三条全失败 → `SourceUnavailableError` → `FAILED` + `reason="SOURCE_UNAVAILABLE"`；**不得**为凑活而猜路径或猜桶名。
2. 🔴 **全文拼接只能发生在 `assemble_text_lines()`**：四条支路都调它；任务体与 `clause_payloads()` **禁止**二次拼接字符串（否则偏移与 3-5 的索引必然错位）。分隔符 `"\n"`、空行跳过 —— 这两条也是唯一处。
3. 🔴 **坐标零例外**：本任务**不做任何缩放**。PDF 原生坐标已是 PDF_POINTS；OCR 坐标由 3-3 归一；DOCX 无真值（走 §5.6 的降级）。源码里**不得**出现 `72 /`、`src_dpi=` 等换算字面量（§⑦ 断言 5 会抓）。
4. 🔴 **行切分只用库能力**：PDF 原生用 `extract_text_lines()`；OCR 结果**逐条成行**，只按 `(page, y, x)` 排序，**不做**二次合并或自定义聚类（那是 3-7 的职责）。
5. 🔴 **要素统一从装配后的全文抽取**：一律调 `elements_from_text(full_text)`，**不调** `extract_elements(source_path)` —— 后者会再读一次文件、再走一遍行构建，形成第二条解析路径（四路结果不一致时无法排查）。（实修口径见 `3-4 §5.3`：甲方 / 乙方**限定前 2 页** —— 先按 `TextLine.page <= PARTY_PAGES` 过滤行、**用同一个 `assemble_text_lines()`** 装配一次，再把该文本传给 `elements_from_text()`；其余要素用全文。**不要**为此另写装配逻辑，也不要为此改调 `extract_elements(source_path)`）。要素 `bbox`：用 `full_text.find(value)`（`value` 非空且长度 ≥ 2）定位 → `locate()` 并集框；未命中 → `None`。
6. 🔴 **条款 bbox 的定位与自校验**：按 3-4 §5.4 的「本编号行起、下一个编号行前一行止」复扫行序列得到行区间 → 与 `clauses_from_lines()` 的结果**逐条对齐**。若条数不一致或 `label` 不匹配 → 该条款 `bbox=None`、`page_no=None` + 一条 warning（**不得**猜测对齐关系）。
7. 🔴 **状态判定表（唯一处）**：凡命中 `DEGRADED` 原因即降级，`FAILED` 优先于 `DEGRADED`。

| 情况 | status | 必进 `warnings` |
|---|---|---|
| 源文件不可得 / 格式不支持（`UnsupportedFormatError`）/ 渲染失败 / 抽取抛异常 | `FAILED` | 是（含异常类型） |
| 走 OCR 但引擎不可用（`OcrEngineUnavailableError`） | `DEGRADED` | 是（`engine_name="none"`、`ocrUsed=True`） |
| 印章模块未落盘（`ocr/seal.py` 不存在） | `DEGRADED` | 是（**只记一条**，不逐页刷屏） |
| 版面模块未落盘（`layout/analyzer.py` 不存在） | `DEGRADED` | 是（**只记一条**） |
| DOCX 路径（无真值坐标） | `DEGRADED` | 是（`coordinatesSynthetic=True`） |
| 页数超 `MAX_OCR_PAGES`（默认 50）被截断 | `DEGRADED` | 是（写明截断到第几页） |
| 条款行区间与 AST 条数不一致 | `DEGRADED` | 是 |
| 其余（含：印章未检出但模块可用） | `SUCCESS` | — |

8. 🔴 **不抛异常给 broker**：`ParsePipeline.run()` 内部 `try/except` 收敛；`FAILED` 也要有完整 `stageLog`（哪个阶段炸的、耗时多少）。
9. ⚠️ **软依赖模块缺失只警告一次**：`ocr/seal.py`（3-8）与 `layout/analyzer.py`（3-7）缺失时，用模块级一次性标记（`_SEAL_IMPORT_WARNED` / `_LAYOUT_IMPORT_WARNED`），避免 30 页合同产生 30 条相同的 warning。
10. ⚠️ **超时与页数护城河**：常量 `MAX_OCR_PAGES = 50`（扫描件逐页 OCR 的成本上限）；`OcrSettings.timeout_s` 由 3-3 内部消费，本任务**不再包一层超时**。
11. ⚠️ **`worker/progress.py` 只增不改**：本任务新增 parse 三件套；**不得**改动 `AuditProgressReporter` 与审核阶段表（若发现必须共用一段代码，先提出来，不要顺手重构别人的落点）。
12. ⚠️ **工件写盘**：`data/parse/{contractId}.json`，UTF-8 无 BOM、`ensure_ascii=False`、先写 `.tmp` 再 `replace()`（防半截文件）；工件只做**调试/联调**用途，**不是**正式持久化。
13. ⚠️ **打点**：命名空间 `get_logger("worker.parse")`；`log_event("parse.start" / "parse.route" / "parse.ocr" / "parse.extract" / "parse.done" / "parse.degrade" / "parse.fail")`，全部带 `trace_id` 与 `contract_id`。
