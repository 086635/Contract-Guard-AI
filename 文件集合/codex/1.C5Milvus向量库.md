## ⑤ 接口规格

```python
# rag_core/adapters/milvus_store.py
class MilvusVectorStore:
    """Milvus 备选向量库（`VectorStorePort` 实现）。

    设计要点：
    1. **延迟导入**：`pymilvus` 只在方法内 import —— 未安装时默认路径完全不受影响；
    2. **默认值红线**：本类**不得**出现在任何默认分支里（默认仍是 `inmemory`）；
    3. 集合 schema / 索引 / 一致性级别以 `1-2 §⑤` 为准（本卡不重复字段定义）。
    """

    def __init__(self, *, mode: str = "server", uri: str = "", token: str = "",
                 db_name: str = "default", collection: str = "contract_clauses",
                 timeout_s: float = 5.0) -> None: ...
    # 以及 VectorStorePort 的全部方法
```
**协议自证**：`isinstance(store, VectorStorePort)`（`runtime_checkable`，只校验方法名存在）。

> ⚠️ **落地纠偏（2026-09-22，实测）**：本节的 `uri: str = ""` 默认值改为
> `uri: str = "http://localhost:19530"`，与 `1-2 §⑥` 骨架及 `1-3 §⑤` 的 `milvus_uri`
> 默认值一致（空串会构造必败）。另：`timeout_s` **必须真的透传**给 `MilvusClient(timeout=…)`

> `StoreUnavailableError`。详见 `1-2 §⑪`。

## ⑥ 实现规范

1. 🔴 **延迟导入**：`import pymilvus` 只允许出现在方法体内；模块顶层**不得**出现（否则缺包会连带 `import rag_core` 崩）。
2. 🔴 **不得成为默认**：本卡不得改 `RagSettings.vector_store` 默认值，也不得改 `factory` 的分支顺序。
3. 🔴 **payload 往返一致**：写入用 `chunk.to_payload()`、检索用 `ContractChunk.from_payload()`（**与 Qdrant 分支同口径**）。
4. 🔴 **过滤语义对齐**：`RetrievalFilters` 的字段 → Milvus 标量过滤表达式；**语义必须与 Qdrant 分支一致**（否则双跑对不上）。
5. ⚠️ **集成用例必须 skip-able**：`CG_RAG_TEST_MILVUS_URI` 未设置 → skip（**不得 fail / error**）。
6. ⚠️ **重合度门禁**：集成用例断言 `|Top10(InMemory) ∩ Top10(Milvus)| / 10 ≥ 0.8`；低于阈值要打印差异 id 便于排查。
7. ⚠️ **打点**：`log_event("store.upsert.done"/"store.search.done", backend="milvus", count=…, latency_ms=…)`。

### 实测后回填 · 追加（**pymilvus 3.0.0 上实测到的 4 处版本差异**，均已按 `1-2 §⑦` 的处置原则落到代码）

| # | 项 | 实测结果（2026-09-22） | 代码处置 |
|---|---|---|---|
| 1 | `metric_type=COSINE` 时 `distance` 的含义 | 🔴 **是余弦距离 `1 - cos`（越小越相似）**，不是相似度：同向量自检索 `0.0`、正交 `1.0`、反向 `2.0`，结果按该值**升序**返回。与 `1-2 §⑤` 的预期**相反** | `_score_from_distance()` 反向映射为相似度（契约 `VectorHit.score` = 越大越相似），与 Qdrant / InMemory 同口径；守卫用例 `test_score_from_distance_is_similarity` |
| 2 | `add_index(index_type="INVERTED")` 是否被支持 | 🔴 **不支持**：translator 强制要求每个索引都给 `metric_type`，engine 又只接受向量字段（`create_index only supports vector fields`）→ 带标量索引的 `create_collection` **整体失败** | 按 `1-2 §⑦-5`「不支持则去掉该循环」→ **不建标量索引**（expr 过滤仍正确，仅失去过滤加速）；守卫用例 `test_ensure_collection_builds_schema_without_scalar_indexes` |
| 3 | `client.delete()` 的返回结构 | `list[str]`（服务端返回主键时）**或** `{"delete_count": N, "cost": …}`（零值被 `OmitZeroDict` 省略）；**都不是**单一 dict | `delete_by_doc()` 三分支兼容（dict / list-tuple / 带属性对象），取不到计数返回 0 |
| 4 | `client.search()` 命中的主键键名 | 键名是**主键字段名** `chunk_id`（`search_result.py:151` 用 `pk_name`），**不是** `id` | 新增唯一处常量 `_PK_FIELD = "chunk_id"`，写入 schema 与读取命中共用 |
| 5 | 集合 load 时机 | 新建后 `search` 正常；但**跨进程/重启**后集合处于 `released`，`search` 报 `code=101 Collection ... is in state 'released'` | `ensure_collection()` 的「已存在」分支补 `load_collection()`（`load` 幂等，实测连调 2 次均 OK）；守卫用例 `test_ensure_collection_loads_existing_collection` |
| 6 | VARCHAR 主键 `max_length` | uuid5 = 36 字符，用 64 安全（实测可写入）；`_MAX_LEN` 已按 `ContractChunk` 的 `max_length` 逐字段核对（`doc_id` 200 / `law_code` 64 / `category` 64 等） | 守卫用例 `test_max_len_covers_contract_limits`（列宽 < 契约上限会写入被拒） |
| 7 | `count()` 的实现口径 | 🔴 **2026-09-23 真 server v2.5.4 实测**：`get_collection_stats()["row_count"]` 是**物理行数** —— ①含**逻辑删除**的行（写 3 删 3 `flush()` 后仍返回 **3**）；②未 `flush()` 前恒为 **0**。**milvus-lite 3.0 上测不出这两点** | 改用 `count(*)` 聚合 + `consistency_level="Strong"`：真机实测 `0 → 3 → 3（幂等）→ 0`，**无需 flush**。详见 `1-2 §⑪.6`；这同时是 `0-C3`（T-A4）断言 2 / 断言 6 在真 server 上能过的前提 |
