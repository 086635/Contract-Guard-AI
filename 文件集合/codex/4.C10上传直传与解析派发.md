## ⑤ 接口规格

```python
class ContractService:
    async def presign_upload(self, body: PresignRequest) -> PresignData: ...
    async def upload(self, body: UploadBody) -> TaskProgress: ...
```

流程要求：

```text
presign:
  校验 file_name/file_type → 生成 file_key → object_storage.presign_put(600)

upload:
  ContractRepository.create(status=PARSING)
  → TaskRepository.create(task_type="PARSE_DOC")
  → TaskDispatcherPort.send("parse_doc", args=(file_key, contract_id))
  → TaskProgress(task_id, stage="queued", percent=0.0, status=RUNNING)
```

## ⑥ 实现规范

1. `file_key` 必须去除路径穿越和不可控字符，禁止直接拼接客户端路径。
2. 文件类型继续引用 OpenAPI `FileType`，不支持类型返回 415。
3. DB 写入和任务派发需按事务/补偿语义明确：任务派发失败不能留下无任务合同。
4. Celery task 名固定为 `parse_doc`，由 C9 的任务网关发送，不 import worker。
5. `TaskProgress.status` 没有 PENDING；入队状态使用 `RUNNING + percent=0.0`。

## ⑦ 验收标准

| # | 断言 |
|---|---|
| 1 | presign 返回非空 URL、稳定 fileKey、expiresIn=600 |
| 2 | upload 在 DB 创建合同和任务行 |
| 3 | task dispatcher 收到 `parse_doc` 与相同 contract_id/file_key |
| 4 | 任务派发失败时合同状态不会停在无法追踪的状态 |
| 5 | 不支持/危险文件名返回 4xx，不产生对象键 |
