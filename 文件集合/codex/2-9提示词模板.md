```text

                 conflict → "conflict"    extract → "extract"(可选)
                 standard_compare / report_draft → 不调 LLM（无模板）

```

### 模板正文必须包含的**四段结构**（硬性）

```text
1) 角色    —— 「你是企业合同风险审核专家……」等一句角色设定
2) 任务    —— 输入是什么、要判什么、判定尺度（含 `{{tolerance}}` 的用法说明）
3) 输出    —— 「严格输出 JSON」+ **字段名清单**（不写类型细节、不抄 schema 全文）
4) 约束    —— 至少包含以下三条中的相关项：
     · 不得编造法条；无依据时必须标注【缺失标准对照】
     · 溯源引用只能来自 `{{rag_context}}`，不得虚构来源
     · 判定必须给出可核对的依据片段（推理链每一步要有原文证据）
```

## ⑥ 实现规范

1. 🔴 **文件编码 UTF-8 无 BOM、换行 LF**：Windows 下手写极易引入 CRLF；写入时显式 `newline="\n"`（本仓已多次踩编码坑，标准 §8 坑表）。
2. 🔴 **占位符只允许 `{{snake_case}}`**：与 `loader._PLACEHOLDER` 的正则 `\{\{(\w+)\}\}` 完全一致；禁止 `{{ 空格 }}`、禁止全角括号。
3. 🔴 **模板名 == 文件名 stem**：`PromptLibrary` 以 `path.stem` 作键，改名即等于改键（映射表会失配）。
4. 🔴 **禁止写死的具体内容**：不得出现具体法条编号（如"第五百八十五条"）、模型名（`gpt-`）、供应商名、甲方/乙方真实名称。**写死 = 引导幻觉**。
5. 🔴 **禁止抄 JSON Schema 全文**：只写字段名清单。真值由 `invoke_structured(schema)` 在运行时强制（`2-2`）。
6. 🔴 **空召回措辞必须与契约一致**：模板中出现「【缺失标准对照】」字样，与 `EMPTY_CONTEXT_HINT` 的措辞对齐（**只对齐关键词，不复制整句**）。
7. ⚠️ **渲染是严格模式**：`render` 缺键会 `KeyError`（既有行为）。调用方必须传齐占位符——**空值传空串**，不要漏键。
8. ⚠️ 模板文件**不加**版本头 / 注释行（会进 Prompt 正文）；版本记录在本文件的「实测后回填」表。
9. ⚠️ 模板总长建议 ≤ 1200 字符：过长会挤占 `max_context_tokens`（默认 3000）预算。

## ⑨ 避坑清单

| # | 坑 | 说明 |
|---|---|---|
| 1 | 把 JSON Schema 全文抄进模板 | 代码改字段后模板不更新 → "模型输出对、解析失败"的幽灵问题 |
| 2 | 模板里写死法条编号举例 | 会被模型当成"必须引用这一条"，直接制造幻觉 |
| 3 | 用 Jinja2 语法 `{% for %}` | `PromptLibrary` 只认 `{{key}}`，会原样输出给模型 |
| 4 | 在节点里留一份"兜底 Prompt" | 违反唯一处原则；`2-4 §⑥` 已约定缺模板 → `SKIPPED` |
| 5 | 文件名与 `PROMPT_NAMES` 不一致 | `get(name)` 直接 `KeyError`，且错误信息不含路径，排查困难 |
| 6 | Windows 编辑器存成 CRLF / 带 BOM | Prompt 正文会混入 `\r`，影响模型输出稳定性；断言 5 会抓 |
| 7 | 渲染时漏传占位符 | `render` 严格模式直接 `KeyError`；空值要传空串 |
| 8 | 模板过长 | 挤占 3000 token 上下文预算，RAG 证据反而进不去 |
| 9 | 认为"P1 先跳过" | 跳过它 → 风险/冲突/改写三个阶段全部 `SKIPPED`，图能跑但**没有产出**，演示时等于没做 |
