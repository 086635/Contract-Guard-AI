## ② 范围

### ✅ 做
1. `detect_document_type` 增补 PNG / JPEG / TIFF 魔数。
2. `_ALLOWED_EXTENSIONS` 为 `FileType.image` 放行 `.png/.jpg/.jpeg/.tif/.tiff`。
3. 首跳任务沿用 `SCAN_UPLOAD → PARSE_DOC`；解析走 `RouteKind.IMAGE` → OCR。
4. `initial_preview_status` 对图片返回 `DONE`，预览对象=原图。
5. 前端上传 `accept` 放行图片扩展名。

### ❌ 不做
- 不做图片专用新页面；不做多页 TIFF 的复杂分页（按单页处理并记录警告）。

```text
detect_document_type(b"\x89PNG\r\n\x1a\n...") -> "IMAGE"
detect_document_type(b"\xff\xd8\xff...")         -> "IMAGE"
_FILE_TYPE -> expected 映射新增 IMAGE -> "IMAGE"
initial_preview_status("contract.png") -> PreviewStatus.done（preview_object_key = 原图 storage_path）
```

## ⑥ 实现规范

1. 魔数优先、扩展名只做自洽校验（沿用 §0.6 / C57 既定原则）。
2. 图片不参与 `_pdf_is_closed` / DOCX 结构校验分支。
3. 预览对图片**不再返回 `ERR_UNSUPPORTED_PREVIEW_SOURCE`**，避免把合法输入判成失败。
4. OCR 坐标沿用现有归一与写库路径，不新增第二套坐标换算。

## ⑦ 验收标准

| # | 断言 |
|---|---|
| 1 | PNG/JPEG 魔数被识别为 `IMAGE`；伪造扩展名的非图片被拒 |
| 2 | `.png` 上传通过准入；`.pdf` 伪装成 `.png` 被拒 |
| 3 | 图片解析走 OCR，`contract_elements` 出现该合同的带坐标切片 |
| 4 | `initial_preview_status("x.png")` 为 `DONE` 且 `preview_object_key == storage_path` |
