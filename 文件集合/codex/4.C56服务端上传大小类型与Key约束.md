## ② 范围

### ✅ 做

- PresignRequest 兼容新增 sizeBytes/contentType。
- 正式环境强制校验大小、类型和扩展名，文件 key 只能服务端生成。
- upload 阶段 stat_object 复核 size/ETag/bucket/prefix。
- 前端提交大小/类型，但只作提示，不承担安全。

### ❌ 不做

- 不信任客户端 Content-Type/文件名。
- 不新增第二套上传路由。
- 不在前端决定 bucket/key。

## ⑤ 接口规格

```text

```

## ⑥ 实现规范

1. 最大值统一为现有 50 MB 常量。
2. key 前缀固定 contracts/{yyyy}/{mm}/uuid-name。
3. 错误使用 ERR_UNSUPPORTED_FILE_TYPE/ERR_FILE_TOO_LARGE。
4. 对象不在 bucket/prefix 内直接拒绝。

### 实测后回填·断言逐条

| # | 断言 | 实测结果 |
|---|---|---|
| 1 | 超限拒绝 | 通过：`test_size_limit_server_side`（`sizeBytes > 50 MB` → `UploadObjectError(413)`，且**不签发** presigned URL） |
| 2 | 任意 key 拒绝 | 通过：`test_arbitrary_key_rejected`（`../reports/...` → 400，且**不访问**对象存储）+ `test_validate_upload_object_rejects_foreign_prefix` |
| 3 | stat size 不一致拒绝 | 通过：`test_stat_size_mismatch_rejected`（声明 1024 / stat 50 MB → 409）；ETag 分支 `test_etag_mismatch` → 409 |
| 4 | 前端仍在提交前提示错误 | 通过：`UploadPanel.chooseFile` 仍拦 `>50 MB` 与非 `pdf|docx`；`tsc --noEmit`（web-ui）退出码 0 |
