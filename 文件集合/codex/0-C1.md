## ⑤ 接口规格

```python
# rag_core/config.py（追加到「向量库」分组末尾）
class RagSettings(BaseSettings):
    milvus_mode: Literal["server", "lite"] = Field(
        default="server",
        description="server=连服务（推荐，Windows 只能用它）；lite=本地文件（Linux/macOS）",
    )
    milvus_uri: str = Field(
        default="http://localhost:19530",
        description="server 模式为服务地址；lite 模式为本地 .db 文件路径",
    )
    milvus_token: str = Field(default="", description="认证串 user:password 或 API Key；为空表示无认证")
    milvus_db_name: str = Field(default="default", description="Milvus 数据库名")
    milvus_timeout_s: float = Field(default=5.0, ge=0.1, description="Milvus 请求超时（秒）")

    vector_store: Literal["inmemory", "qdrant", "milvus"] = Field(
        default="inmemory",
        description="向量库实现。inmemory=零依赖（默认/单测）；qdrant/milvus=真实向量库",
    )
```

# rag_core/factory.py（在 qdrant 分支之后追加）

## ⑥ 实现规范

1. 🔴 **保留 `"inmemory"` 与 `"qdrant"` 两个既有取值**，默认仍 `inmemory`（删任一值都会破坏离线默认可跑与回退路径）。
2. 🔴 `milvus` 分支必须**函数内延迟导入**，与 qdrant 分支风格一致。
3. 🔴 **复用 `settings.collection`**，不得新增独立 collection 配置项（否则与 Qdrant 双跑无法对比，见 `1-3 §⑪-7`）。
4. 🔴 **裁决（`0.§0.11.2` 规则 3）**：`adapters/__init__.py` **不再改**。T-A1 已用 PEP 562 懒导出（`__all__` 含 `MilvusVectorStore` + `__getattr__` 延迟 import）；`1-3 §⑥` 的“顶层 import 是安全的”写法被 T-A1 实测推翻（缺 `pymilvus` 时会把整个 adapters 出口绑死）。`1-3 §⑥` 的导出片段作废，本卡 §⑦ 断言 6 改为“核销已存在的懒导出”。
5. `milvus_timeout_s` 必须**真实透传**给 `MilvusVectorStore(timeout=…)`（`MilvusClient` 构造即建连，不传会让该配置成为死配置，见 `1-2 §⑪.2-#1`）。

### ⑩.1 §⑦-1 的写法**不可执行**（已改判为两条替身）

原文断言 1 写的是「`type(build_vector_store(s)) is MilvusVectorStore`（**不建连**）」。
实测：`MilvusVectorStore.__init__` **构造即建连**（`MilvusClient(...)` 直接握手，见 `1-2 §⑪.3-#3`），
本机无 Milvus 服务时该调用必然抛 `StoreUnavailableError` —— 所以"验类型"这条**不能**用真实分支做。

**改判为两条互为补充的离线用例**（都已落地，见 §⑩.3）：

1. `test_build_vector_store_milvus`：注入**假 `pymilvus`**（`conftest.py::fake_pymilvus`）→ 断言类型 +
   `isinstance(store, VectorStorePort)`，同时核销 §⑧-1「三分支各一条」；
2. `test_milvus_branch_raises_store_unavailable_without_server`：**不注入假 SDK、无服务**时，
   milvus 分支必须抛 `StoreUnavailableError`（若抛 `ValueError` 就说明分支**根本没接上**）——
   这条才是"接线真的存在"的证明；已配置真实服务（`CG_RAG_TEST_MILVUS_URI`）时 skip。
   实测耗时 ≈ 8.9 s（含 `pymilvus` 真实 import + 一次连接失败），是本卡用例里最慢的一条（已知、可接受）。

### ⑩.5 追加纠偏（2026-09-23，**由 T-A3 起服务触发**）：§⑩.1 的第 2 条替身不再成立

**现象**：`0-C2`（T-A3）按本仓 compose 真的把 Milvus 起在 `19530` 上之后，全量门禁出现
**1 failed**：`test_milvus_branch_raises_store_unavailable_without_server` →
`Failed: DID NOT RAISE StoreUnavailableError`。

**根因**：该用例（§⑩.1 第 2 条）用 `_settings(vector_store="milvus")`，即**沿用配置默认
`milvus_uri=http://localhost:19530`**，断言"无人监听 → 抛 `StoreUnavailableError`"。
这条断言把**宿主机环境**当成了前提：此前 `19530` 无人监听故成立，而 T-A3 的交付物正是让
`19530` 上有服务 —— 于是「Milvus 起没起」直接决定本用例红绿。原有的
`CG_RAG_TEST_MILVUS_URI` skip 守卫也救不了：T-A3 **不设**该 env（它是集成测试的开关）。

**处置（改判，`0.§0.11.2` 规则 3）**：把被测 URI 从"默认值"改为 `_closed_port_uri()`
—— 向 OS 借一个端口后**立即释放**，得到一个**确定无人监听**的端点（新增模块级 helper
`_closed_port_uri()`，`import socket`）。同时**删掉 skip 守卫**：断言既然与环境无关，
就没有再跳过的理由（覆盖面只增不减）。

> ⚠️ 这不是"放宽断言"：`pytest.raises(StoreUnavailableError)` 一字未动，改的是**输入**
> （默认值 → 构造的关闭端点），使断言从"依赖宿主恰好没起服务"变成"与宿主无关、恒成立"。

**实测**：`pytest packages/rag-core/tests/test_config_factory.py` → **17 passed**（耗时 9.5 s，
其中本条 6.76 s，含 `pymilvus` 真实 import + 一次连接失败）；连跑两次皆绿（与 Milvus 是否在
`19530` 运行无关）。ruff check / format 该文件零新增。
