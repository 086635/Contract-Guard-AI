## 1. 任务目标

把 T-D7-8 的「备份恢复」从一句要求落成**可执行、可验证、默认安全**的运维资产：

1. PostgreSQL 每日 `pg_dump`、MinIO 每日镜像；
2. 保留数量 / 目录 / 时间戳可配置，dry-run 可预演；
3. 恢复演练校验「备份可读 → alembic head 一致 → 对象数量与逐条清单一致」；
4. 失败退出码与日志写入运维输出；脚本内不硬编码任何 secret。

## 2. 实现说明

### 2.1 `scripts/backup_postgres.sh`（新建）

- CLI：`--dsn` / `--out` / `--retain` / `--dry-run` / `--help`；对应 `CG_BACKUP_PG_DSN` / `CG_BACKUP_OUT` / `CG_BACKUP_RETAIN`，另支持 `CG_BACKUP_TIMESTAMP`（回放/测试）与 `CG_PG_DUMP_BIN` / `CG_PG_RESTORE_BIN` / `CG_PSQL_BIN` 覆盖可执行文件。
- 产出（`<out>/`，命名族严格受保留策略约束）：
  - `postgres_<db>_<YYYYMMDDThhmmssZ>.dump`（`pg_dump --format=custom --no-owner --no-privileges`）
  - `...meta`（sha256 / size / alembic 版本，**不含 DSN**）
  - `...sha256`、`...log`（含 `exit_code`）
- 校验：dump 非空 + `pg_restore --list` 可读，之后才写 meta/sha256。
- 保留：`--retain N` 只保留最近 N 份 `postgres_<db>_*.dump`，同族 `.meta/.sha256/.log` 一并删除；`N=0`（缺省）**不清理**。
- 失败：dump 退出码原样记入日志并返回 4（`exit_code=7` 的用例即此路径），半成品 dump 被删除，不留下「看起来像备份」的坏文件。

### 2.2 `scripts/backup_minio.sh`（新建）

- CLI：`--alias` / `--bucket` / `--out` / `--retain` / `--dry-run` / `--help`；对应 `CG_BACKUP_MINIO_ALIAS` / `CG_BACKUP_MINIO_BUCKET` / `CG_BACKUP_OUT` / `CG_BACKUP_RETAIN`，`CG_MINIO_MC_BIN` 覆盖 `mc`。
- **凭据红线**：脚本只接受已配置的 mc alias 名，不接收也不打印 access/secret key；临时凭据由部署方用 `MC_HOST_<alias>` 注入。
- 产出 `<out>/minio_<alias>_<bucket>_<UTC>/`：
  - `objects/`：镜像出的对象树（恢复演练直接 mirror 回 bucket，**元数据不混进对象树**）
  - `objects.tsv`：`<size>\t<key>` 全量清单，恢复后逐条比对
  - `manifest.txt`：来源与 `object_count`（无凭据）
  - `backup.log`：`exit_code`
- 校验：mirror 成功后比较 `mc ls --recursive --json` 源行数与 `objects/` 实际文件数，不一致即 5。
- 保留：只删 `<out>/` 下名字严格匹配 `minio_<alias>_<bucket>_<UTC>` 的**直接子目录**，未知目录一律不动。

### 2.3 `scripts/restore_drill.sh`（新建）

- CLI：`--pg-backup`（文件或目录，目录取最新 dump）/ `--minio-backup` / `--target-dsn` / `--target-alias` / `--target-bucket` / `--report` / `--execute` / `--dry-run`。
- **默认 dry-run**：只打印 4 步计划与目标（DSN 脱敏），不调用 `pg_restore/psql/mc`、不写报告、不碰目标；`--execute` 才真正恢复。
- `--execute` 校验链：
  1. `sha256` 与 `.meta` 一致（存在 meta 时）→ 2. `pg_restore --list` 可读 → 3. 目标 PG 可达 →
  4. `pg_restore --clean --if-exists --exit-on-error --no-owner --no-privileges` →
  5. 恢复后 `alembic_version` 与备份 meta 一致 →
  6. `mc mirror` 备份 `objects/` 回目标 bucket，再把目标 `mc ls --recursive --json` 解析清单与 `objects.tsv` **逐条比对**（不是只比数量）。
- 通过后在 `--report`（默认与 PG 备份同目录）写 `restore_drill_<ts>.log`，含 expected/restored alembic、object_count、`exit_code=0`。

### 2.4 `scripts/tests/test_backup_args.py` + `pytest.ini`（新建 / 修改）

- 用临时目录里的伪 `pg_dump/pg_restore/psql/mc` 覆盖可执行文件做**离线**断言，不依赖真实服务、不需要外部环境变量：
  - `test_backup_args`（三个脚本的 `--help` 与必填/非法参数退出码）
  - `test_restore_drill_dry_run`（dry-run 零副作用）
  - `test_backup_no_secret_in_output`（URL 与 key=value 两种口令全抹除）
  - `test_retention_only_target_dir`（只动目标命名族 + 兄弟目录/未知文件不动）
  - `test_backup_restore_dry_run`（父文档 `4-7 §⑧.1` 列出的同名字用例）
  - 另有备份产物可校验、失败退出码、MinIO 镜像清单、恢复执行、alembic 不一致、`--execute` 必填目标等 6 条

## 7. 边界与后续

### 边界声明

- **不自动删除未知目录**：保留策略只匹配本卡命名族，且只作用于 `--out` 的直接子项（§⑨-1）；
- **不把备份逻辑放进 worker 业务代码**：全部落在 `scripts/`，与 `apps/async-worker` 无 import 关系；
- **不在脚本里硬编码 secret**：MinIO 只认 mc alias / `MC_HOST_<alias>`，PG 口令只走 DSN 且任何输出都过 `redact`；
- **恢复不自动执行**：默认 dry-run，`--execute` 是显式动作（§⑥.3）；
- **不新增第二套备份机制**：PostgreSQL 用 `pg_dump/pg_restore`、对象存储用 `mc mirror`（§③ 适配性三问）。

### 两处需知晓的决策

1. **备份元数据放对象树之外**（`minio_*/objects/` 与 `objects.tsv`/`manifest.txt` 同级）：
   否则恢复演练 `mc mirror` 回 bucket 时会把 `objects.tsv` 之类当成业务对象传上去。
2. **卡首行落点与 §④ 交付物表不一致**：按 SOP「命名以文档为准」采用 §④ 的
   `scripts/backup_postgres.sh` / `backup_minio.sh` / `restore_drill.sh` 平铺命名，
   未创建 `scripts/backup/`、`scripts/restore/` 目录（避免与 §④ 及 §⑤ CLI 命名冲突），已在卡片回填区显式记录。
