## 2. 实现内容

### 2.1 冲突候选粗筛

[build_conflict_candidates()](E:/important_project/Serve_bage/packages/ai-engine/ai_engine/graphs/nodes.py:637)

关键词组：

```text
付款 / 支付 / 价款 / 结算 / 发票
违约 / 赔偿 / 责任 / 免责 / 不可抗力
期限 / 有效期 / 提前 / 终止 / 续约
```

算法：

1. 按组筛选含有相关关键词的条款。
2. 只对同组条款生成 `i < j` 候选。
3. 用索引对去重，消除多关键词重复命中。
4. 按 `(条款跨度, 左索引, 右索引)` 稳定排序。
5. 截断到 `max_conflict_pairs`。

### 2.2 冲突批量精判

[_ConflictDraft / _ConflictBatch](E:/important_project/Serve_bage/packages/ai-engine/ai_engine/graphs/nodes.py:71)

模型只允许输出：

```text
pair_index
conflict_type
description
level
suggestion
```

代码负责：

```text
id
sourceClauseId
targetClauseId
citations = []
```

`pair_index` 会做重复与越界检查；非法项只记 warning，不污染结果。

### 2.3 冲突失败隔离

| 情况 | 行为 |
|---|---|
| 无条款 | `SKIPPED`，零 LLM |
| 候选为 0 | `OK`，零 LLM |
| 缺模板 | `SKIPPED` |
| 单批 LLM 失败 | 跳过该批，其他批继续，最终 `DEGRADED` |
| pair_index 越界 / 重复 | 丢弃该项并 warning |

### 2.4 标准比对

[standard_compare_node()](E:/important_project/Serve_bage/packages/ai-engine/ai_engine/graphs/nodes.py:823)

每个条款调用一次 C9：

```text
RagTool(
    query=条款正文,
    source_types=[STANDARD_CLAUSE, LAW_ARTICLE],
    top_k=3,
    reason="standard_compare",
)
```

状态判定：

| Tool status | 行为 |
|---|---|
| `EMPTY` | 生成一条 MissingClause，status 仍为 `OK` |
| `OK` + citations | 已存在标准对照 |
| `DEGRADED` / 无 citations | 降级，不判定缺失 |
| 抛异常 | 降级，不判定缺失 |
| Tool 为 None | 降级 `missing=[]` |

MissingClause 字段固定为 OpenAPI camelCase：

```text
id
standardClauseId
title
reason
suggestion
canAutoFill
```

## 4. 质量评测

### 4.1 性能红线

| 指标 | 实测 |
|---|---:|
| 100 条款同组候选 | 50 |
| 原全量对数 | 4950 |
| 50 对 batch_size=10 | 5 次 LLM |
| 100 条款精判调用 | 5 次 |

结论：

- 候选生成允许做规则两两筛查，但 LLM 精判严格受 `max_conflict_pairs` 和批大小约束。
- 消除了 100 条款全对 4950 次调用的风险。

### 4.2 静态与边界质量

| 维度 | 评价 | 说明 |
|---|---|---|
| 检索边界 | 通过 | 只调用 C9 `RagTool` |
| 契约边界 | 通过 | 复用 `CrossClauseConflict` 与 OpenAPI 字段 |
| 幻觉防护 | 通过 | id / clauseId 不由 LLM 生成 |
| 缺失语义 | 通过 | 仅 EMPTY 视为缺失 |
| 服务故障处理 | 通过 | 异常只降级，不伪造缺失 |
| 批次隔离 | 通过 | 单批失败不丢其他批 |
| 排序稳定性 | 通过 | span + 索引双键 |

### 4.3 当前限制

1. **矛盾召回 / 精准尚未评测**
   当前只验证流程、预算和恢复路径，不评价模型对矛盾的理解质量。

2. **关键词粗筛可能漏召回**
   未命中付款 / 责任 / 期限关键词的潜在矛盾不会进入 LLM 精判。

3. **缺失检测依赖模块 1 语料和阈值**
   `EMPTY` 的语义已经正确区分；但语料缺失和阈值配置仍会影响真实缺失率。

4. **C10 尚未接线**
   六阶段图已可跑，但还没有 worker 任务、进度上报和最终结果序列化。
