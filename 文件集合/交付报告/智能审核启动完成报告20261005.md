# 智能审核模型接线完成报告（2026-10-05）

任务：T-D6 用户追加维护。先完成开发文档，再修改并实测；本轮 20 个程序 / 测试文件，22 个既有文件差异另加新评分辅助文件与维护开发卡。未提交、推送 GitHub 或部署生产环境。

已将分类、要素提取、风险 / 矛盾审核及共用模型工厂的大模型调用接入 DeepSeek 云端。API、任务服务、数据库、队列、对象存储和前端本地服务已启动。OCR、向量化路径和印章极坐标展开继续在本机执行，相关源文件逐项哈希保持；原 React / Vite、FastAPI / Celery、六阶段审核图、契约、依赖锁与原健康分算法保持。

此前没有显示分数的原因：后端已经启动，运行配置却是 offline 测试模型，实际风险必需字段为空，审核 FAILED、healthScore 为空。后来真实本机模型已完成首轮审核，但用户考虑 8GB 显存明确选择云端 DeepSeek。本次使用 deepseek-flash 真实复审；本地 LLM 服务已停止，已下载权重和运行包留在原 tmp 目录供回滚。

当前合同复验：7 页、44 条款、151 行、4689 字，分类 PURCHASE；审核 DEGRADED，参考健康分 **20/100**，合规 0、履约 0、完整性 100。返回 44 条模型风险提示（HIGH 7 / MEDIUM 29 / LOW 8）与 50 条模型矛盾提示；它们属于待人工核对的模型结果，不代表已证实的法律风险。六阶段累计耗时约 267.1 秒。模型曾有 9 次工具空响应，均通过原 JSON 备用路径恢复，诊断保留；摘要优先显示实际的标准依据不足。

标准知识库没有召回可核对依据，不能据此判定“缺失 44 条标准”。现已修正为缺失项 0，并明确提示评分仅供参考。当前 embedding 配置仍是原本地 **hash** 默认路径，不是已经接通 BGE 的真实语义向量服务；本轮没有把 embedding、OCR 或极坐标迁到云端。后续完整标准审核需要配置本地语义向量服务与可核对标准资料，当前不能宣称完整自动审核已验收。

审核质量限制：原风险节点主要逐条审阅，实测会把独立的章节标题当作内容不足，跨条款约定也可能产生误报；矛盾提示同样尚未人工验证。以上 44 / 50 是本次模型返回数量，不能视为已确认的问题数；完整性维度 100 是原算法按当前缺失项 0 计算的数值，标准依据尚未核验。
