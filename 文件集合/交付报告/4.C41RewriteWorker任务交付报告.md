## 1. 任务目标

C41 解决的是 `/agent/rewrite` 从“网关只负责派发”到“异步 Worker 可以真实执行改写”的最后一跳：

```text
C15 / API Gateway
  -> send("rewrite", task_id=xRequestId)
  -> C41 worker.tasks.rewrite
  -> ai_engine.agents.rewriter.rewrite_clause()
  -> RewriteData camelCase JSON
  -> C36 前端 Diff 消费
```

本次没有新增公共 API，也没有重新实现 Agent 改写图、Prompt 或 RAG 检索；C41 仅新增 Celery 执行适配层，并保持既有契约与依赖方向不变。

## 3. 实现说明

### 3.1 Celery 任务入口

落点：`apps/async-worker/worker/tasks/rewrite.py`

核心流程：

1. 从请求中取 `xRequestId` 作为 trace ID；缺省时生成临时诊断 ID；
2. 用 `AgentRewriteRequest.model_validate()` 做契约校验；
3. 调用 `rewrite_clause(request)`；
4. 使用 camelCase alias 序列化真实 `RewriteData`；
5. 校验 `taskId` 与 `xRequestId` 一致；
6. 记录成功日志，返回 JSON 可序列化结果；
7. 捕获契约、模型和未知异常，统一进入失败路径。

任务声明保持：

```python
@celery_app.task(name="rewrite", bind=True)
def rewrite_task(self, payload: dict[str, Any]) -> dict[str, Any]:
    ...
```

### 3.2 成功结果

成功返回 `RewriteData` 的 JSON alias，包含：

- `taskId`
- `clauseId`
- `before`
- `after`
- `diff`
- `reasoningSteps`
- `citations`
- `updatedAt`

其中结果内容来自 `rewrite_clause()`，不经过 Worker 自行拼装或 Mock 伪造。

### 3.3 异常与可观测性

- `ValidationError` 明确作为非法任务输入抛出；
- `RewriteUnavailableError` 保留模型/Graph 不可用语义；
- 其他异常包装为 `RewriteUnavailableError`，由 Celery 标记为 FAILURE；
- 失败时记录 `rewrite.task.fail`，包含 trace ID 和错误表示；
- 成功时记录 `rewrite.task.done`，包含合同、条款和 trace ID；
- 失败不会返回半成品或假 Diff。

### 3.4 Worker 注册

`apps/async-worker/worker/main.py` 的 include 已增加：

```python
"worker.tasks.rewrite",
```

未改变 Celery broker、backend、serializer 或其他注册模块。
