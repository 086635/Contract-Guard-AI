## 1. 交付范围

本卡负责：

- 给 qdrant / minio 补健康检查，并让 api / worker 对 postgres / redis / qdrant / minio 全部按 `service_healthy` 启动。
- 新增一次性 `migrate` 服务（复用 api 镜像）执行 `alembic upgrade head`，api / worker 依赖其 `service_completed_successfully`。
- worker 环境变量补齐 RAG 检索层与 LLM 默认档。

本卡不负责：

- 修改 `Dockerfile.api` / `Dockerfile.worker` 业务逻辑。
- 纳入 `web` / `nginx`（属 T-D5）。
- Milvus 的默认化（保持可选 profile）。

### 背景（真实验证中暴露的两个既有问题）

1. **构建上下文错位**：compose 里 `context: .` 会被解析成 **compose 文件所在目录**（`docker/`），而 Dockerfile 需要仓库根（`COPY pyproject.toml/packages/apps`）——`docker compose build api` 必然失败。已修正为 `context: ..`。
2. **api-gateway 缺 async 依赖**：容器内 SQLAlchemy async 引擎需要 `greenlet`，但 `apps/api-gateway/pyproject.toml` 只声明了 `sqlalchemy>=2.0`（未带 `[asyncio]` extra）；`uv sync --package api-gateway` 的依赖闭包不含 greenlet，`migrate` 因此 `ImportError`。已改为 `sqlalchemy[asyncio]>=2.0` 并用仓库既定的 `uv sync --all-packages` 更新 `uv.lock`。

## 2. 实现内容

### 2.1 健康检查

| 服务 | 探针 | 依据 |
|---|---|---|
| postgres | `pg_isready -U cg`（沿用） | 既有 |
| redis | `redis-cli ping`（沿用） | 既有 |
| qdrant | `bash -c` 用 `/dev/tcp` 打 `/readyz` 取 200 | 镜像内无 curl/wget，只有 bash+grep（实测） |
| minio | `curl -f http://localhost:9000/minio/health/live` | 镜像内有 curl（实测） |
| api | `python -c` 打 `http://localhost:8000/health` | api 镜像自带 python（实测 200） |
| worker | `/app/.venv/bin/celery -A worker.main inspect ping --timeout 3` | venv 内有 celery（实测 pong） |

### 2.2 一次性 `migrate` 服务

```yaml
migrate:
  build: { context: .., dockerfile: docker/Dockerfile.api }
  environment: { CG_POSTGRES_DSN: postgresql+asyncpg://cg:cg@postgres:5432/cg }
  command: ["uv","run","--package","api-gateway","alembic","-c","apps/api-gateway/alembic.ini","upgrade","head"]
  depends_on: { postgres: { condition: service_healthy } }
  restart: "no"
```

### 2.3 worker 环境变量补齐

```yaml
CG_RAG_VECTOR_STORE: qdrant
CG_RAG_QDRANT_MODE: server
CG_RAG_QDRANT_URL: http://qdrant:6333
CG_LLM_PROVIDER: offline
```

（`CG_CELERY_BROKER` / `CG_CELERY_BACKEND` 沿用 redis `/1`、`/2`。）

## 5. 边界与已知事项

1. **越界声明**：为让 compose 全栈真正构建/启动，改动了 3 个**非 C24 落点**文件——`pyproject.toml`（workspace exclude）、`apps/api-gateway/pyproject.toml`（greenlet extra）、`uv.lock`（锁更新）。二者均为"既有缺陷 + 最小修复"，不新增契约字段。
2. **api/worker healthcheck 属追加项**：C24 卡 §② 只点名 qdrant/minio，但 §⑦-5 要求 api/worker 也 `healthy`；为使验收可判定，补齐了 api 与 worker 的 healthcheck（worker 的 Celery 结果后端就绪验证仍属 C25）。
3. **本机 5432 冲突**：compose 的 `postgres` 端口映射（`5432:5432`）与本机**原生 PostgreSQL 16 服务**冲突。真实验证时用临时 override（`ports: !reset []`，仅走 compose 内网）完成，验证后已删除，交付文件未改端口。
4. **不在 scope**：`web` / `nginx` 未纳入（其 `context` 仍为 `docker/`，属 T-D5）。
5. **Milvus**：保持可选，不成为默认值。
