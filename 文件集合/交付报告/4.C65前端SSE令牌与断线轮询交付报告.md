## 2. 实现说明

### 2.1 `services.ts`：把订阅状态机抽成可注入的纯逻辑

```text
parseTaskProgress(raw)                       # 进度事件解析（唯一处，含包络兼容）
TASK_POLL_INTERVAL_MS = 2000                 # 轮询兜底间隔
MAX_STREAM_ATTEMPTS   = 2                    # 首次 + 一次换 token 重连（禁止无限重连）
createTaskSubscription(taskId, onProgress, onError, deps) -> unsubscribe
taskApi.issueStreamToken(taskId)             # POST /tasks/{id}/stream-token
taskApi.subscribe(...)                       # 生产装配：httpClient + EventSource + setInterval
```

状态机：

```text
① POST stream-token（Bearer 走 httpClient）→ EventSource(`/tasks/{id}/stream?streamToken=...`)
② 流断开/令牌过期 → 关闭旧连接 → 重新取 token → 再连一次（attempts 封顶 2）
③ 再失败 → onError 提示 + 2 秒轮询 GET /tasks/{id}（立即先拉一次）
④ 终态（DONE/FAILED）或 unsubscribe() → 统一 finish：清 timer + 关连接
```

- **每次重连都换新 token**（⑥-1）：`connect()` 重新调用 `issueToken`，不复用旧令牌；
- **attempts 在 `connect()` 开头自增**：即使取 token 直接 403/404 也受上限约束（否则会无限重试）；
- **终结性错误**（`ERR_UNAUTHORIZED` / `ERR_FORBIDDEN` / `ERR_CONTRACT_NOT_FOUND`，由 C51 错误包络注入的
  `error.code`）→ **不重连、不轮询**，直接把安全 message 交给 UI（§②「不忽略 403/404」）；
- **token 只出现在 URL**：`encodeURIComponent(token)`；错误回调传的是原始 error（不含令牌），全程无日志。

## 7. 边界与后续

### 边界声明

- **不把 access token 拼 URL**：URL 里只有 60 秒 stream token（`encodeURIComponent`）；
- **不断线后无限重连**：`MAX_STREAM_ATTEMPTS = 2`，之后一律回退轮询；
- **不忽略 403/404**：终结性错误码直接终结订阅并把安全 message 交给 UI；
- **不新增第二套进度订阅**：仍是 `taskApi.subscribe` 一条路径（⑤ 的接口签名不变，仍返回同步 `unsubscribe`）。

### 三处需知晓的决策

1. **`onError` 类型由 `(event: Event)` 放宽为 `(error: unknown)`**：C64 之后错误可能来自
   `POST stream-token`（axios 错误）而非 EventSource，原类型无法表达该分支；三个调用点此前都没传
   第三个参数，因此**无破坏性**。
2. **`attempts` 在 `connect()` 开头自增**：否则 `issueToken` 持续失败（如 403）时 `attempts` 永不增长，
   会退化成无限重试；这是实现期发现的真实缺陷，已由 `test_terminal_error_stops_without_polling` 锁死。
3. **轮询失败不抛错**：网络抖动时保留轮询兜底（下一拍继续）；只有 **终结性错误码** 才终结订阅。
