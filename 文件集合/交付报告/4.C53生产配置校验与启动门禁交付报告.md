## 1. 任务目标

C53 建立生产环境配置拒绝矩阵与启动门禁：

```text
FastAPI lifespan 启动
  -> Settings.validate_production()
  -> 网关字段 / LlmSettings / RagSettings 逐项校验
  -> 任一危险默认值存在则抛 ProductionConfigError
  -> 不进入请求服务
```

目标是避免“测试/离线档被误当作生产部署档”，同时不破坏 development/test 的离线默认行为。

---

## 2. 实现说明

### 2.1 网关配置

落点：`apps/api-gateway/app/config.py`

- 新增：

```text
runtime_env: development | test | production = development
Settings.validate_production()->None
ProductionConfigError(field, reason)
```

- 生产校验覆盖：
  - 空 JWT secret 或仓库默认占位 secret；
  - PostgreSQL DSN 仍使用 `cg:cg`；
  - MinIO access/secret 仍使用 `minioadmin` 或空值；
  - `CG_MINIO_PUBLIC_ENDPOINT` 的解析结果指向 localhost / loopback；
  - LLM provider 仍为 `offline`；
  - embedding 仍为 `hash`；
  - reranker 为 `noop` 或显式关闭。
- 校验错误只包含字段名和原因，不回显 secret。
- 非 production 环境直接返回，不触碰离线默认值。

### 2.2 LLM 配置

落点：`packages/ai-engine/ai_engine/llm/settings.py`

- 新增 `LlmSettings.validate_production()`。
- production 下拒绝 `provider=offline`。
- 复用 `rag_core.config.ProductionConfigError`，不新增第二套错误类型。

### 2.3 RAG 配置

落点：`packages/rag-core/rag_core/config.py`

- 唯一处新增 `ProductionConfigError(field, reason)`。
- 新增 `RagSettings.validate_production()`。
- production 下拒绝：
  - `embed_mode=hash`；
  - `rerank_mode=noop`；
  - `rerank_enabled=false`。

### 2.4 启动接线

落点：`apps/api-gateway/app/main.py`

- 新增 FastAPI `lifespan`。
- 服务开始处理请求前调用：

```text
settings.validate_production()
```

- 校验失败直接阻止应用启动，不会先接受 `/health` 或业务请求。
- development/test 下 validator 直接返回，保持原有离线启动行为。

### 2.5 默认值文档

落点：`.env.example`

新增：

```text
CG_RUNTIME_ENV=development
```

并说明 `production` 会拒绝离线 LLM、hash embedding、noop reranker、默认 secret/口令和 localhost 公网 endpoint。
