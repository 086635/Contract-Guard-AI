## 1. 任务目标

C58 是 T-D7-5 的第一张卡，解决 D7-I09「审核页缺少真实预览接口与文件 URL 契约」的服务端一半：

1. 预览元数据持久化（一合同一行）+ 显式状态机 `PENDING/RUNNING/DONE/FAILED`。
2. `GET preview` 返回元数据与**短期签名 URL**；URL 运行时签发、不落库、不暴露内部对象 key。
3. `POST preview/retry` 派发 `convert_doc`（C59 实现转换），且**幂等**、仅 ADMIN/REVIEWER。
4. 合同不存在/不可见都返回 404，不泄露存在性。

## 2. 实现说明

### 2.1 契约（唯一 SSOT）

落点：`packages/schema/openapi.yaml`（+63 行，纯加法）

```text
PreviewStatus   = PENDING | RUNNING | DONE | FAILED
PreviewData     { contractId, status, previewUrl(nullable), expiresIn, pageCount(nullable),
                  converterVersion(nullable), createdAt }
PreviewResponse = ApiEnvelopeBase + data: PreviewData
GET  /contracts/{contractId}/preview         -> PreviewResponse         （已登录且可见合同）
POST /contracts/{contractId}/preview/retry   -> ContractUploadResponse  （ADMIN/REVIEWER + X-Request-ID）
```

生成物 `app/generated/schemas.py`、`src/api/generated/{types,zod}.ts` 由 `tsx scripts/gen-*.ts` 重新生成，**未手改**（三者 gitignored）。

### 2.2 持久化

落点：`apps/api-gateway/app/db/models.py`、`apps/api-gateway/alembic/versions/20261001_0011_add_contract_previews.py`、`apps/api-gateway/app/db/repository/preview.py`

```text
contract_previews
  id (PK) | contract_id (FK contracts.id, UNIQUE) | status(preview_status enum)
  preview_object_key (内部 key，nullable) | convert_task_id (在飞转换任务，nullable)
  page_count | converter_version | error_message | created_at | updated_at
  INDEX ix_contract_previews_status
```

`preview_object_key` 只在服务内部使用；**绝不进 API 响应**。仓储与迁移的列/索引由 `test_db_alembic::test_migration_schema_matches_c1_metadata` 逐列比对。

### 2.3 服务：`app/services/preview_service.py`（新建）

```text
source_kind_of(filename)        -> "PDF" | "DOCX" | None      （选预览管线）
initial_preview_status(filename)-> DONE(pdf) | PENDING(docx) | FAILED(其它)
preview_object_key_for(contract)-> PDF 用原文 storage_path；DOCX 等 C59 写派生对象
PreviewService.get(contractId)  -> 读/初始化预览行 -> PreviewData（运行时 presign_get，TTL=900）
PreviewService.retry(contractId)-> 幂等派发 convert_doc；返回 TaskProgress
```

- **状态机**：`PENDING`（DOCX 初始）→ `RUNNING`（retry 派发成功）→ `DONE`/`FAILED`（C59 转换后写入）。
- **幂等**：`RUNNING` 且已有 `convert_task_id` 时不再重复派发；`DONE` 时 retry 不派发。
- **URL**：仅 `DONE` 且有对象 key 时 `presign_get(key, 900)`，`expiresIn` 才非 0。

### 2.4 路由

落点：`apps/api-gateway/app/api/v1/contracts.py`

- `GET /contracts/{id}/preview`：`get_current_user` + 合同存在性 → 404（`ContractNotFoundError`）；写 `VIEW` 审计（`resource_type=CONTRACT_PREVIEW`）。
- `POST /contracts/{id}/preview/retry`：`require_roles(Role.admin, Role.reviewer)` + `X-Request-ID` 头（全局幂等中间件键）。
- 两条路由都只经 `PreviewService`，路由内不拼 SQL、不直接碰 MinIO。

- 未实现 DOCX→PDF 实际转换（C59）；未做 BBox 映射（C60）与查看器（C61）；

- 未改 `rag_contracts` / `rag_core/service.py` / OpenAPI 既有字段（本次全部为加法）。

### 三处需知晓的决策（本卡范围内）

1. **预览来源分类用存储文件名后缀**（`source_kind_of`）：`contracts` 表没有 `file_type` 列，而本卡落点不含该列；上传阶段的**真实内容判据**由 C56/C57 完成（magic sniff + 结构校验）。若后续要求 DB 级判定，应新开卡片给 `contracts` 加列。
2. **retry 不写 `audit_tasks` 行**：`audit_task_type` 是 CHECK 约束（`PARSE_DOC/RUN_AUDIT/GEN_REPORT`），加 `CONVERT_DOC` 需要跨卡迁移（且离线迁移测试会把 PG DDL 灌进 SQLite，`DROP CONSTRAINT` 不可执行）。C58 改用本表 `convert_task_id` 实现在飞幂等；**任务行与任务类型登记归 C62**（任务可靠性模型）。返回的 `TaskProgress.taskId` 为在飞 Celery id，预览进度以 `GET preview` 的 `status` 为准。
3. **retry 不写审计事件**：`4-7 §⑥.3` 的审计动作白名单不含预览转换；新增动作要动 OpenAPI 枚举 + DB 约束，属跨卡契约变更。`GET preview` 按既有惯例写 `VIEW`。
