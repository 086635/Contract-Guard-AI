## 2. 当前代码事实

### 2.1 局部记忆骨架

文件：

```text
packages/ai-engine/ai_engine/memory/scoped_memory.py
```

拥有：

```python
DialogTurn
ScopedClauseMemory
ScopedMemoryManager.append()
ScopedMemoryManager.get()
```

缺失：

```python
ScopedMemoryManager.record_turn()
ScopedMemoryManager.set_draft()
ScopedMemoryManager.snapshot()
```

当前窗口通过 `deque(maxlen=5)` 维护，但 `draftAfter` 未纳入 manager 的持久内存：

```text
get() 始终返回 draftAfter=None
```

因此 C11 目前只能直接操作请求携带的 memory 快照，不能通过统一 manager 读取最新草稿。

### 2.2 重复定义

同一类当前有两处：

```text
agents/rewriter.py:
  class ScopedClauseMemory

memory/scoped_memory.py:
  class ScopedClauseMemory
```

这正是 L3 的事实缺陷 F7。

后果：

- 两个 import 路径指向不同 Python 对象。
- 字段虽然暂时相同，但后续只改一处会产生静默漂移。
- 无法通过“同一类型”断言。

T-B5 要求：

```python
from ai_engine.agents.rewriter import ScopedClauseMemory as A
from ai_engine.memory import ScopedClauseMemory as B
assert A is B
```

当前该断言不成立。

### 2.3 全局状态骨架

文件：

```text
packages/ai-engine/ai_engine/memory/global_state.py
```

已有：

```python

ClauseNode
GlobalContractState
GlobalStateManager
```

`GlobalStateManager` 当前是进程内 dict，具备基础 `save()` / `load()`。

该部分属于 C12 的全局层，但尚未与 C11 的 `RewriteState` 或 `GraphDeps` 做统一分层装配。

## 6. 风险

### 风险 1 · 类型身份漂移

两个 `ScopedClauseMemory` 当前字段相同，但一旦只改其中一个，API 与图状态会出现隐性不兼容。

### 风险 2 · 草稿丢失

当前 manager 的 `get()` 固定返回 `draftAfter=None`，多轮改写不能可靠复用上轮草稿。

### 风险 3 · C13 前置不成立

C13 需要稳定 `MemoryStorePort` 和统一 memory 类型。C12 未完成时直接做 C13，会把持久化建在不唯一的类型之上。

### 风险 4 · 全局 / 局部职责混淆

`GlobalContractState` 保存合同 AST 和元信息；`ScopedClauseMemory` 保存当前条款近 3-5 轮。两者不能混存。
