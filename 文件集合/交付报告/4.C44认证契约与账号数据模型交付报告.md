## 1. 任务目标

C44 是 T-D7-1 的身份与权限序列入口，目标是在不实现登录/JWT/路由行为的前提下，先把认证契约、用户持久化模型和用户仓储冻结下来，供后续 C45~C50 消费。

本次交付形成的最小闭环是：

```text
openapi.yaml
  -> Role / CurrentUser / LoginRequest / TokenData / UserListData 等 DTO
  -> users ORM + Alembic migration
  -> UserRepository（规范化、唯一约束、安全 DTO）
  -> C45 认证安全原语 / C46 AuthService / C47 Auth+RBAC 路由
```

## 3. 实现说明

### 3.1 OpenAPI 契约加法

落点：`packages/schema/openapi.yaml`

新增 DTO：

- `Role = ADMIN | REVIEWER | VIEWER`
- `CurrentUser`
- `LoginRequest`
- `RefreshRequest`
- `TokenData`
- `UserListData`
- `UserCreateRequest`
- `UserUpdateRequest`
- `CurrentUserResponse`
- `TokenResponse`
- `UserListResponse`
- `UserResponse`

新增路径占位：

- `POST /auth/login`
- `POST /auth/refresh`
- `GET /auth/me`
- `GET /admin/users`
- `POST /admin/users`
- `PATCH /admin/users/{userId}`

这些路径在 C44 阶段只表达契约，不表示 FastAPI 已完成路由实现。路由清单守卫明确区分 20 条已实装 operation 与 6 条 C47 前占位 operation。

### 3.2 用户表模型

落点：`apps/api-gateway/app/db/models.py`

`User` 表包含：

- `id`：UUID 主键；
- `username`：唯一、规范化用户名；
- `password_hash`：仅持久化字段，仓储安全投影不返回；
- `role`：复用 OpenAPI 生成的 `Role` 枚举；
- `is_active`：启用状态；
- `display_name`：显示名；
- `last_login_at`：可为空；
- `created_at` / `updated_at`：UTC 时间戳。

### 3.3 Alembic 迁移

落点：`apps/api-gateway/alembic/versions/20260929_0007_add_users.py`

迁移只做：

1. 创建 `users` 表；
2. 建立用户名唯一约束 `uq_users_username`；
3. 建立角色与启用状态索引；
4. downgrade 按逆序删除索引和表；
5. 不插入任何默认用户。

### 3.4 用户仓储

落点：`apps/api-gateway/app/db/repository/auth.py`

仓储能力：

- `create`：规范化用户名，写入并 flush；重复用户名抛出 `UserAlreadyExistsError`；
- `get`：按 UUID 读取安全投影；
- `get_by_username`：按规范化用户名读取；
- `list`：支持分页、角色、启用状态、用户名/显示名筛选；
- `update`：更新角色、启用状态和显示名，并刷新 `updated_at`。

安全边界：

- 仓储只依赖 SQLAlchemy session 和 `User` 模型；
- 对外返回 `UserRecord`；
- 不向调用方泄漏 ORM 实例、密码哈希或数据库异常细节。
