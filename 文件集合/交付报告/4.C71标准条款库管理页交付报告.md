## 1. 任务目标

把标准条款库从「未联调」占位推进为可用的管理面：

1. Settings →「标准条款库」tab 展示**真实**分页数据（搜索、合同类型/启停过滤）；
2. ADMIN 可新增、编辑、启停、重建检索索引；其它角色只读（无编辑入口）；
3. 保存后强制重读服务端版本；409/403/422 有明确文案；失败可重试；
4. 无数据展示空态，不得回退到演示数据。

## 2. 实现说明

### 2.1 服务层（`src/api/services.ts`）

新增 `standardClauseApi`，全部经唯一 `httpClient`（自动带 `X-Request-ID` 幂等头）：

```ts
standardClauseApi.list({ page, pageSize, query, contractType, isEnabled })
standardClauseApi.create(body)      // StandardClauseCreateRequest
standardClauseApi.update(id, body)  // StandardClauseUpdateRequest（带 version 乐观锁）
standardClauseApi.rebuildIndex()    // → TaskProgress
```

### 2.2 面板模型层（`src/components/settings/standardClauseModel.ts`，纯逻辑可单测）

- `StandardClauseController`：`load / create / save / setEnabled / rebuildIndex / retry / setFilters / clearNotice`，
  内部保存 `items/total/hasMore/loading/saving/error/message/empty/filters`，以 `subscribe`/`getState`
  适配 React `useSyncExternalStore`（快照引用只在状态变更时替换）。
- **写后重读**：`create/save/rebuildIndex` 成功后统一 `refreshAfterWrite()` → `load()`，
  对应 §⑥.3「保存后刷新服务端版本」，避免前端拿本地乐观值继续改。
- **权限**：`canManageStandardClause(role)` 仅 `ADMIN` 为真；非 ADMIN 的写方法**直接返回 false 且不发请求**
  （§⑨-2「隐藏按钮即权限」的反面：后端仍 ADMIN-only，前端只是体验层）。
- **错误文案**：`standardClauseErrorMessage` 按状态码给明确文案；`retry()` 重放**上一次失败的动作**
  （加载/保存/重建各自注册重试闭包）。
- **查询参数**：`toListParams` 只在有值时下发 `query/contractType/isEnabled`，空过滤不下发空串。

### 2.3 面板视图（`src/components/settings/StandardClausePanel.tsx`）

- 顶部：条数说明 + ADMIN 专属「重建索引」「新建条款」；
- 工具栏：关键字搜索、合同类型过滤、启停过滤、查询；
- 行内编辑器：标题/合同类型/正文 + 取消/保存（保存失败保留草稿，可直接重试）；
- 列表项：标题 + 启用/停用 Badge + 合同类型/版本/来源 + 正文预览 + ADMIN 专属「编辑/停用·启用」；
- 状态区：加载中 / 空态（按角色区分文案）/ 错误横幅（含「重试」与关闭）；
- 角色来源：`useAuthStore((state) => state.user?.role)`，不新增权限状态库。

### 2.4 接线与样式

- `src/views/Settings.tsx`：`tab === "library"` 渲染 `<StandardClausePanel contractType={currentRule.contractType} />`，
  原「标准条款库状态由后续知识库联调提供 / 未联调」占位删除；规则配置三 tab 保持原样。
- `src/index.css`：新增 `.standard-clause-*` 样式（工具栏/编辑器/列表/空态/错误态），沿用现有 `data-state`、`button` 体系。
