## 1. 任务目标

把「标准条款库」从 UI 上的“未联调”占位推进为可维护、可检索、可审计的产品能力：

1. 复用 `SourceType.STANDARD_CLAUSE` 与现有 RAG 检索入口（不新增第二套检索算法）；
2. 提供 CRUD / 分页 / 启停 DTO 与 ADMIN-only API；
3. 写入**现有**向量库集合与索引规则，并提供索引重建入口；
4. 删除=软停用、来源与版本可追溯、索引更新可重试且幂等。

## 2. 实现说明

### 2.1 契约（`packages/schema/openapi.yaml`）

- 新增 schema：`StandardClause{id,title,contractType,text,isEnabled,version,source?,updatedAt?}`、
  `StandardClauseListData`、`StandardClauseCreateRequest`、`StandardClauseUpdateRequest`（`version` 必填=乐观锁）、
  `StandardClauseListResponse` / `StandardClauseResponse`（复用 `ApiEnvelopeBase`）。
- 新增路径（tags: `Admin`，全局 `bearerAuth`，写操作带 `X-Request-ID` 幂等头）：
  - `GET/POST /admin/standard-clauses`
  - `POST /admin/standard-clauses/rebuild`（返回既有 `TaskProgressResponse`）
  - `PATCH /admin/standard-clauses/{clauseId}`（`isEnabled=false` 即软删除）
- 生成物 `schemas.py` / `types.ts` / `zod.ts` 由 `tsx` 生成器重生成（三者均被 `.gitignore` 忽略，属本地构建产物）。

### 2.2 PG 人工维护源（**落点扩展**）

- `app/db/models.py::StandardClause` → 表 `standard_clauses`
  （`id/title/contract_type/text/is_enabled/version/source/created_at/updated_at` + 两个索引）。
- `alembic/versions/20261002_0013_add_standard_clauses.py`（`down_revision=20261001_0012`，`downgrade` 完整可回滚）。
- `app/db/repository/standard_clause.py`：CRUD/分页/关键字与合同类型过滤、`list_all()`（重建用）、
  乐观锁冲突 `StandardClauseVersionConflictError`、不存在 `StandardClauseNotFoundError`。

### 2.3 RAG 索引同步（唯一检索入口）

- `app/services/standard_clause_service.py::StandardClauseIndexer`：
  - 用 `build_service_from_settings()`（RAG 唯一工厂）取 `embedder` + `vector_store`，写入**同一个** `contract_clauses` 集合；
  - `ContractChunk(doc_id="std:<id>", source_type=STANDARD_CLAUSE, chunk_type=CLAUSE, title/text/contract_type/embedding_model…)`；
  - `chunk_id = ContractChunk.make_chunk_id(doc_id, section_id, 0)` 确定性生成 → 重复 upsert 幂等；
  - `remove(clause_id)` → `delete_by_doc("std:<id>")`（停用即从索引移除，满足“停用后不再命中”）。
- `StandardClauseService`：create/update 先 flush 元数据 → 同步索引 → 同一事务 commit；
  索引失败 → `rollback` + `StandardClauseIndexError`（路由映射 503），可重试；
  `rebuild_index()` 全量：启用条目 upsert + 停用条目删除 + `indexHealth`，返回 `TaskProgress.result`。
- 未改 `rag_core/service.py`、未改 `rag_contracts`、未新增第二个向量集合（§③ 适配性三问）。

### 2.4 路由与权限（`app/api/v1/standard_clauses.py`）

- 四个操作全部 `Depends(require_roles(Role.admin))`；VIEWER/REVIEWER 403 并由 `require_roles` 写 `AUTH_DENIED` 审计。
- 写路径额外写 `SETTINGS_UPDATE` + `STANDARD_CLAUSE` 审计（success/failure），与 C50 审计采集点一致。
- 路由经 `get_standard_clause_service` → `get_service_context` 取同一请求会话，
  满足既有守卫 `test_every_v1_route_uses_service_context`。
