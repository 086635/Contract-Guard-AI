## 1. 接缝纠偏

C20 实现时发现 C18 的 `ReportRenderInput` 只接受 snake_case 字段，而 `4-3 §⑤.1` 的跨进程载荷契约使用 camelCase：

```text
contractId
generatedAt
healthScore
```

为保持网关到 worker 的载荷契约一致，修正为：

- `ReportRenderInput` 使用 `Field(alias=...)` 声明 camelCase 别名。
- 保留 `populate_by_name=True`，现有 snake_case 构造继续可用。
- 新增别名解析回归测试，避免 C18/C20 再次漂移。

## 2. 实现内容

### 2.1 Celery 任务

落点：`apps/async-worker/worker/tasks/gen_report.py`

`gen_report_task(self, contract_id, payload)` 行为：

1. 生成 `trace_id` 并启动报告进度上报。
2. `payload is None` 时返回 `FAILED`。
3. 使用 `ReportRenderInput.model_validate(payload)` 校验载荷。
4. 校验 payload 的 `contractId` 与任务参数一致。
5. 调用 `render_report_docx()` 生成 DOCX。
6. 调用 `upload_report()` 上传 MinIO。
7. 返回 JSON 可序列化结果。
8. 捕获渲染、上传等异常，统一返回 `FAILED`，不向 broker 抛异常。

成功结果：

```python
{
    "contractId": "<uuid>",
    "status": "DONE",
    "format": "DOCX",
    "storagePath": "reports/<uuid>/<timestamp>_<uuid8>.docx",
    "warnings": [],
}
```

失败结果：

```python
{
    "contractId": "<uuid>",
    "status": "FAILED",
    "format": "DOCX",
    "storagePath": "",
    "warnings": ["<reason>"],
}
```

### 2.2 报告进度上报

落点：`apps/async-worker/worker/progress.py`

新增：

```python
REPORT_STAGES = ("render", "upload")
REPORT_STAGE_PERCENT = {
    "render": 0.60,
    "upload": 0.95,
}
ReportProgressReporter
```

报告链路独立于解析链路和审核链路：

- 不复用 `PARSE_STAGES`。
- 不复用 `AUDIT_STAGES`。
- 未知阶段只告警并忽略。
- 进度单调不回退。
- `update_state` 失败不影响任务本身。
