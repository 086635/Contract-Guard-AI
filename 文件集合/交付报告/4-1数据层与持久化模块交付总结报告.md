## 1. 任务目标与边界

### 1.1 目标

1. 建立合同业务的结构化持久化层。
2. 为 API Gateway 提供不泄漏 ORM 的异步 DAL。
3. 用 Alembic 管理 schema，不手改数据库。
4. 保持离线测试可运行，外部 DB 未配置时自动 skip。
5. 为 T-D2、T-D3 提供合同、任务、结果、配置、反馈和报告读写能力。

### 1.2 明确不做

- 不实现 API Gateway 路由去 Mock，属于 T-D2。
- 不实现 worker 报告生成，属于 T-D3。
- 不修改 OpenAPI 契约、`rag_contracts` 或生成物。
- 不实现业务审核、OCR、RAG 逻辑。

## 5. 关键设计决策与纠偏

### 5.1 ORM 不泄漏到路由层

C4/C5/C6 使用仓储层持久化 DTO：

- C4：`ContractCreate` / `ContractDetail` / `ContractSummary` / `TaskRecord`
- C5：`ReportRecord`
- C6：`RuleUpsert` / `RuleRecord` / `FeedbackRecord`

完整 OpenAPI DTO 聚合留给服务层。

### 5.2 seal 独立表

`SealSignatureDetection` 使用独立 `seal_detections` 表，
未把 seal 数据塞进 `audit_risks` 的 JSON 逃生舱。

### 5.3 事务边界

Repository 只执行 `flush()`，不主动 `commit()`；
事务提交由调用方或服务层统一控制。
