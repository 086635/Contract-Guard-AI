## 1. 关键纠偏：DTO 名称与 OpenAPI 生成物不一致

C4 原接口写的是：

```python
ContractDetail
ContractCreate
```

实测 OpenAPI 生成物中不存在这两个类，且生成物 `Contract` 需要
`version`、`currentVersionId`、`healthScore` 等 `contracts` 表没有的字段。
如果强行返回生成物 `Contract`，只能伪造未持久化字段。

因此本卡按以下边界落地：

1. `ContractCreate` / `ContractDetail` / `ContractSummary` 定义为 **repository 持久化 DTO**。
2. 这些 DTO 只投影 `contracts` 表列。
3. `TaskRepository` 返回 `TaskRecord`，不返回 ORM `AuditTask`。
4. 全量 OpenAPI `Contract` 的服务层聚合不在 C4 范围。

该纠偏已写入 C4 组件卡头部。

## 2. 实现内容

落点：[contract.py](E:/important_project/Serve_bage/apps/api-gateway/app/db/repository/contract.py:1)

### 2.1 持久化 DTO

| DTO | 用途 |
|---|---|
| `ContractCreate` | 创建合同记录 |
| `ContractSummary` | 合同列表投影 |
| `ContractDetail` | 合同单条投影 |
| `TaskRecord` | 任务单条投影 |

所有 DTO 均开启 `from_attributes=True`，从 ORM 对象安全转换。

### 2.2 ContractRepository

| 方法 | 行为 |
|---|---|
| `list(page, page_size)` | 分页、总数、按创建时间倒序 |
| `get(contract_id)` | 按主键读取，不存在返回 `None` |
| `create(meta)` | add + flush，返回 `ContractDetail` |
| `update_status(...)` | 更新状态并刷新 `updated_at` |

分页参数约束：

- `page >= 1`
- `1 <= page_size <= 100`

### 2.3 TaskRepository

| 方法 | 行为 |
|---|---|
| `create(...)` | 新任务默认 `stage=queued`、`progress=0.0`、`status=RUNNING` |
| `get(task_id)` | 按主键读取 |
| `update_status(...)` | 更新任务状态与错误信息 |
| `update_progress(...)` | 写入阶段与 `0..1` 进度 |

`update_progress` 在进入数据库前校验范围，`progress=1.1` 直接抛 `ValueError`。
