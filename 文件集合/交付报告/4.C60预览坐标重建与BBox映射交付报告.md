## 1. 任务目标

C60 接在 C59 之后，补上 D7-I10 的后半段：**DOCX 走完 DOCX→PDF 转换后，条款坐标必须来自转换 PDF 的真实文本行**，
而不是 DOCX 的合成坐标（按段落顺序推断的占位值）：

1. 对转换后 PDF 复用 `doc_processor` 文本抽取 + aligner 重建坐标。
2. 把条款文本与预览 PDF 行文本对齐，更新可定位 BBox。
3. 无法对齐的条款保持 `bbox=null` 并写 warning。
4. 坐标统一 `PDF_POINTS`、1-based page。

## 2. 实现说明

### 2.1 对齐纯函数（`app/services/preview_service.py`）

```text
extract_preview_lines(pdf)            -> (lines: list[TextLine], page_sizes)   # pdfplumber，PDF_POINTS
_normalize_with_map(text)             -> (归一化文本, 原始下标映射)             # 折叠空白
find_text_span(clause_text, ...)      -> [start, end) | None                   # 原始偏移
clamp_bbox(bbox, page_size)           -> BBox                                  # 越界夹取
union_bbox(boxes, page, page_size)    -> BBox | None                           # 同页并集；退化返回 None
align_chunks_to_lines(chunks, ...)    -> (updated_chunks, aligned, unaligned, mismatch)
```

对齐规则（本卡**唯一定义处**）：

1. **归一化空间匹配**：DOCX 与 PDF 的换行/缩进不同，先折叠空白为单空格再查找，命中后回到**原始偏移**，
   交给 `BBoxAligner.locate(start, end)`（复用 `3-5` 的索引，不新写坐标算法）。
2. **最短长度门槛** `MIN_ALIGN_CHARS = 8`：过短文本（如「甲方」）易误配，直接判为不可匹配。
3. **并集框**：只取**起始页**的行框并集（单个 BBox 无法跨页），与 `3-6 _union_bbox` 同口径。
4. **越界夹取**：并集框按页尺寸夹取；夹取后零面积 → 视为无几何框（不伪造高亮）。
5. **只改 `bbox` / `page_no`**：其余 27 个字段与 `chunk_id` 原样保留 —— 这是 `bulk_upsert` 幂等更新的前提。

### 2.2 服务编排（`PreviewService.rebuild_preview_bbox`）

```text
rebuild_preview_bbox(contract_id, preview_pdf=None) -> AlignmentReport{contract_id, aligned, unaligned, mismatch, warnings}
  · 守卫：预览行必须 DONE 且 converter_version 非空（= 转换产物）→ 否则 return 空报告 + warning
  · 取 PDF：显式路径优先；否则用 download_object() 拉到**任务私有临时目录**并在 finally 清理
  · 抽行 → 建索引 → 逐条对齐 → IngestionService.finalize_preview_alignment() 写回
```

调用点：`PreviewService.reconcile_convert()` 在把预览置 `DONE` 之后调用一次；**失败只告警**，不影响预览可用。

### 2.3 写回（`app/services/ingestion.py`）

```text
IngestionService.finalize_preview_alignment(contract_id, chunks) -> int
  · 复用 ElementRepository.bulk_upsert()（按 chunk_id upsert，幂等）
  · 空输入不触发写
```

### 2.4 投影防御（`app/services/projector.py`）

`ContractProjector._is_renderable()`：页码 < 1、宽高非正、坐标非有限 → **不投影 bbox**（`None`）。
这是最后一道「不伪造高亮」的防线，与前端「无 bbox 不画框」的约定一致。

### 2.5 端口扩展（本卡对 §0.8 的落点扩展）

`ObjectStoragePort.download_object(file_key, target_path)` + `MinioObjectStorage` 实现
（内部 client `fget_object`，只读）。理由：坐标重建必须**在服务端读取转换产物**，而网关原有端口只有
`presign_put/presign_get/stat_object`（C8 时代的最小面）。未新增第二套对象存储适配器。

## 7. 边界与后续

### 边界声明

- **不沿用 DOCX 合成坐标**：合成坐标（`_NullAligner` 路径）在 DOCX 阶段就是 `bbox=None`；C60 只在**转换产物**上重建，
  且无法对齐时主动清空旧值（`test_unmatched_clears_stale_synthetic_bbox`）；
- **不在前端猜坐标**：C60 只产出坐标真相；前端只做比例映射（C61）；
- **不对无法对齐的文本伪造高亮**：`bbox=None` 一路到 API（`_is_renderable` 再兜一次）；
- **不新增第二套坐标算法**：索引/缩放复用 `doc_processor.aligner`，并集/跨页口径与 `3-6 _union_bbox` 一致；
- 未改 `rag_contracts` 既有字段与枚举（`BBox` 复用，未新增字段）。

### 两处需知晓的决策

1. **落点扩展（2 个文件）**：`app/services/ports.py`、`app/services/storage.py` 不在本卡 ④ 清单内。
   理由：坐标重建必须服务端读取转换产物，端口缺 `download_object` 就无法闭环；扩展是**追加方法**，
   未新增第二套适配器、未改既有方法语义。
2. **`MIN_ALIGN_CHARS = 8`**：短文本（<8 字）不参与对齐，避免「甲方」这类词误配到无关位置，
   宁可 `bbox=None`（记录 warning）也不给错框。

### 未做（明确归属）

- **相对变焦映射**（PDF.js 视口 ↔ PDF_POINTS）：前端职责，归 **C61**；
- **pageCount**：本卡不写 `contract_previews.page_count`（需要页数口径确认）。转换产物的页数可由
  `extract_preview_lines()` 的 `page_sizes` 直接得到，若要落库建议随 **C61** 一并补（本卡未擅自新增字段语义）；
- 真实 `pdfplumber` + 真实 MinIO 的端到端证据：归 **C67/T-D7-8**（需要真实转换产物）。

### 后续
