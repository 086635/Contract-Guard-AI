## 2. 实现说明

### 2.1 探针（`app/main.py`）

```text
GET /health        → 兼容保留（等价 live）
GET /health/live   → {"status":"ok"}                     # 只表示进程活着，**不查任何外部依赖**
GET /health/ready  → {"status","service","checks":{database,redis,minio,qdrant}}
                     全部 ok → 200；任一 error/超时/异常 → **503**
```

- **四项依赖各走既有适配器**（不新增第二套客户端）：
  `database` → SQLAlchemy engine `SELECT 1`；
  `redis` → `RedisProgressBroker.ping()`（C67 新增端口方法）；
  `minio` → `MinioObjectStorage.bucket_exists()`（C67 新增端口方法）；
  `qdrant` → `rag_core.factory.build_vector_store(...)` 的 `health()`（复用 C55 的适配器探针）。
- **单依赖 2 秒超时**（`READINESS_TIMEOUT_S`），异常/超时统一折算 `error`；
- 响应体**只有依赖名与 ok/error**，不含连接串、地址与凭据（⑥-1）。
- 同步适配器调用走 `asyncio.to_thread`，不阻塞事件循环。

### 2.2 生产 overlay（`docker/docker-compose.prod.yml`，在 C66 secret 层之上叠加）

| 项 | 做法 |
|---|---|
| 端口 | 内网服务 `ports: !override []`；nginx 固定 `["80:80","443:443"]`；`--profile milvus` 的 milvus/etcd 同样不发布端口 |
| 可用性 | 每个服务 `restart: unless-stopped`（migrate/minio-init 保持 `"no"`） |
| 资源 | `deploy.resources.limits.{cpus,memory}`，全部 `${CG_*_CPUS:-…}` / `${CG_*_MEMORY:-…}` 可覆盖 |
| 日志 | json-file 轮转 `${CG_LOG_MAX_SIZE:-10m}` / `${CG_LOG_MAX_FILE:-5}` |
| 探针接线 | api healthcheck → `/health/live`；`CG_DISABLE_DOCS: "true"` |
| 依赖门禁 | `worker.depends_on.clamav.condition: service_healthy`（C57 的 `service_started` 升级） |
| P2 支线 | milvus + etcd 转入 `profiles: ["milvus"]`：生产默认**不启动**，需要时才开 |

> TLS / 安全头 / 限流仍是 **C68**（`docker/nginx.prod.conf`）；本卡只改端口与编排。

## 7. 边界与后续

### 边界声明

- **不删除 development compose**：基础文件保持本地开发端口；prod 用叠加层收敛（`test_development_compose_kept` 守卫）；
- **不让 MinIO/Qdrant 直连公网**：两者在 prod overlay 里 `ports: !override []`；
- **不用容器启动成功替代依赖就绪**：`live` 只表示进程活着，依赖就绪一律由 `ready` 表达（探针超时也算不可用）；
- **不新增第二套部署编排**：仍是同一份 `docker-compose.yml` + 一个 prod overlay（无第二个 stack 定义）。

### 三处需知晓的决策

1. **端口收敛用 `ports: !override []`**：compose 对 `ports` 默认是合并语义，无法靠覆盖单个 key 删除映射；
   `!override`（Compose 2.24+，本机 v5.4.0）是官方支持的替换语法，已用 `docker compose config` 实测生效。
2. **Qdrant 探针复用 `rag_core` 适配器**：网关没有自己的向量库客户端，`QdrantVectorStore.health()` 是既有唯一实现；
   `inmemory` 实现没有 `health()` 时视为就绪（生产由 C55 门禁强制 qdrant）。
3. **`pytest.ini` 增加 `docker/tests`**：卡片指定的契约测试路径不在原 `testpaths` 内，不加上就**静默不跑**。
