## 2. 实现说明

### 2.1 `app/config.py`：secret 文件注入（唯一处）

```python
jwt_secret_file / postgres_password_file / minio_access_key_file / minio_secret_key_file / llm_api_key_file

@model_validator(mode="after")
def _apply_secret_files(self) -> Settings:
    · 文件值覆盖内联值（优先级：文件 > 环境变量 > 默认值）
    · CG_POSTGRES_PASSWORD_FILE → 口令按 URL 规则转义后注入 DSN（协议/主机/端口/库名保持）
    · CG_LLM_API_KEY_FILE → 写入进程环境（ai_engine 的 LlmSettings 从环境读 key）
    · 文件不可读 / 为空 → 立刻失败（ProductionConfigError，消息只含字段名）
```

- **`SecretStr`**：`jwt_secret` / `minio_access_key` / `minio_secret_key` 改为 `SecretStr`，
  `repr(settings)`、`model_dump()`、`model_dump_json()` 一律输出 `**********`（§⑥-1 / 断言 3）。
- **`_read_secret_file`**：错误信息只给「字段名 + 异常类型」，**不回显文件内容或路径**（§⑨-2）。
- **生产门禁扩展**：`validate_production()` 增加 `CG_LLM_API_KEY` 必填（C54 的 `LlmSettings.validate_production`
  只检查 provider 与 external-data 开关，缺 key 会在运行期才炸）。
- **自检 CLI**：`python -m app.config --check` → 通过打印「配置自检通过」；失败打印
  `配置自检失败：<字段名> → <原因>` 并 exit 1。

## 7. 边界与后续

### 边界声明

- **不提交真实 secret**：模板与 compose 只有占位/路径；测试用的 secret 全在 `tmp_path` 里；
- **不以空字符串作为生产默认**：空值即门禁失败（JWT/DB/MinIO/LLM 全覆盖）；
- **不把 secret 回显到日志**：`SecretStr` 掩码 + 校验消息只给字段名 + CLI 只打印字段名；
- **不新增第二套 env 命名**：沿用 `CG_` 前缀与 `BaseSettings`，新变量一律 `<既有变量>_FILE`。

### 三处需知晓的决策

1. **`*_FILE` 的解析放在 `Settings` 构造期**（`model_validator`）：这样 `app.db.session`、`storage.py`
   等**在 import 期读取 settings 的地方**也能拿到注入后的值；代价是 pydantic 会把 validator 的异常
   包成 `ValidationError`（消息仍保留字段名，测试已按此断言）。
2. **`CG_LLM_API_KEY_FILE` 写进程环境**：`ai_engine` 的 `LlmSettings` 从环境读 key，而 ai-engine 不在本卡落点；
   把文件值落到 `os.environ` 是让「文件注入」在**运行期真正生效**的最小改动（值不落镜像、不进日志）。
3. **`jwt_secret`/`minio_*` 改为 `SecretStr`**：这是断言 3 唯一可靠的实现方式（`repr`/`dump` 全掩码），
   代价是 2 处消费方改为 `.get_secret_value()`（已一并提交）。
