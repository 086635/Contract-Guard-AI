## 1. 任务目标与边界

### 1.1 本卡目标

1. 建立审核图的依赖注入边界，防止模型、客户端和配置对象进入可序列化 state。
2. 固化唯一的六阶段拓扑，避免后续节点自行拼接边或改变执行顺序。
3. 提供 C5~C8 共同复用的模型解析、模板解析、条款预算和阶段状态增量 helper。
4. 让图骨架在没有业务节点、没有 Prompt、没有 RAG Tool、没有 API Key 的环境下也能跑完。

### 1.2 明确不做

- 不实现 classify / extract / risk / conflict / standard_compare / report_draft 的业务产出。
- 不调用真实 LLM、RAG 服务、网络、数据库或文件系统。
- 不把 `GraphDeps` 放进 `AuditState`。
- 不构造 `ChatOpenAI`、`RAGService` 或 Prompt 库实例。
- 不实现 checkpointer 后端选择，只透传调用方传入的实例。
- 不修改 `rag_contracts`、`rag_core/service.py` 或 C3 的 15 个状态键。

### 1.3 依赖方向

本卡新增代码保持以下方向：

```text
C3 AuditState
    |
    v
C4 GraphDeps / nodes / audit_graph
    |
    +--> C2 get_chat_model
    +--> PromptLibrary
    +--> rag_contracts.AgentRAGToolResult
```

未出现 `worker`、`apps/*`、`rag_core` 实现、Qdrant、Milvus 或 HTTP SDK 依赖。

## 2. 实现内容

### 2.1 依赖容器

落点：[deps.py](E:/important_project/Serve_bage/packages/ai-engine/ai_engine/graphs/deps.py:21)

```python
@dataclass(frozen=True, slots=True)
class GraphDeps:
    rag_tool: Callable[..., AgentRAGToolResult] | None = None
    llm: BaseChatModel | None = None
    prompt_lib: PromptLibrary | None = None
    max_clauses: int = 100
    max_conflict_pairs: int = 50
    conflict_batch_size: int = 10
```

设计结果：

- 依赖容器不可变，避免节点运行期意外修改共享配置。
- `rag_tool=None` 是合法状态，用于图骨架编译和后续节点的显式降级。
- `llm=None` 时由节点惰性调用 C2 的 `get_chat_model(role)`，构图期不构造模型。
- `prompt_lib=None` 等价于空库，后续 LLM 节点应直接 `SKIPPED`。
- 所有预算项都是纯标量，不进入 state。

### 2.2 共享节点辅助函数

落点：[nodes.py](E:/important_project/Serve_bage/packages/ai-engine/ai_engine/graphs/nodes.py:22)

| 符号 | 作用 |
|---|---|
| `_resolve_llm(deps, role)` | 优先使用注入模型，否则走唯一模型工厂 |
| `_resolve_prompt(deps, name)` | 缺库或缺模板返回 `None`，不抛异常 |
| `_bounded_clauses(state, deps)` | 按 `max_clauses` 截断，并返回固定预算 warning |
| `_stage_update(...)` | 返回统一的 `warnings + stage_log` 状态增量 |

条款预算 warning 固定为：

```text
条款数 {n} 超过上限 {m}，仅审核前 {m} 条
```

这保证后续 C5~C8 不需要各自实现第二套预算文案或阶段日志结构。

### 2.3 固定六阶段拓扑

落点：[audit_graph.py](E:/important_project/Serve_bage/packages/ai-engine/ai_engine/graphs/audit_graph.py:39)

```text
START
  -> classify
  -> extract
  -> risk
  -> conflict
  -> standard_compare
  -> report_draft
  -> END
```

实现方式：

- `StateGraph(AuditState)`。
- 节点名逐字取自 `AUDIT_STAGES`。
- 节点函数通过 `functools.partial(node, deps=deps)` 绑定依赖。
- 相邻阶段使用 `itertools.pairwise` 连接。
- `checkpointer` 原样传给 `compile()`。

### 2.4 占位节点

六个节点当前都返回：

```python
{
    "warnings": [],
    "stage_log": [
        {
            "stage": "...",
            "status": "SKIPPED",
            "latency_ms": ...,
            "detail": "Cx 未实现：stage 节点",
        }
    ],
}
```

节点归属：

| 节点 | 后续实现卡 |
|---|---|
| `classify` | C5 |
| `extract` | C5 |
| `risk` | C6 |
| `conflict` | C7 |
| `standard_compare` | C7 |
| `report_draft` | C8 |

占位实现不读取 state 的业务内容，不调用依赖对象，不构造模型或 RAG 客户端。

## 4. 质量评测

### 4.1 边界质量

| 维度 | 评价 | 说明 |
|---|---|---|
| 状态可序列化 | 通过 | `GraphDeps` 未进入 `AuditState` |
| 单一模型入口 | 通过 | 节点只调用 C2 resolver，不直接构造模型 |
| 单一阶段定义 | 通过 | 节点名与流式顺序均来自 `AUDIT_STAGES` |
| RAG 隔离 | 通过 | 只声明可调用契约，不 import 向量库或 SDK |
| checkpointer 解耦 | 通过 | 只注入，不绑定 InMemory / Postgres / Redis |
| 后续扩展边界 | 通过 | C5~C8 可直接替换节点函数，无需改拓扑 |

### 4.2 可靠性

- 无参数 `GraphDeps()` 可以编译并运行。
- `rag_tool=None` 不会在 C4 阶段被解引用。
- 六节点占位执行不会访问外部服务。
- 条款预算 helper 有明确 warning，不会静默丢弃。
- 阶段日志统一包含 `stage / status / latency_ms / detail`。

### 4.3 当前限制

1. **节点尚无业务产出**
   当前所有阶段都为 `SKIPPED`。这不代表审核图已经能完成审核，只代表骨架可运行。

2. **Prompt 尚未接入**
   `_resolve_prompt()` 已提供安全入口，但 C14 模板尚未落盘。

3. **RAG Tool 尚未接入**
   `risk` 与 `standard_compare` 的真实 RAG 调用需要先完成 C9。

4. **C6 / C7 的执行顺序**
   C6 必须在 C9 后执行；C7 的 standard_compare 部分也依赖 C9。

5. **尚无端到端质量指标**
   本卡不产生风险、矛盾、缺失条款或报告，因此不评测召回率、精准率或健康分。
   这些指标应在 C5~C10 完成后按任务层 `test_audit_graph.py` 统一评测。
