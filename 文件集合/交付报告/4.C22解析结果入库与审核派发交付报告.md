## 1. 交付范围

本卡负责：

- 网关侧惰性结果入库（沿用 C21「worker 不直连 DB、gateway 按 Celery 结果落库」模式）。
- 解析结果入库：最新 `PARSE_DOC` 任务 DONE 后，把 `clauses` 投影为 `ContractChunk` 写入 `contract_elements`、把 `sealDetections` 写入 `seal_detections`。
- 审核派发：解析入库成功后派发 `run_audit` 并建 `audit_tasks` 行。
- 在 `GET /contracts/{id}/elements|seals|parse-status` 读前触发（幂等）。

本卡不负责：

- 新增 API 端点、修改 `openapi.yaml` / 生成物。
- 让 worker 直连 PostgreSQL。
- 重写 RAG / Agent / OCR 解析或审核逻辑。
- 审核结果入库（属 `4.C23`）。

### 背景（为什么本卡存在）

实测发现 T-D2 收官后仍有一处断链：`TaskKind.RUN_AUDIT` 已声明但**没有任何 service 调用它**，且 `ElementRepository/RiskRepository/SealRepository.bulk_upsert` **只在测试里被调用**——真实链路上解析/审核结果从不入库、`run_audit` 从不触发、报告必为空。故 T-D4（端到端联调）新增 C22/C23 补上该业务接线，`4-4` 文档已同步「范围纠偏」。

## 2. 实现内容

### 2.1 `IngestionService.finalize_parse`

落点：`apps/api-gateway/app/services/ingestion.py`

流程：

1. 读取最新 `PARSE_DOC` 任务；无任务直接返回 `False`。
2. 按任务 `celery_task_id` 读取 Celery 快照；非 DONE（RUNNING/FAILED/无快照）返回 `False`，**不写库不派发**。
3. 只信任快照 `result` 顶层的 `clauses` / `sealDetections`，缺失按空列表处理。
4. 逐条投影 `clause → ContractChunk`；`sealDetections` 校验为 `SealSignatureDetection`。
5. `ElementRepository.bulk_upsert` / `SealRepository.bulk_upsert` 写入并 `commit`。
6. 有条款时调用 `ensure_audit_dispatched`；单条投影/派发失败隔离为 warning，不抛给路由。

### 2.2 `IngestionService.ensure_audit_dispatched`

1. 查该合同最新 `RUN_AUDIT` 任务行；已存在且 `celery_task_id` 非空则直接复用（幂等）。
2. 否则 `task_dispatcher.send(TaskKind.RUN_AUDIT, args=(str(contract_id), clause_payload))`。
3. `TaskRepository.create(contract_id, "RUN_AUDIT", celery_task_id)` 并 `commit`。

`clause_payload` 直接取解析结果的 `clauses`，与 `worker.adapters.to_clause_inputs` 可消费的形状一致。

### 2.3 `clause_payload_to_chunk`（唯一投影口径）

| clause 键 | `ContractChunk` 字段 | 规则 |
|---|---|---|
| `clause_id` | `section_id` / `chunk_id` | `chunk_id = make_chunk_id(contract_id, clause_id, 0)` |
| `text` | `text` / `text_hash` / `char_count` / `token_count` | `hash = compute_text_hash(text)`；`token = round(char/1.5)` |
| `label` | `title` / `section_path` | 兜底取 `clause_id` |
| `level` / `parent_id` | `level` / `parent_section_id` | 缺省 `0` / `None` |
| `page_no` + `bbox` | `page_no` / `bbox` | 有几何才构造 `BBox`，否则 `None` |
| — | `doc_id` / `source_type` / `chunk_type` / `seq_in_doc` | `contract_id` / `STANDARD_CLAUSE` / `CLAUSE` / 序号（对齐既有 `_chunk` 夹具口径） |

### 2.4 触发点

`ResultService.parse_status / elements / seals` 在 `_require_contract` 之后调用 `IngestionService(self._context).finalize_parse(contract_id)`（幂等，重复读不重复写）。

## 5. 边界与已知事项

1. **测试基座改动（越界声明）**：`apps/api-gateway/tests/service_testkit.py` 的默认 `task_dispatcher` 由裸 `object()` 改为实现 `TaskDispatcherPort` 的 `_NullTaskDispatcher`（`get_status → None`）。原因：C22 新增的读路径会调用 `get_status`，旧的裸 `object()` 默认值违反端口协议，会让既有真实 PG 测试 `test_contract_results_real` 崩。属测试基建修复，不动生产契约。
2. **不新增端点 / 不改契约**：`openapi.yaml`、`rag_contracts`、`service.py`、生成物均未触碰；worker 不直连 PostgreSQL。
3. **幂等边界**：`bulk_upsert` 按 `chunk_id` / 结果主键冲突更新；派发按 `audit_tasks` 行 + `celery_task_id` 判重。
4. **审核结果入库**：`risks/conflicts → audit_risks` 属下一张卡 `4.C23`，本卡不越界。
5. **环境事实（卡点定位记录）**：`scripts/eval_recall.py` 把 BM25 临时目录写在 `data/reports/`，在受限沙箱下写入被拒会使 `tempfile.mkdtemp` 循环重试而「假卡死」；全量门禁需在可写 `data/` 的权限下运行。此为既有脚本行为，与本卡代码无关。
