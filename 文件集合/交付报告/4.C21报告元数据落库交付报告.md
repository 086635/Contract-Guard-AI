## 1. 交付范围

本卡负责：

- 从 DAL 聚合报告任务输入。
- 派发 `gen_report` Celery 任务。
- 根据最新 `GEN_REPORT` 任务结果补写 `audit_reports`。
- 运行时签发报告下载 URL。

本卡不负责：

- 在网关生成 DOCX。
- 让 worker 直连 PostgreSQL。
- 修改报告契约字段。
- 把 `downloadUrl` 写入数据库。

## 2. 实现内容

### 2.1 `generate`

落点：`apps/api-gateway/app/services/report_service.py`

流程：

1. 检查合同存在。
2. 从 `ResultService` 读取 `risks/conflicts/elements`。
3. 按 `4-3 §⑤.1` 组装 payload。
4. 向 Celery 发送 `gen_report`，参数为 `(contract_id, payload)`。
5. 创建 `audit_tasks.task_type=GEN_REPORT` 行。
6. 返回 `TaskProgress(RUNNING@0)`。

### 2.2 `get`

流程：

1. 检查合同存在。
2. 优先读取 `audit_reports`；已有报告直接签发下载 URL。
3. 无报告时读取最新 `GEN_REPORT` 任务。
4. 读取 Celery 快照：
   - `DONE` 且顶层 `storagePath` 非空：写 `audit_reports`，commit，签发 URL。
   - `RUNNING` 或无快照：404。
   - `FAILED`：502。
   - `DONE` 但缺少 `storagePath`：502。
5. 下载 URL 每次运行时重新签发，不落库。

### 2.3 错误语义

- `ReportNotFoundError`：报告不存在或任务尚未完成。
- `ReportUnavailableError`：任务失败、结果无效或 MinIO 预签名失败。

## 5. 边界与已知事项

1. worker 不直连 PostgreSQL；报告元数据只由 gateway 写入。
2. 任务未完成时仍返回 404，进度查询走 `/tasks/{taskId}`。
3. `downloadUrl` 运行时签发，不进入 `audit_reports`。
4. 成功路径只信任 Celery 结果顶层的 `storagePath`，不信任任意扩展字段。
5. 真实 PostgreSQL 集成用例需要 `CG_POSTGRES_DSN`；本轮离线门禁中按设计 skip。
