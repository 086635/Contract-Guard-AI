## 1. 任务目标

C57 是 T-D7-7 的第二张卡，接在 C56（大小/类型/key 约束）之后，解决 D7-I13 的第 3 层：

1. 用**文件内容**（magic bytes + 容器结构）判定真实类型，扩展名只作声明一致性。
2. 提供 `CG_UPLOAD_AV_MODE=off|clamav` 两档；`off` 供 development/test，production 强制 `clamav`。
3. 扫描不通过（类型不符 / 病毒 / 超时 / AV 不可用）**绝不派发 parse**。
4. 拒绝记录只写安全摘要，不写文件内容。

## 2. 实现说明

### 2.1 扫描核心：`worker/storage/av_scan.py`（新建）

```text
detect_document_type(data) -> "PDF" | "DOCX" | None      # 纯函数，可离线测试
  · PDF  : 以 %PDF- 开头 且 尾部窗口内含 %%EOF
  · DOCX : ZIP magic + [Content_Types].xml + word/document.xml（结构校验）
ScanResult{status,detected_type,reason}                  # status ∈ {SUCCESS, FAILED}
ClamdScanner(host, port, timeout_s).scan(data)           # clamd zINSTREAM，stdlib socket
av_mode()                                                # 读 CG_UPLOAD_AV_MODE，默认 off
```

`ScanResult.reason` 只放**安全摘要码**：`MAGIC_MISMATCH`、`AV_INFECTED:<签名名>`、
`AV_TIMEOUT`、`AV_UNAVAILABLE:<ExceptionType>`、`AV_BAD_RESPONSE`、`SOURCE_UNAVAILABLE:<ExceptionType>`、
`ERR_FILE_TOO_LARGE`、`DISPATCH_FAILED:<ExceptionType>`。**不含文件内容，也不回显用户文件名。**

### 2.2 扫描任务：`worker/tasks/scan_upload.py`（新建）

```text
scan_upload(file_key, file_name, file_type, contract_id=None, *, local_path=None) -> dict
```

- 前三个参数即卡片 §⑤ 的接口；`contract_id` 是「通过后链式派发 parse」所需（网关必传），
  `local_path` 与 `parse_doc` 同款，仅供离线联调。
- 流程：读取对象（最多 `MAX_SCAN_BYTES + 1` = 50 MB + 1）→ `scan_bytes` →
  `CLEAN` 且给了 `contract_id` 时 `dispatch_parse()`（worker→worker `send_task("parse_doc")`）。
- **不抛异常给 broker**：读不到源文件、类型未登记、派发失败都折算成 `REJECTED` 信封。
- 已注册进 `worker.main` 的 `include`（`test_scan_task_is_registered_in_celery_include` 守卫）。

### 2.3 网关接线（upload 流程）

落点：`apps/api-gateway/app/services/dispatch.py`、`contract_service.py`、`app/config.py`

```text
TaskKind += SCAN_UPLOAD = "scan_upload"
_dispatch_target(body, contract_id):
    CG_UPLOAD_AV_MODE=off    -> PARSE_DOC   (file_key, contract_id)         # 保持原行为
    CG_UPLOAD_AV_MODE=clamav -> SCAN_UPLOAD (file_key, file_name, file_type, contract_id)
```

- `off` 是 development/test 默认，**C10 既有上传链路行为不变**（`test_contract_upload_real.py` 的
  `dispatcher.calls == [("parse_doc", ...)]` 与 `task_type == "PARSE_DOC"` 继续成立）。
- `validate_production()` 新增门禁：production + `off` → 启动即失败（`CG_UPLOAD_AV_MODE`）。

### 2.4 容器编排

落点：`docker/docker-compose.yml`

- 新增 `clamav` 服务（`clamav/clamav:stable`，`clamdcheck.sh` 健康检查，`start_period: 180s`——
  首次启动要下载病毒库）与 `clamdb` volume。
- `api` / `worker` 注入 `CG_UPLOAD_AV_MODE: ${CG_UPLOAD_AV_MODE:-off}`；worker 另注入
  `CG_CLAMAV_HOST=clamav`、`CG_CLAMAV_PORT=3310`，并 `depends_on: clamav: service_started`。
- 开发档默认 `off`（不扫描），生产档由 C67 prod profile 打开——与母文档「development/test 可 off，production 必须 clamav」一致。

- **不新增第二套上传扫描入口**：扫描只有 `worker.tasks.scan_upload` 一个入口，网关只按
  `TaskKind.SCAN_UPLOAD` 派发；
- 未引入新第三方依赖（ClamAV 走 stdlib `socket`）；
- 未改 `rag_contracts` / `rag_core/service.py` / OpenAPI 既有字段；
- 唯一对既有测试的改动：`test_production_settings.py` 的**合法 production 夹具**补
  `upload_av_mode="clamav"`（因为 production 新增了该必需项），并**新增**负向与 development 用例；
  未放宽或删除任何既有断言。

### 状态词表选择（重要）

`ScanResult.status` **只用平台既有任务状态 `SUCCESS` / `FAILED`**，不使用自定义 `REJECTED`：

- 网关 `TaskService.get` 的既有约定是 `result.status == "FAILED"` → `Status.failed`；
- 若用自定义词，被拒的上传会被判成 `DONE`，前端显示「已完成」——这是假阴性；
- 因此拒绝分支的 payload `status` 就是 `"FAILED"`，`reason` 承担具体原因（`AV_INFECTED` 等）；
- `test_payload_status_reuses_platform_task_vocabulary` 用**字面量断言**锁死该约定。

### 本轮未覆盖、按母文档归属 C63 的部分

`4-07 §⑤.8` 的「所有拒绝事件写审计」与 C57 §② 的「扫描成功后才更新 contract 可解析状态」，
需要**在网关侧**写 `audit_events` 与改 `contracts.status`：

- 父文档已把这件事指派给 **C63**（`4.C63Stale任务回收与心跳对账.md`：「reconciler 定期扫描…超限则标记 FAILED 并写审计」）；
- `async-worker` 无 PostgreSQL/SQLAlchemy 依赖，且 `4.C22` 设计点 1 明确「worker 不直连 DB、gateway 按 Celery 结果落库」；
- 因此本轮**不在 worker 里新造 DB 通道**（会同时违反模块边界与既有唯一拓扑），把该半部交给 C63 的 reconciler。

C57 自身可验证的部分（内容判据、AV 档位与门禁、扫描不通过不派发 parse、拒绝以 `FAILED` 上报）
已全部落盘并有测试；DB 侧审计/合同状态是 C63 的落点。

### 已知限制（交 C67/T-D7-8）

1. 真实 ClamAV 容器未在本轮启动（无外部服务），因此没有真实 clamd 的 E2E 证据——
   `test_clamav_infected_rejected` 明确标注为端口 Fake，符合避坑清单 §⑨-2。
2. `clamav/clamav:stable` 首次启动需下载病毒库（约 1~3 分钟），故 worker 只依赖
   `service_started`；生产就绪探针（readiness/limit）由 C67 负责。
3. `CG_UPLOAD_AV_MODE` 同时存在于网关（首跳任务选择）与 worker（是否调 clamd）两侧，
   两者必须一致；compose 用同一变量注入，prod profile 需保证同值。
