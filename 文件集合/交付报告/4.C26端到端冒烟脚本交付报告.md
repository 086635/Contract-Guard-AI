## 1. 交付范围与背景

C26 的交付物是 `scripts/e2e_smoke.py`：按真实流程走网关端点，不 mock、不绕过。

实施中实测发现 3 处**上游业务代码缺口**会挡住卡内断言；经**用户逐条授权**后一并修补：

1. `GET /tasks/{id}` 恒 `RUNNING/queued` —— `TaskService` 用 DB task id 查 Celery；
2. SSE 收不到进度事件 —— worker 从不 publish 到 redis pub/sub；
3. 离线档 0 风险/矛盾时 DOCX 无「溯源」子标题 —— C18 渲染器行为（**不改 C18**，改为条件断言）。

---

## 2. 实现内容

### 2.1 `scripts/e2e_smoke.py`（交付物）

- 离线档默认：生成含 5 条「第 X 条」条款的内存 DOCX → presign → MinIO 直传（预签名 PUT 失败时回退 SDK）→ upload → SSE（立刻订阅，收 RUNNING+DONE）→ 轮询 `/tasks/{id}` 到 DONE → `/elements`（触发 C22）→ `/risks`+`/conflicts`（触发 C23）→ `/report/generate` → `/report/{id}` → 下载 DOCX 回读章节。
- 其余端点覆盖：`GET /contracts`、`GET /contracts/{id}`、`GET /settings/rules`、`POST /feedback`、`POST /agent/rewrite`。
- 回归：`phase1_smoke.py` 与 `eval_recall.py`（`--gold weak_gold.jsonl`）均断言 exit 0。
- 退出码：`0=通过 / 1=链路失败 / 2=参数或环境错误`；每条断言打印 `[PASS]/[DEGRADED]/[FAIL]`。

### 2.2 修复 1：`TaskService` 查询键（已授权）

`apps/api-gateway/app/services/task_service.py` 新增 `_celery_lookup_id(record, task_id)`：
优先用任务行登记的 `celery_task_id`，回退 `str(task_id)`；`get`/`stream` 共用。
`stream` 转发事件时把 `taskId` 归一为请求的 task id（初始快照与实时事件一致）。

### 2.3 修复 2：Progress Pub/Sub（已授权）

- **唯一处上移**：channel 命名移到 `packages/cg-observability/cg_observability/progress.py::task_progress_channel`（worker 不能 import `app.*`）。
- `app/services/progress.py` 改为 import 该共享符号（保留再导出）。
- `worker/progress.py`：三个 reporter 的 `_emit` 在 `update_state` 后调用新 `_publish_progress`，把 meta publish 到 `task_progress:{celery_task_id}`；客户端惰性构造、失败只告警并熔断（不阻断任务）。
- `0.§0.7.5` 定义归属表已同步（channel 命名指向 `cg_observability`）。

### 2.4 修复 3：断言调整（已授权）

脚本「溯源」断言改为条件判定：**仅当 risks/conflicts 非空时硬判定**；离线 0 风险/0 矛盾的空态记为**显式 DEGRADED**（不改 C18 渲染器）。

## 5. 边界与已知事项

1. **授权范围**：修复 1/2/3 均已获用户逐条授权；未改 `rag_contracts` 契约字段与枚举。
2. **C18 未改**：离线 0 风险/矛盾无「溯源」子标题属渲染器既有行为，按授权以显式 DEGRADED 记录。
3. **`POST /agent/rewrite` 502**：`rewrite` 任务未注册进 worker `include`，属 Agent/worker 接线范围，非 C26；脚本对其软判定（不误伤核心链）。
4. **运行副产物**：冒烟会在 MinIO `contracts` 桶写入样本文档/报告，并触发 `scripts/eval_recall.py` 在 `data/reports` 生成临时目录（既有行为）。
5. **容器热更新说明**：因本机 CN 加速器对 `python:3.11-slim` 返回 401，本轮用 `docker cp` + 重启把源码注入运行中的 api/worker 容器完成端到端验证；镜像重建在镜像源恢复后 `docker compose build api worker` 即可。
