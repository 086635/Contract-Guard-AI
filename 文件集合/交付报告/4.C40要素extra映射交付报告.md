## 1. 组件目标与边界

C40 解决的是解析结果中的 `elements` 与数据库 `contract_elements`、前端 `ContractElement` 之间的字段丢失问题。

本次只使用 `ContractChunk.extra` 作为短期兼容逃生舱：

- 不新增表；
- 不修改 `ContractChunk` 28 字段；
- 不修改 `ContractElement` OpenAPI DTO；
- 不改变 C22 原有 clause → chunk 路径；
- 不让 Projector 从占位 text 反推真实 value。

## 2. 实现接缝

### 2.1 elements → ContractChunk

落点：`apps/api-gateway/app/services/ingestion.py`

新增：

```python
def element_payload_to_chunk(
    contract_id: str,
    element: dict[str, Any],
) -> ContractChunk:
    ...
```

映射规则：

| 解析层字段 | ContractChunk 字段 | 规则 |
|---|---|---|
| `key` | `section_id` / `chunk_id` | `make_chunk_id(contract_id, key, 0)` |
| `label` | `title` / `section_path` | 缺省使用 key |
| `value` | `text` / `extra.value` | 空值使用 label 作 text 占位，extra 保留 null |
| `confidence` | `extra.confidence` | 校验 0~1 |
| `isCustom` | `extra.isCustom` | 必须为 boolean |
| `bbox` | `bbox` / `page_no` | 有几何时保存 PDF BBox |
| — | `category` | 固定 `CONTRACT_ELEMENT` |
| — | `source_type` | `STANDARD_CLAUSE` 兼容值 |
| — | `chunk_type` | `PARAGRAPH` |

### 2.2 ContractChunk → ContractElement

落点：`apps/api-gateway/app/services/projector.py`

`ContractProjector.elements()` 对 `category == "CONTRACT_ELEMENT"`：

- `value` 从 `extra["value"]` 读取；
- `confidence` 从 `extra["confidence"]` 读取；
- `isCustom` 从 `extra["isCustom"]` 读取；
- `bbox` 从持久化 BBox 还原；
- 不把 `chunk.text` 作为真实 value 返回。

---

## 3. 缺陷与边界处理

1. **空 value**：只影响可检索 text 的兼容值，真实 `extra.value` 保持 `null`。
2. **非法 confidence**：单条投影抛出后由 `_build_element_chunks()` 转为 warning，不阻断其他 element。
3. **非法 key/value/isCustom**：单条隔离或显式失败，不污染整批解析结果。
4. **重复解析**：`make_chunk_id` 与 `bulk_upsert` 保证幂等。
5. **clause 兼容**：原有 C22 clause → chunk 以及 C13 五读端点保持原行为。
