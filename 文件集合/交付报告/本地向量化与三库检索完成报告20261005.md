# 本地向量化与三库检索完成报告（2026-10-05）

本轮已完成本机 BGE-M3、持久化三库、真实检索及云端 DeepSeek 审核/改写接线。原框架、六阶段审核图、三阶段改写图、健康分公式、OCR 和印章极坐标算法保持。代码默认离线配置保留；当前运行实例通过本机配置启用真实服务。没有提交或推送 GitHub。

开发记录先于代码落盘：`文件集合/codex/4-6本地向量化与三库检索20261005.md`（T-D6 用户追加维护）。原目录和完整副本同步，逐文件哈希清单见本报告所附测试记录。

## 当前可以使用的功能

- 前端地址：`http://127.0.0.1:5173`，后台 API 8000、Ollama 11434、Qdrant 6333 均为本机服务。
- 在规则设置中选择“审核知识库”，可切换标准库、条款库、法典库，查看真实来源、适用范围、模型状态并检索；条款库保留原人工编辑/启停入口，需要管理员角色。
- 当前合同复审：解析成功，7 页、44 个条款；DeepSeek 输出 44 条风险（高 10 / 中 29 / 低 5）、50 条矛盾，健康分 **20**。220 个真实检索引用（范本 132 / 法条 88）。最终为 **DEGRADED / 需人工复核**，不是离线或后台未启动。
- 真实改写接口返回 HTTP 200、Diff 和法条/范本引用；实测 23.29 秒，测试没有采纳修改或覆盖合同。

当前合同涉及工业产品，初始农副产品范本只能参考通用合同表述。两份范本均未经企业确认审批，标准比对会声明缺少企业基线，不能据此判定缺失条款。健康分沿用原公式，仅作为审核结果的辅助展示。

## 安装、语料与运行方式

| 项 | 实测状态 |
|---|---|
| Ollama | 复用本任务已安装的官方 v0.35.1，BGE-M3 本机运行；未加载本地生成模型 |
| BGE-M3 | HuggingFace GPUStack 的 BAAI BGE-M3 GGUF Q8_0 转换版；固定 revision，634553760 字节，SHA-256 校验吻合 |

| Qdrant | 官方 Windows v1.19.1，固定运行包并校验官方摘要；回环 server 模式共享，重启后仍有 1330 个记录 |
| 标准库 | 国家市场监管总局官方示范文本 2 份：委托合同、农副产品买卖合同 |
| 条款库 | 官方范本按原切片器和合同类型展开 70 个可检索记录；重复导入新增 0、已有 70 |
| 法典库 | 官方《中华人民共和国民法典》全文 1260 条；通用法条不受当前合同类型过滤 |
| 模型分工 | OCR、印章算法、BGE-M3 向量和 Qdrant 在本机；审核/改写生成用 DeepSeek 云端 |

检索采用原 dense 语义召回和 ContextBuilder 预算。当前 BM25 关闭、reranker 为原 noop；本轮没有宣称混合检索或增加精排模型。模型约 605 MiB，运行包、模型缓存、索引及密钥均留在本机忽略目录，不进入源代码交付。

语料及来源清单：`文件集合/知识库/官方初始库20261005`。保存的是官方网页/PDF提取文本，不是原版式 PDF；站点在本机直接下载发生 TLS EOF/WAF，采用工具读取的官方内容保存，没有关闭证书验证。哈希校验对象为保存的提取文本。

## 本轮实际更改

| 位置 | 改动及原因 |
|---|---|
| `scripts/import_official_knowledge.py`、对应测试 | 校验官方 URL、原文哈希、文件边界、适用范围；复用原切片/入库。条款使用原 PG 管理表和索引 ID，重复导入保留人工编辑 |
| `ai_engine/agents/tools.py`、对应测试 | 同类范本与通用法条分组召回，再用原 ContextBuilder 合并预算；部分库不足明确降级，引用只指向实际注入片段 |
| `rag_core/adapters/embedding.py` | 本机 HTTP 嵌入回环直连，避免系统代理干扰；云端行为保留 |
| `ai_engine/llm/factory.py`、对应测试 | 修复后台线程在 Windows truststore 证书链获取中长期阻塞；DeepSeek 显式 certifi SSLContext，同步/异步均验证证书和主机名，系统代理和原超时仍保留 |
| `ai_engine/graphs/nodes.py`、对应测试 | 标准比对只用标准来源；官方参考范本不是企业审批基线，缺少基线时提示人工复核，健康分公式没有改动 |
| `ai_engine/graphs/rewrite_graph.py`、对应测试 | 仅有原文/规则参数的字典不能再绕过 RAG；非空检索 context_block 才复用，随后执行原三阶段改写 |
| API `knowledge.py`、`main.py`、对应测试 | 增加两个管理员只读来源/语义状态、检索预览端点，沿用 ServiceContext 与标准响应信封 |
| `packages/schema/openapi.yaml` 和原 Python/TS/Zod 生成物 | 两个只读端点在原 SSOT 登记后生成，40 个 operations / 35 个 paths；没有改变合同、RAG 冻结字段 |
| 前端 KnowledgePanel / knowledge API / services / Settings、对应测试 | 设置入口显示三库真实数量、来源及检索结果；保留原条款管理，处理加载、错误和过期请求 |
| 接口数量/发布生成物守卫及原发布报告 | 数量更新为新增两个端点；追加精确生成哈希，保留历史登记和严格校验 |
| `文件集合/codex`、知识库、交付报告 | 开发卡九节回填、六处登记、官方原文及完成报告/测试证据 |
| 本机启动与运行配置 | 复用原启动方式追加本机知识服务；显式启用 BGE-M3 与独立 Qdrant 集合，保持代码默认值 |

工具环境原 `uvx` 缺失、TS 生成工具在中文路径失败：使用已有锁版本 Python 生成器、相同生成选项及原 header 后处理；TS 输入临时暂存 ASCII 路径。没有更改生成脚本、包清单或依赖锁。pnpm 自动写入的构建审批占位元数据已恢复为本轮开始前的原值。

后台卡住的旧任务是本任务发起的验收任务，已按准确进程和任务 ID 收尾并写明失败原因；其他历史任务行保留。真实复审重新派发后完成。模型结构化输出有若干 function_calling 格式重试，原 JSON 回退成功生成风险结果；详细警告原样记录在复审证据，未把回退伪装为一次成功。
