## 1. 任务目标

C59 是 T-D7-5 的第二张卡，补上 D7-I10「没有 DOCX→PDF 转换任务」：

1. 在 `async-worker` 里新增 `convert_doc` 任务与**独立 `convert` 队列**。
2. LibreOffice 只在容器内 headless 运行；网关不调 LibreOffice。
3. 每次转换用**独立临时目录**，原文只读、不删除也不就地覆盖。
4. 失败/超时返回**结构化 FAILED**（不抛异常给 broker），可重试且不影响原文。

## 2. 实现说明

### 2.1 转换任务：`worker/tasks/convert_doc.py`（新建）

```text
convert_doc_task(contract_id, source_key, *, local_path=None)
  → {contractId, status, storagePath, converterVersion, warnings}      # status ∈ {SUCCESS, FAILED}

convert_document(source, out_dir, timeout_s)     # soffice --headless --norestore --convert-to pdf --outdir ...
preview_object_key(contract_id, out_name)        # contract_previews/{contractId}/{uuid4().hex}-{name}.pdf
converter_version()                              # CG_CONVERTER_VERSION 固定，否则 soffice --version（缓存）
```

- **独立临时目录**：`tempfile.mkdtemp(prefix="cg-convert-{contract_id}-")`，`finally` 内 `rmtree`，绝不共享（§⑨-1）。
- **原文只读**：本地源用 `shutil.copyfile` 复制进私有目录；MinIO 源用 `fget_object` 只读拉取，**从不** `remove_object`、也不写回原 key。
- **失败语义**：非 0 退出 → `CONVERT_EXIT_CODE:<n>`；退出 0 但无产物 → `CONVERT_NO_OUTPUT`；`TimeoutExpired` → `CONVERT_TIMEOUT`；其它异常 → `CONVERT_UNAVAILABLE:<Type>`；全部走 `_failure()` 返回结构化 FAILED，**不抛给 broker**（§⑨-2）。
- **日志安全**：只记录 `contract_id / source_key / object_key / reason / converter_version`，不含文件内容。

### 2.2 队列与编排

落点：`apps/async-worker/worker/main.py`、`docker/Dockerfile.worker`、`docker/docker-compose.yml`

- `worker.main`：`include` 注册 `worker.tasks.convert_doc`；`task_routes={"convert_doc": {"queue": CONVERT_QUEUE}}`，`CONVERT_QUEUE = os.getenv("CG_CELERY_CONVERT_QUEUE", "convert")`（即卡片 §⑤ 的 `CELERY_QUEUES=convert`）。
- `Dockerfile.worker`：`apt-get install libreoffice-writer fonts-noto-cjk fonts-dejavu-core`（headless 转换 + 中文契约字体）。
- compose 新增 `worker-convert` 服务：同镜像、`-Q convert` 只消费转换队列，`CG_CONVERT_TIMEOUT_S=120`、`CG_SOFFICE_BIN=soffice`。
- `docker compose config --quiet` → exit 0。

### 2.3 转换结果回写（本卡对 C58 的衔接，落点扩展）

`4-07 §⑥.6` 明确 **worker 不写业务 DB**，但本卡 ⑥.4 要求「转换版本写入预览表」，因此回写放在网关既有预览文件上：

```text
PreviewService.reconcile_convert(contract_id)
  · Celery DONE + result.status=SUCCESS → mark_done(key, converterVersion)   → 预览 DONE，URL 从派生对象签发
  · Celery FAILED 或 result.status=FAILED → mark_failed(warnings[0])        → 预览 FAILED，可重试
  · 仍 RUNNING → 原样返回（下次读取或 C63 reconciler 再试）
```

触发点：`PreviewService.get()` 在状态为 `RUNNING` 时做一次对账（幂等，读路径无副作用除状态收敛）。这样 C58 的 `PENDING → RUNNING → DONE/FAILED` 状态机在生产路径上真正闭环。

## 7. 边界与后续

### 边界声明

- 未新建 `apps/doc-convert`；未让 gateway 调用 LibreOffice；未在转换时删除原文；
- **不新增第二套任务框架**：复用既有 `celery_app` 与 `worker.storage`，只加一个任务 + 一条队列路由；
- worker 仍**不写业务 DB**（回写落在网关侧既有预览服务）。

### 两处需知晓的决策

1. **落点扩展**：`app/services/preview_service.py`、`app/db/repository/preview.py`、
   `tests/test_preview_routes.py` 三个文件超出本卡 ④ 的落点清单。理由：本卡 ⑥.4 要求
   「转换版本写入预览表」，而 `4-07 §⑥.6` 规定 worker 不写业务 DB —— 回写只能落网关，且必须改
   C58 已建的预览文件（不新建第二套预览状态表）。
2. **接口顺序对齐**：C58 原按 `(source_key, contract_id)` 派发，与本卡 §⑤ 的
   `convert_doc(contract_id, source_key)` 相反；已按**本卡定义**修正并同步 C58 的断言。

### 未做（明确归属）

- **页数（pageCount）**：本卡结果信封不含页数（卡片 §⑤ 未定义）；转换后重新抽取/对齐与页数由 **C60** 负责。
