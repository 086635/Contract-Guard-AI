## 1. 任务目标

把「报告只有一个 DOCX 下载地址」推进为真正的双格式导出：

1. 报告任务同时生成 DOCX 与 PDF 并分别上传；
2. `ReportData` 保留 `downloadUrl`，新增 `wordDownloadUrl` / `pdfDownloadUrl`；
3. `ReportService` 分别签发短期下载 URL；
4. 前端两个按钮分别下载对应格式，失败态明确、格式绝不混用。

---

## 2. 实现说明

### 2.1 契约（`packages/schema/openapi.yaml`，兼容加法）

```yaml
downloadUrl:     string          # 兼容字段（指向 DOCX）
wordDownloadUrl: string          # 新增：Word(DOCX)，与 downloadUrl 同对象
pdfDownloadUrl:  string | null   # 新增：PDF；未生成时为 null
```

`required` 未变（旧客户端继续可用）；`gen-ts` / `gen-zod` / `gen-py` 三产物已重生成（生成物 gitignore）。

### 2.2 Worker（`worker/tasks/gen_report.py`）

- 阶段保持既有 `render` → `upload`（不新增阶段表）；
- `render_report_docx` 产出 DOCX → `_export_pdf()` 复用 C59 `convert_document`（LibreOffice headless）→ 两格式分别 `upload_report(..., extension=...)`；
- **降级语义**：DOCX 成功而 PDF 失败（转换异常 / 非 `%PDF-` / PDF 上传失败）→ `status=DEGRADED`、`pdfStoragePath=""`、warnings 记 `PDF_EXPORT_FAILED:*` / `PDF_UPLOAD_FAILED:*`；DOCX 失败 → `FAILED`。任何情况都不返回假 URL。
- 结果形状：`{contractId, status, format, storagePath, pdfStoragePath, warnings}`（`storagePath` 仍为 DOCX，兼容 C21 语义）。

### 2.3 存储与元数据

- `worker/storage/minio_client.py::upload_report(..., extension="docx"|"pdf")`：**唯一上传入口**同时支持两种扩展名，key 后缀与 `content-type` 一一对应（`_REPORT_CONTENT_TYPES`）。
- `worker/tasks/convert_doc.py`：`_timeout_s()` 公开为 `convert_timeout_s()`（超时读取唯一处），供报告任务复用。
- `audit_reports.pdf_storage_path`（可空，迁移 `20261002_0014`）：NULL = 该报告只有 DOCX（PDF 失败或历史数据）。

### 2.4 网关（`app/services/report_service.py`）

- `ReportService` 构造改为可注入 `contracts/tasks/reports`（离线单测用，与 C58 `PreviewService` 同款）；
- finalize 时同时读取 `storagePath`（DOCX）与 `pdfStoragePath`（可缺省）并落库；
- `_to_report_data`：`downloadUrl = wordDownloadUrl = presign(DOCX)`；`pdfDownloadUrl = presign(PDF)` 或 `None`（不签发假 URL）。

### 2.5 前端（`src/views/Report.tsx`）

- 表头按钮拆成 **下载 Word**（`wordDownloadUrl ?? downloadUrl`）与 **下载 PDF**（仅 `pdfDownloadUrl`）；
- PDF 缺失时按钮仍可点，点击给「PDF 尚未生成，可点击「重新生成」后重试。」并显示 `PDF 未生成` 徽标文案；URL 解析失败也给格式专属错误文案；
- 样式 `.report-export-hint` 追加到 `index.css`。

## 7. 边界与后续

### 边界声明

- **不新增第二套渲染器**：PDF 复用 C59 `convert_document`（LibreOffice），DOCX 复用 C18 `render_report_docx`；
- **不破坏旧语义**：`downloadUrl` 仍指向 DOCX；`format` 列仍为 `DOCX`（PDF 是派生附件）；
- **不返回假 URL**：PDF 失败时 `pdfDownloadUrl=null` + 前端明确提示；
- **前端不转换**：PDF 由 worker 产出，前端只消费契约；
- **worker 不写业务 DB**：两个对象 key 仍随 Celery 结果回传，由网关落库（C21 模式）。

### 未做（明确归属）

- **浏览器下载魔数 + 双按钮点击 E2E** → **C75**（Playwright，含真实下载文件头校验）；
- **真实 LibreOffice PDF 转换的回归门禁** → 沿用 C59 的 `CG_CONVERT_TEST_SOFFICE` 环境门禁（同一 `convert_document`；本机无 soffice，故 C72 未新增永久 skip 用例）；
- **PDF 的对象生命周期/清理策略** → 未在 T-D7-9 范围。

### 后续

- **C73**：Zod 运行时响应校验。**C74/C75**：T-D7 回归收口与 Playwright E2E（含 DOCX/PDF 下载魔数）。
