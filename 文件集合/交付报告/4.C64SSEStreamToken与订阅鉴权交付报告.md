## 1. 任务目标

C64 解决 D7-I12：`EventSource` 不能自定义请求头，因此不能携带 Bearer。方案是**短期、单任务作用域**的
stream token（母文档 §⑤.7：`POST /tasks/{taskId}/stream-token` 返回 60 秒 token，EventSource URL 用 `?streamToken=...`）。

---

## 2. 实现说明

### 2.1 契约（唯一 SSOT，⚠️ 触碰契约层）

`packages/schema/openapi.yaml`（+37 行，纯加法）：

```text
StreamTokenData     { streamToken, expiresIn(固定 60) }
StreamTokenResponse = ApiEnvelopeBase + data: StreamTokenData
POST /tasks/{taskId}/stream-token   → StreamTokenResponse（需 Bearer）
GET  /tasks/{taskId}/stream         → 新增可选查询参数 streamToken（EventSource 用）
```

operation 计数 30 → **31**（守卫测试同步）。生成物 `schemas.py` / `types.ts` / `zod.ts` 已重新生成、未手改。

### 2.2 令牌：复用唯一 JWT 实现（`app/services/security.py`）

```text
STREAM_TOKEN_TTL_SECONDS = 60                       # 唯一定处
StreamTokenClaims{sub, task_id, typ="stream", scope="stream", iss, aud, iat, exp}
JwtService.issue_stream(user_id, task_id) -> (token, 60)
JwtService.verify_stream(token) -> StreamTokenClaims
```

- 与 access token 共用 secret/issuer/audience（**不新增第二套签名逻辑**），但 `typ`/`scope` 必须是 `stream`
  且必须携带 `taskId` → **access token 天然无法伪装成 stream token**（断言 4）。
- 时间校验同样走注入时钟（`now=`），测试可复现过期行为。

### 2.3 服务与路由（`task_service.py` / `api/v1/tasks.py`）

```text
TaskService.assert_access(task_id, user)       # 任务访问权**唯一处**：不存在 → 404（不泄露存在性）
TaskService.issue_stream_token(task_id, user)  # 先 assert_access，再签发
TaskService.verify_stream_token(task_id, tok)  # 校验签名/过期/类型 + 令牌 taskId 必须等于路径 taskId
```

`stream_principal`（SSE 凭据唯一处）：

| 请求形态 | 处理 |
|---|---|
| `Authorization: Bearer <access>` | 复用 `get_current_user`（fetch/客户端兼容路径） |
| `?streamToken=<短期令牌>` | `verify_stream_token`（EventSource 路径） |
| 两者都没有 | 401（**不放宽匿名订阅**） |
| 令牌合法但属于别的任务 | 403 |
| 把 access token 放查询串 | 401（类型不符） |

路由挂载调整：`main.py` 不再对 `tasks.router` 统一加 `get_current_user`，改为**每条路由自带凭据**
（`GET /tasks/{id}` 与 `POST /stream-token` 用 `get_current_user`；`/stream` 用 `stream_principal`）。
「所有受保护 v1 路由都需凭据」的约束仍然成立，只是 SSE 的凭据形态不同。

### 2.4 SSE 响应形态

`sse.py` 新增 `SSE_MEDIA_TYPE="text/event-stream"` 与 `SSE_HEADERS`（唯一处），路由直接引用，
确保「SSE 响应保持 text/event-stream」不会被就地改坏。

## 7. 边界与后续

### 边界声明

- **不把 access token 放 query**：查询串只接受 `typ=stream` 的短期令牌，access token 一律 401；
- **不放宽匿名 SSE**：没有 Bearer 也没有 streamToken → 401；令牌无效/过期 → 401；
- **不让 token 可用于其他任务**：令牌绑定 `taskId`，跨任务复用 → 403；
- **不新增第二套 SSE 通道**：仍是 `/tasks/{taskId}/stream` 一条路径、一个 `TaskService.stream`。

### 一处必须点名的缺口（本卡无法闭合，已登记）

🔴 **`contracts` 归属字段缺失**：母文档 `4-7 §⑤.11` 明确要求
「迁移顺序：users/audit → **contracts 归属字段** → tasks 可靠性字段 → previews」，
并要求「老合同迁移时 `created_by_id` 允许 null，但必须打上 `legacy` 标记」；
`4-7 §⑦` 的 D7-I02 也把「无 `created_by`/`assigned_to`」列为**必须闭环**。
实测（本轮）：`app/db/models.py` 的 `Contract` 只有 id/filename/file_size/file_hash/storage_path/status/contract_type/version/created_at/updated_at，
**没有任何归属字段**；全部迁移中也没有对 `contracts` 加过归属列。

因此：
- C64 现在能强制的是「令牌 `(userId, taskId)` 绑定」与「跨任务拒绝」（断言 3 的可执行部分）；
- **「同一租户内他人合同」当前无法判定**——因为所有已认证用户对所有合同可见（单租户私有化部署口径）；
- 建议**新开一张卡片**（归属 T-D7-1 / D7-I02 的收尾）：`contracts.created_by_id`（可空 + `legacy` 标记）
  + 上传时写入 + `TaskService.assert_access` 收紧（该函数已预留 `user` 参数，**只改这一处**）。
