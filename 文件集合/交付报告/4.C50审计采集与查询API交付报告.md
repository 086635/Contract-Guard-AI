## 1. 任务目标

C50 把 C49 的 append-only 审计仓储接成可用的审计采集链路，并新增管理员查询入口：

```text
业务路由
  -> AuditService.write_event
  -> AuditRepository.append
  -> audit_events

ADMIN -> GET /api/v1/audit/events -> AuditService.list
```

## 2. 实现说明

### 2.1 AuditService

落点：`apps/api-gateway/app/services/audit_service.py`

```text
AuditService.write_event(action, resource_type, outcome, ...)
AuditService.list(filters, page, page_size)
```

- 唯一写入入口；
- 自动补充 traceId；
- 使用 `begin_nested()` savepoint 隔离审计写失败；
- 捕获异常后仅记录 warning，不向主业务抛异常；
- 查询只读，直接委托 `AuditRepository.list`。

### 2.2 metadata 白名单与脱敏

`sanitize_metadata`：

- 只保留白名单 key；
- 敏感 key 统一写 `[REDACTED]`；
- 只允许简单标量和简单列表；
- 字符串截断到 256 字符；
- 未知字段、嵌套对象直接丢弃；
- 禁止合同正文、Prompt、密码、access/refresh token、Cookie/Authorization。

覆盖脱敏 key 包括：

```text
password / token / accessToken / refreshToken / authorization / cookie
secret / apiKey / prompt / promptTemplate / originalText / content / body / requestBody
```

### 2.3 采集点

| 动作 | 接入位置 | 结果 |
|---|---|---|
| LOGIN / REFRESH / LOGOUT | `api/v1/auth.py` | 成功、失败、锁定/拒绝 |
| USER_CREATE / USER_UPDATE | `api/v1/auth.py` | 管理动作成功/失败/拒绝 |
| UPLOAD | `api/v1/contracts.py` | 合同上传成功 |
| VIEW | `api/v1/contracts.py` | 合同列表/详情成功 |
| COMMIT | `api/v1/contracts.py` | 合同提交成功 |
| REWRITE | `api/v1/agent.py` | 改写成功/失败 |
| REPORT | `api/v1/report.py` | 报告生成成功/失败 |
| EXPORT | `api/v1/report.py` | 报告读取/下载成功/失败 |
| SETTINGS_UPDATE | `api/v1/config.py` | 配置更新成功 |
| AUTH_DENIED | `api/deps.py::require_roles` | 角色拒绝 |

所有路由只调用 `write_audit_event` / `AuditService`，不直接 insert。

### 2.4 查询 API

落点：

- `apps/api-gateway/app/api/v1/audit.py`
- `packages/schema/openapi.yaml`

接口：

```text
GET /api/v1/audit/events
```

过滤参数：

```text
page / pageSize / actorId / action / resourceType / resourceId
outcome / traceId / from / to
```

权限：

- 仅 ADMIN；
- 无 token → 401；
- VIEWER/REVIEWER → 403，并写 AUTH_DENIED 审计。

### 2.5 HTTP 上下文与 trace

- `IdempotencyMiddleware` 在请求开始时绑定 `trace_id`；
- `AuditService` 自动读取 `get_trace_id()`；
- IP 和 User-Agent 由路由上下文显式传入；
- 不记录 Authorization/Cookie 原文。
