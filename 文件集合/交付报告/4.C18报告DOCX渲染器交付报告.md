## 2. 实现内容

### 2.1 渲染输入模型

落点：`apps/async-worker/worker/report/render_docx.py`

`ReportRenderInput` 包含：

```python
contract_id: str
generated_at: datetime
risks: list[EnhancedRiskItem]
conflicts: list[CrossClauseConflict]
elements: list[dict[str, Any]]
health_score: dict[str, Any] | None
```

风险、矛盾、溯源类型全部复用 `ai_engine` 领域模型，没有复制契约字段。

### 2.2 DOCX 渲染

`render_report_docx(payload)` 使用 `python-docx` 对象 API 生成报告，并写入：

1. 标题、合同编号、生成时间。
2. 风险清单：等级、类别、条款、原文、建议、法律依据。
3. 每条风险的 `citations` 溯源。
4. 矛盾清单：来源条款、目标条款、矛盾类型、说明、建议。
5. 每条矛盾的 `citations` 溯源。
6. 合同要素摘要。
7. 可选健康分区块。

输出为内存中的 `BytesIO` 字节，不写文件、不返回 URL、不访问数据库或对象存储。

### 2.3 公开出口

`apps/async-worker/worker/report/__init__.py` 导出：

```python
ReportRenderInput
render_report_docx
```

## 5. 边界与已知事项

1. 本卡没有触碰 `rag_contracts`、网关路由、数据库模型或 MinIO 客户端。
2. 渲染器不依赖 Celery，单测可完全离线运行。
3. `uv sync --all-packages` 被工作区既有 `apps/web-ui__demo` 目录阻断，该目录没有 `pyproject.toml`。
   本轮没有删除或移动该目录；`uv.lock` 已手工同步 `python-docx`，且 `.venv` 中该包已存在、测试通过。
4. 报告文件上传、任务编排和元数据落库仍未实现，不能把本卡描述成 T-D3 整体完成。
