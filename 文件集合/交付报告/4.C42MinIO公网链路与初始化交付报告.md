## 1. 任务目标

C42 解决浏览器直传与报告下载链路中的 MinIO endpoint 问题：

```text
API Gateway 内部访问
  -> CG_MINIO_ENDPOINT=minio:9000
  -> stat_object / 服务端对象操作

浏览器访问
  -> CG_MINIO_PUBLIC_ENDPOINT=localhost:9000
  -> presign_put / presign_get
  -> 真实 PUT / GET
```

同时补齐 Compose 启动时的 `contracts` bucket 幂等初始化，以及浏览器来源的 CORS 配置。

## 3. 实现说明

### 3.1 配置回退

落点：`apps/api-gateway/app/config.py`

新增：

```python
minio_public_endpoint: str | None = None
minio_region: str = "us-east-1"

@property
def resolved_minio_public_endpoint(self) -> str:
    return self.minio_public_endpoint or self.minio_endpoint
```

Compose API 显式设置：

```yaml
CG_MINIO_PUBLIC_ENDPOINT: localhost:9000
```

### 3.2 双 client 适配器

落点：`apps/api-gateway/app/services/storage.py`

- `_internal_client`：使用 `settings.minio_endpoint`；`_public_client` 使用 `settings.resolved_minio_public_endpoint`；两者都传入 `region=settings.minio_region`，避免 SDK 签 URL 前做 GetBucketLocation 网络探测。
- `_public_client`：使用 `settings.resolved_minio_public_endpoint`；
- `stat_object()`：只调用 `_internal_client`；
- `presign_put()`：只调用 `_public_client`；
- `presign_get()`：只调用 `_public_client`。

两个 client 各自构造和签名，没有对 internal URL 做 host 字符串替换。

### 3.3 Compose 与 CORS 初始化

落点：

- `docker/docker-compose.yml`
- `docker/minio-cors.json`

实际启动链：

```text
minio 服务
  -> 读取 /config/minio-cors.json
  -> 注入 MINIO_API_CORS_ALLOW_ORIGIN
  -> server /data

minio-init
  -> mc alias set local http://minio:9000 ...
  -> mc mb --ignore-existing local/contracts
```

`docker/minio-cors.json` 当前是单行 JSON 数组：

```json
["http://localhost:5173","http://localhost:8080"]
```

API 和 Worker 均依赖 `minio-init` 成功完成，避免 bucket 尚未创建时启动。

### 3.4 实测纠偏：不使用 `mc cors set`

当前验证的 MinIO：

```text
quay.io/minio/minio:latest
RELEASE.2025-09-07T16-13-09Z
```

其 S3 `PutBucketCors` 实测返回：

```text
HTTP 501 Not Implemented
A header you provided implies functionality that is not implemented
```

因此没有保留无效的 `mc cors set` 调用，而是采用 MinIO 支持的启动配置：

```text
MINIO_API_CORS_ALLOW_ORIGIN=<来自单一 CORS 文件的来源列表>
```

这样仍保持“单一 CORS 定义文件”约束，同时避免写入一个必然失败的初始化步骤。
