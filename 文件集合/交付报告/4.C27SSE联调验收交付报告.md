## 1. 交付范围

本卡负责：为 `/tasks/{taskId}/stream` 建立**离线**的 SSE 联调验收用例——进度事件两类、订阅生命周期（终态关闭 / 客户端断开）、非法事件容错。

本卡不负责：新增端点、修改 SSE 通道协议、依赖真实 redis/Celery（用 Fake 端口离线跑）。

### 背景

C26 已修复 SSE 的两处上游缺口（`TaskService` 用 `celery_task_id` 查 Celery / 定 channel；worker `progress` 把 meta publish 到 `task_progress:{celery_task_id}`）。C27 在其上用 Fake 端口把 SSE 行为钉成可回归的用例。

---

## 2. 实现内容

测试文件：`apps/api-gateway/tests/test_sse_e2e.py`（全离线）

测试替身（不 import worker、不连 redis/Celery/PG）：

| 替身 | 作用 |
|---|---|
| `_FakeSession` | 只覆盖 `TaskRepository.get` 用到的 `session.get`，返回一条 `AuditTask` |
| `_FakeDispatcher` | 记录 Celery 查询键、返回可配置 `TaskStatusSnapshot` |
| `_FakeProgressBroker` | 记录 subscribe / unsubscribe，按脚本推送事件 |

用例：

| 用例 | 断言 |
|---|---|
| `test_stream_emits_running_then_done_and_closes_subscription` | `RUNNING`+`DONE` 均透出、末事件 `DONE`、查询键与 channel key 均为 `celery_task_id`、订阅关闭 |
| `test_stream_with_terminal_snapshot_does_not_subscribe` | 快照已 `DONE` 时不订阅、只发 1 条终态事件 |
| `test_stream_unsubscribes_on_client_disconnect` | 客户端 `aclose()` 后 unsubscribe |
| `test_stream_skips_invalid_event_and_continues` | 缺字段非法事件被跳过，随后仍收到 `DONE` |
| `test_task_service_has_no_mock_factory` | `task_service.py` 源码无 `MockDataFactory` |

## 5. 边界与已知事项

1. **全离线**：不需要 redis / Celery / PostgreSQL，`pytest` 不因缺服务 skip。
2. **不伪造事件形状**：事件体走真实 `TaskProgress.model_validate` 校验路径（非法事件即在此被拦下）。
3. **订阅关闭语义**：unsubscribe 由进度端口的生成器 `finally` 负责（与 `RedisProgressBroker` 同构）；用例通过显式 `aclose` + 让异步生成器 finalize 来稳定断言。
4. **channel 唯一处**：`task_progress_channel` 定义在 `cg_observability`（C26 上移并更新 `0.§0.7.5`）。
