## 1. 任务目标与边界

### 1.1 C1 目标

1. 建立 9 张 PostgreSQL 业务表：
   `contracts`、`contract_elements`、`audit_tasks`、`audit_risks`、
   `seal_detections`、`settings_rules`、`audit_reports`、`user_feedbacks`。
2. 将 OpenAPI 与 `rag_contracts` 中的契约枚举映射为数据库列。
3. 为迁移、DAL 和后续网关真实化提供唯一 ORM 定义。

### 1.2 C1 明确不做

- 不新增或修改契约字段、枚举值。
- 不实现 session、DAL、Alembic。
- 不触碰 `rag_contracts`、`service.py`、生成物或 worker 内部。

### 1.3 C2 目标

1. 建立异步 Alembic 环境，`target_metadata` 直接复用 C1 的 `Base.metadata`。
2. 建立首版 `create tables` 迁移，覆盖 C1 的 7 张表。
3. 每个 `create_table` 都有对应 downgrade，保证可回滚。
4. 提供离线 SQL 验证和真实 PostgreSQL 集成测试，后者无 DSN 时自动 skip。

### 1.4 C2 明确不做

- 不手改数据库，不写旁路建表 SQL。
- 不使用 `Base.metadata.create_all` 代替迁移。
- 不修改 C1 模型，不提前实现 C3 session 或 C4~C6 DAL。

### 1.5 依赖方向

```text
packages/schema/openapi.yaml
        |
        v
app.generated.schemas ----+
                          +--> app.db.models
packages/rag-contracts ---+          |
                                     v
                                alembic/
```

未出现 `api-gateway -> worker` 或 `rag_contracts -> apps/*` 的反向依赖。

## 2. C1 实现结果

### 2.1 ORM 模型

落点：[models.py](E:/important_project/Serve_bage/apps/api-gateway/app/db/models.py:85)

| 模型 | 表名 | 关键职责 |
|---|---|---|
| `Contract` | `contracts` | 合同元数据、状态、合同类型、时间戳 |
| `ContractElement` | `contract_elements` | `ContractChunk` 28 字段持久化投影 |
| `AuditTask` | `audit_tasks` | 解析、审核、报告任务进度与状态 |
| `AuditRisk` | `audit_risks` | 风险与跨条款矛盾结果投影 |
| `SealDetection` | `seal_detections` | 印章与签名检测结果投影 |
| `SettingsRule` | `settings_rules` | 审核规则配置 |
| `AuditReport` | `audit_reports` | DOCX 报告元数据 |
| `UserFeedback` | `user_feedbacks` | 多态反馈数据 |

### 2.2 契约枚举映射

| 数据库列 | 枚举来源 |
|---|---|
| `contracts.status` | OpenAPI `ContractStatus` |
| `contracts.contract_type` | `rag_contracts.ContractType` |
| `contract_elements.source_type` | `rag_contracts.SourceType` |
| `contract_elements.chunk_type` | `rag_contracts.ChunkType` |
| `audit_tasks.status` | OpenAPI `Status` |
| `audit_risks.category` | OpenAPI `RiskCategory` |
| `audit_risks.level` | OpenAPI `RiskLevel` |
| `audit_risks.conflict_type` | OpenAPI `ConflictType` |
| `audit_reports.status` | OpenAPI `Status` |
| `user_feedbacks.target_type` | OpenAPI `TargetType` |
| `user_feedbacks.verdict` | OpenAPI `FeedbackVerdict` |

枚举列使用 `native_enum=False + create_constraint=True + validate_strings=True`。
非法字符串在 ORM flush 时直接被拒绝。

### 2.3 关键约束

- `audit_tasks.progress` 限定为 `0.0..1.0`。
- `audit_reports.format` 限定为 `DOCX`。
- `embedding_dim` 只允许 `NULL` 或项目锁定的 `1024`。
- `LAW_ARTICLE` 必须有 `law_code`。
- `WINDOW_SLICE` 必须有 `parent_section_id`。
- `vector_id` 必须等于 `chunk_id`。
- `user_feedbacks` 使用 `target_type + target_id`，不保留旧的 `risk_id` 单态设计。

落点：[env.py](E:/important_project/Serve_bage/apps/api-gateway/alembic/env.py:29)

关键行为：

1. `target_metadata = Base.metadata`，直接复用 C1 模型元数据。

- `script_location = %(here)s/alembic`
- `prepend_sys_path = %(here)s`
- `sqlalchemy.url` 留空，由环境变量或测试配置提供

### 3.2 首版迁移

落点：[20260926_0001_create_tables.py](E:/important_project/Serve_bage/apps/api-gateway/alembic/versions/20260926_0001_create_tables.py:50)

`upgrade()`（0001）按依赖顺序创建 7 张基础表，`0002` 追加 `seal_detections`，`0003` 追加 commit/version：

```text
contracts
settings_rules
contract_elements
audit_tasks
audit_risks
audit_reports
user_feedbacks
```

`downgrade()` 按逆序删除 7 张基础表，并显式删除对应索引；
`0002` / `0003` 的 downgrade 删除增量表与列。
